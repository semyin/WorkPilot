# P12 任务与助手档案迁移

更新日期：2026-10-04。程序 `0.1.0-alpha.12.15`，SQLite 数据版本仍为 11。

这是 Q41/T-P12-03 的任务与助手迁移部分。整组任务的记录、附件和文件历史可加密备份，导入只读查阅，再单独确认恢复。现已增加逐项目/原目录映射、历史命令分页，以及未决操作的人工核对闸门。设置中的“完整资料迁移”可以把所选项目、配置、记忆、技能、任务、附件历史和当前文件装入同一个备份，详见 [统一迁移与人工核对](P12-统一迁移与人工核对.md)。独立档案入口继续保留；导入历史不覆盖当前文件，P12 整体验收另按阶段记录判断。

## 使用入口

设置 → 任务与助手档案迁移。

1. 停止主任务、助手及文件操作，选择一个主任务。可切换到已归档任务，列表分页加载；所有助手自动包括在内，不允许单独导出某个成员。
2. 选择新的 `.wptask` 文件位置，输入并重复至少 12 个字符的口令。已有文件不会覆盖，口令丢失后无法找回。
3. 在目标 WorkPilot 选择该文件、输入口令，点击“核验并预览任务档案”。核验整个文件后显示任务树、消息/过程记录数、正文容量、已包含附件和文件历史的数量及容量，以及旧包未包含的数量。
4. 确认后加入“已导入的任务档案”。按类别分页查阅，展开保存的正文和关联正文；“全部保存正文”可以独立查看每个已保存内容对象。
5. 已导入档案可使用新口令另存，保持原档案编号和内容。重复导入、重启后再导入或同一档案重新加密再导入，不会增加重复档案。

原任务、原消息顺序、排队状态和所有工作区文件保持原样。导入不创建可执行任务，不启用旧审批，不调度助手，不触发模型或工具，也不更改全局模型、权限、定时和项目设置。

## 从档案恢复单任务

在已导入档案下方选择“从档案恢复任务”：

1. 选择本机模型配置。已有模型会话必须匹配原协议、模型名称和服务地址；可以使用重新配置的本机密钥，不复制原密钥。有历史时不能通过换模型绕过续接检查。
2. 选择本机项目。原任务有项目时必须指定目标项目；文件夹必须存在且身份未变化。任务档案不复制项目文件，请先使用项目文件迁移入口准备所需文件。历史中的绝对路径不自动改写。
3. 预览新任务标题、模型地址、项目目录、消息/排队数量、历史结果数、模式、恢复状态及完整规则。原任务规则保留，目标项目规则合并显示；预览后配置发生变化必须重新预览。
4. 确认后一次保存新的任务、会话、主助手和消息编号。原模式保留，权限固定为“请求审批”，命令执行关闭；原来的审批、工具待执行快照、登录、定时计划和协作调度不启用。
5. 点击“打开恢复的任务”，可以查看原对话、队列、计划及历史结果。需要手动点击“继续任务”；原任务已完成且没有新消息时，须先发送新要求。待回答的问题继续等待用户。恢复本身不连接模型，不执行工具。

单任务入口只接收没有助手的档案；多助手档案使用下方团队入口。随包附件在预览和确认时重新解析核对。旧版未保存附件原文的档案仍只能查阅，需要从原任务重新导出新版档案。等待审批、待执行工具批次、结果不确定的步骤或未完成文件操作现在可以保留原记录并恢复，但不安装其执行权；预览逐项列出原记录，恢复后先填写人工核对说明才能手动继续。旧批次没有确定结果的调用封存为“迁移未重放、效果待核对”，不能因为迁入而重复执行。原生模型历史只接收已支持的助手消息和工具调用结构；未知类型、系统角色注入、调用/结果不匹配或缺少关联正文均拒绝。

保存的完整模型历史、压缩摘要、工具结果、计划、已发送方向和排队/引导状态保留。历史步骤仅通过当前恢复任务自己的结果索引查阅，不作为可重新运行的旧步骤安装。迁入的历史消息保留原时间，新任务创建记录使用恢复时间；过程记录标明恢复来源，原来的完整运行/审批过程继续在档案库查阅。历史命令输出已重建任务自有 stdout/stderr 关联，支持按页读取；正文中的任意内容编号不产生读取权限，另一任务不能借旧步骤编号读取输出。

每份档案在同一数据目录只恢复一次。重复确认或重启重试返回原任务，不重复添加、不修改后来设置、不取消归档或自动重新运行。对象写入后，活动记录、结果索引和回执在一次事务中保存；提交前取消或数据库失败不会留下半个可见任务。恢复后的任务可再次导出、导入和恢复，原历史结果索引仍随包携带，既有来源任务不修改。

## 从档案恢复多助手团队

选择包含多个任务的档案，下方会显示“从档案恢复多助手任务”。流程使用 `team_restore_options`、`team_restore_preview`、`team_restore`，不改变旧单任务接口。

1. 为主任务和每个助手选择本机模型。已有历史按原协议、模型、服务地址匹配，本机存在匹配配置时先选中供核对；没有运行历史的助手可以另选。普通快捷入口将同项目团队恢复到一个本机项目；跨项目或多原目录时使用“分别映射多个项目和原文件夹”，为每个原项目及历史目录明确选择目标。
2. 预览每个任务的状态、消息/队列、模型、上级、依赖、接替/被接替、交付及检查状态。任务内容与规则可展开阅读。团队人数、并行、层级和接替上限保留；主任务/成员的模式分别保留。
3. 确认后新建整棵任务树及对应助手、会话、消息编号。父子、同级依赖、接替链和继承自上级的已发送要求重新关联；原对话、模型调用与工具结果正文不进行字符串替换。失败保持失败、完成保持完成；其它可恢复状态保持待手动继续或待回答。全部协作开关关闭、待启动标记清空、请求审批、命令关闭，旧运行、审批、定时、待处理调用和执行回执不导入活动表。
4. 已保存的交付重建为属于新任务/助手的记录。旧步骤编号仅作为历史来源，模型 `inspect_agent` 查看步骤时按该助手自己的历史结果索引读取；不能使用其它成员的旧步骤。旧的“交付已认可”和“放弃分支”结论保留。待检查交付清除旧查看标记，模型须重新查看当前交付再认可；旧报告编号无效。
5. 手动继续主任务后，符合条件的中断/未启动助手按原依赖启动。已完成、失败、被接替、已放弃分支不自动重跑；主任务可依照现有规则明确安排新的接替。已有运行历史的助手不能因为迁入后没有当前运行编号，就被当作全新助手修改分工或重复追加依赖内容。待回答的问题继续等待用户输入。

团队新旧任务编号映射作为平台数据提供给模型，明确要求使用当前成员编号。旧编号不被当作工具别名，也不扩大成员访问范围。再次迁移会合并来源映射，最多保留 1024 项；超过容量明确拒绝，不截断历史。交付的历史运行/步骤只作查阅来源，不安装成可以重放的活动运行。

保存使用一次数据库事务。任何成员保存失败，整组任务、成员关系、消息和恢复回执一起撤回；已有来源和目标任务不修改。整组来源正文在恢复根任务的来源事件中保留一次，子任务的历史结果和新交付另有引用，可再次整组导出。重复确认、重启或再加密后再次恢复返回同一团队，不更改后来的权限和状态。

预览会核对父子身份、重复成员名、依赖环/跨组依赖、接替链的双向关系与次数、交付归属及结果正文。不完整记录不能跳过后继续创建。有效的协作等待、未结束工具批次、审批和不确定效果会进入新任务的人工核对清单；旧等待与审批不会重新调度，主任务也不能绕过尚未核对的子助手。无新运行但仍保留旧交付、状态已发生变化的未收尾记录同样拒绝，避免把过期交付当成当前结果。

## 本批内容与边界

包含选定主任务及全部后代助手的 29 类已保存记录：

- 任务、助手身份、用户消息与排队位置、运行结果。
- 会话配置和上下文、历次运行、检查点、模型/工具步骤、已保存效果与人工核对结果。
- 助手分工、父子与依赖关系、交付、审查、接替关系、协作开关与等待记录。
- 工具调用、审批内容、工具正文、模型连接检查。
- 文件工作区操作、操作正文、旧版受管理文件变动、旧版成果及版本。
- 命令回执、事件、事件正文关联。

引用的已保存正文按原字节和摘要搬迁，包含长消息、模型结果、工具输出、上下文压缩后的历史与交付内容。当前界面的消息 128 条、步骤 64 条限制不用于导出；按数据库中的完整所选任务集合查询。模型当初没有保存的输出无法补造。

这不是数据库复制。表名和范围由程序固定，档案中的数据不会作为 SQL 或命令执行。原始编号只用于展示来源和历史关联，不成为目标环境的活动任务编号。历史中的路径仅作为文字保留，不访问或修改其指向的项目文件。

新版包含附件/图片原文件，以及所选任务组拥有的文件历史版本；不包含来源解析缓存，目标用当前受限文档进程重新解析。未包括：当前项目文件、其它任务拥有的文件版本、工具的加密待执行快照、浏览器登录、凭据、定时计划、项目/记忆设置、扩展安装及环境。当前项目文件仍可单独迁移，也可使用统一迁移入口与项目、任务、记忆、技能一起选择；写入文件另经审批，统一回执保存关联和重试进度。独立选择版本仍可使用文件历史迁移入口。旧包没有附件原文时不会凭旧编号猜测或绑定本机同名资料。

## 附件原文与历史引用恢复

新版档案自动保存本组所有附件原文，包括已移除附件，用于保留历史来源。预览列出文件名、所属任务、格式、大小、解析警告及已移除状态。确认时再次核对解析结果及本机附件库容量；有变化要求重新预览。格式支持和页面预览限制沿用 P10，不静默丢弃解析失败的资料。

- 原字节在导出包内与记录一起加密；目标导入后单独写入由本机系统凭据保护的加密文件库，不作为普通会话正文保存。只有确认恢复才创建新的附件记录。
- 每个附件生成新编号，只绑定其原来所属的新任务。原项目路径、生成操作仅保留为来源描述，当前活动路径、版本和操作关联清空，不访问旧绝对路径、不覆盖项目文件。
- 原对话、模型历史、已发送要求、排队消息和图片数据不做字符串替换。任务独立维护旧附件编号到新编号的映射：模型读取旧引用时解析到自己的新附件；消息旧标记用于识别已交付状态。
- 未交付的上传附件仍不提供给模型；排队附件只有消息真正交付后才提供。已移除附件恢复后仍不可读、不会出现在可用列表。原生成成果和项目快照保留原来在任务中的可见规则。子助手不会因为继承上级消息而取得上级附件。
- 映射只用于模型文档读取、图片引用和交付识别，不成为通用管理接口别名，避免旧编号移除原任务的附件。界面始终使用新编号。
- 附件、任务、成员关系、消息和恢复回执在同一数据库事务提交。任一记录失败或提交前取消则全部回退；重复确认和重启不重复添加。再次迁移合并历史来源编号，每任务最多 1024 项，超限拒绝、不截断。
- 取消只停止当前档案操作，不取消其它种类的资料迁移。90 秒处理预算到期请求停止，并等待工作进程清理；底层 I/O 可能延长返回时间。完整档案已发布或恢复事务已提交时仍报告成功事实。预览、取消和失败产生的未引用加密对象留待版本清理处理。

## 文件历史随任务恢复

索引版本 3 自动包含主任务和全部助手各自拥有的已保存文件修改。保存修改前后原字节、相对路径、改名来源、变更类型、原时间和最初来源。P04 旧文本写入记录按同一格式导出；读取和核对已保存正文，不修改来源历史表，也不要求原项目文件夹在线。

1. 导出核对每个版本的大小和摘要，将旧文本版本放入本机加密版本库后装入加密档案。不会复制本机解密密钥、旧文件身份或活动操作凭据。
2. 目标核验仅在内存处理；确认导入才使用目标自己的密钥重新加密。此时没有活动文件历史，也没有项目文件改动。
3. 恢复时必须选择有明确文件夹的本机项目。预览列出历史路径、所属任务、修改类型和修改前后大小，确认时再次核对原文。普通快捷入口使用一个原目录；多个原目录改用分别映射入口，每个原目录选择本机目标项目，缺少映射明确拒绝。
4. 历史行使用新的编号，任务归属映射到对应的新主任务或助手，目录身份绑定目标项目。操作记录只表示“已导入历史”，不安装为可重放的旧命令。每次修改有各自记录，同一路径的多个版本不会相互覆盖或冲突。
5. 文件历史和任务、消息、成员、附件及回执在同一事务中保存；中途失败或提交前取消整组回退。再次迁移保留最初来源。重复恢复及重启返回已有结果，不重新插入版本。
6. 恢复后在“文件与终端 → 修改历史”查看差异或完整版本。另行恢复具体文件时，仍核对当前项目和文件版本、保存被替换内容并按权限审批。审批期间文件改变会拒绝执行；原文件夹不会被访问或覆盖。

旧索引版本 1/2 没有独立文件历史时，仍按原规则允许恢复任务，预览会提示缺少这部分版本；需要补齐应从原任务重新导出。旧包缺少附件原文的限制保持。当前不复制磁盘上的最新文件，也不改写对话中的旧绝对路径；因此有当前文件依赖的任务，继续前还需准备目标文件。新的统一迁移包与分别映射入口覆盖跨资料来源关联和多原目录映射；旧独立包保留其原功能，不猜测没有保存的关联。

## 持久化与保护

- 独立管理命令 `task_archive` 包含导出、核验、导入、列表、分页读取、已存档案另存，以及独立的 `restore_preview` / `restore`。口令使用 `SecretInput`，不进入命令历史或事件日志。
- 格式标识保持 `WPTASK01`，新索引版本 3，记录快照版本仍为 1 / schema 11。兼容索引版本 1/2；空附件和文件历史字段不序列化，保留旧清单摘要和重复导入回执。沿用已有 PBKDF2-SHA256 和 AES-256-GCM 分帧加密。文件头、帧次序、清单与每份原文字节均核验；错误口令、损坏、遗漏/重复内容和尾部附加数据拒绝。
- 只接收固定记录类别和有效任务树；摘要、数量、内容引用需一致。嵌在工具/模型文本里的内容编号不能用来拉取另一任务的资料：来源导出只从所选任务记录的真实内容关联列建立清单，标题、计划或正文中的普通编号文字不建立读取权限。
- 导出在保存线程内取一致记录集；实际运行、排队运行或文件操作进行中会拒绝。仅有尚未执行的新任务 `queued` 状态不算运行中。
- 源已登记凭据出现在早期内容时拒绝导出；目标也会重新检查自己已登记的凭据。历史模型配置的凭据定位信息清除，密钥库不读取、不搬迁。不能保证自动识别用户自己粘贴但从未登记的所有未知秘密，应将口令与备份妥善保管。
- 核验阶段不保存解密内容；确认导入后先写入本机内容库，再在一次 SQLite 事务中登记内容与档案。失败或提交前取消不会留下半份可见档案。可能留下未引用内容，回收仍属版本清理待办。
- 本机档案的会话正文与原来的会话记录使用同一内容库，**不是口令加密的本机保险库**；口令保护的是导出文件。附件原文、重新解析结果及独立文件历史使用本机加密文件库。旧文本变动正文原已存在于过程记录时仍按原归档边界保留，不宣称追溯加密全部历史会话。已存档案无需重复输入口令即可查阅。
- 独立档案回执绑定清单摘要。同编号不同内容拒绝；确认指纹绑定实际加密文件与当前数据目录；重新加密文件需要重新预览。永久删除恢复目标后回执仍在，重复操作显示目标已删除，不重新创建。未新增数据库表或数据版本迁移。
- 档案索引中的正文加入已有内容回收器的保留集合。清理未引用对象后，档案仍可查阅和再次导出；分页时临时生成的行文档可以重建，不作为原数据的唯一副本。

## 容量与验证入口
