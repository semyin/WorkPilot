# P12 所选项目文件迁移

程序：`0.1.0-alpha.12.6`；数据版本：11。属于 Q41、T-P12-03 的一段实现，完整应用迁移仍未完成。

## 使用入口

在已绑定项目目录的任务中打开“文件与终端 → 文件迁移”。

1. 在文件夹之间浏览并勾选文件。选择保留在本次面板内，可展开“已选文件”取消。
2. 选择新的备份文件位置，输入并重复至少 12 个字符的口令，导出 `.wpfiles`。
3. 切换到目标项目的任务，选取备份、输入口令和目标子文件夹，先查看来源到目标的逐文件映射。子文件夹留空代表项目根目录。
4. 有任何重名、链接或不可用位置就阻止新导入，换子文件夹后重新预览。确认后，到面板下方的操作记录查看审批、停止和完整结果。
5. 文件修改历史中可查看此次新建文件，使用原恢复流程撤销文件内容变化。自动创建的空文件夹不属于文件历史，不会被自动删除。

导出的是所选普通文件的当时字节，保留相对目录结构；图片等二进制、空文件、中文和空格名称均支持。每次最多 128 个文件，单文件 64 MiB，总内容 256 MiB，元数据 1 MiB。当前目录列表显示前 256 项并说明截断；不代表自动递归选择整个目录。

## 加密与数据边界

`FileTransfer` 为独立管理命令，口令不经过保存命令、事件或普通内容日志。外层标识 `WPFILE01`、包内版本 1，与历史、设置和扩展备份区分。复用现有分帧 AES-256-GCM 和 PBKDF2-SHA256 600000 次派生；每一帧绑定包头和顺序，大小、摘要与尾部均核验。

导出按文件快照保存确切字节，写入加密临时文件，全部写完并核对项目设置后才使用新文件名发布。不会覆盖已有备份，也不写明文临时文件。多个文件并非整个文件系统的同一瞬间快照，导出期间应避免在其它软件里编辑这些文件。

导入完整解密并验证后暂存于目标的加密版本库，口令不随导入请求进入操作记录。来源相对路径、目标相对路径、摘要和大小进入审批范围与操作结果；目标仍绑定当前任务实际目录身份和权限版本。预览不改写项目文件，但会产生加密暂存对象；未引用对象清理继续属于版本生命周期待办。

拒绝越界、绝对路径、大小写歧义、重复文件、文件与祖先目录冲突、链接/重解析路径及硬链接文件。常见凭据文件名、内部环境目录和其它备份文件不能选入；导出与导入还检查当前应用已登记的凭据原文。这个检查不能识别所有任意业务文件中的未知秘密，用户应按自己选择的内容保管备份。系统凭据、登录资料和模型配置不在此文件迁移流程内。

## 写入、审批和恢复

加密暂存单据通过 `WorkbenchAction::ImportFiles` 接入原有流程。导入实际写入要求“直接执行”模式、未归档任务以及有效项目目录。

- “请求审批”和“帮我批准”沿用文件工作台的人工确认入口；本入口没有发起模型自动审查。“完全访问”直接排队执行。
- 审批绑定所选内容、全部来源/目标路径、项目身份及当前权限。批准时和真正获得项目写锁后重新核对；目标已出现文件时不执行原操作。
- 写入前持久保存所选路径的原状态，结束后记录实际变化；异常退出按已有待核对快照恢复历史，不重跑导入。
- 每个文件使用完整临时文件和仅新增方式发布，不能覆盖已有文件。整批文件系统写入不是一个事务：中途停止或失败可能已经写入前面的文件，这些文件和历史保留。
- 结果的 `copied` 为已确认文件，`unconfirmed` 是尚未完成核对的路径，不能当成“保证没有落盘”。若最后核对失败，明确要求查看实际文件，并保留待恢复快照。
- 备份摘要、当前任务、真实目录身份和目标前缀共同决定原操作编号。重复或重启后请求同一导入只返回原操作，包括完成、失败、停止和中断；不会覆盖用户随后修改的文件。需要另一次导入时，改用新子文件夹并重新预览。

契约：`crates/contracts/src/file_transfer.rs`。格式和迁移：`crates/workbench/src/transfer/file_index.rs`、`files.rs`、`codec.rs`。目录内仅新增写入：`crates/tools/src/file_import.rs`。审批、写锁、快照与停止复用 `workbench/src/service/`。界面：`apps/desktop/src/file-workbench/FileTransferPanel.tsx`，原生路径选择接入 Tauri 现有选择器。

```text
npm run check
npm run test:file-transfer
npm run build
npm run test:file-transfer-desktop
npm run package:p12
```

## 尚未覆盖

本页独立文件迁移不携带会话/多助手及附件记录。后续 `0.1.0-alpha.12.14` 的 [任务档案入口](P12-任务与助手档案迁移.md) 已支持同项目任务/团队、随包附件和任务拥有的文件历史恢复，但不会复制项目当前文件。本入口继续用于准备目标项目的当前文件；两者的统一来源关联、多项目/多原目录映射、扩展旧版本/草稿、文件权限和空目录复刻、保留清理与团队永久删除仍待接续。项目内的附件原文件可按普通文件选取，不会因此自动还原会话里的附件记录。受签名保护的更新和完整首版验收尚未完成。
