# P13 Windows 集成验证记录

日期：2026-10-04。状态：进行中。当前候选 alpha.13.4，最新结论见末尾 r3 章节；前面的版本、命令和失败保留历史范围，尚非 Windows V1 验收通过。

## 首轮版本与测试环境

先将 P12 实现及证据提交并推送 `d20c5b25e2d92ee7e3758d4b3d21e55b489ff96b`，远端 `main` 已核对。P12 的 `0.1.0-alpha.12.15` 交付目录保持原样；新改动使用独立 P13 预览 `0.1.0-alpha.13.1`，SQLite 数据版本仍为 11。本轮新代码与文档尚未追加提交。

Windows 11 家庭版 x64（10.0.26200）、AMD Ryzen 7 7840H、16 个逻辑处理器、约 31.3 GiB 内存。测量时暂停本项目编译及其它性能测试；用户其它软件和系统后台活动没有关闭，因此不是隔离实验室或干净 Windows 结果。

全部新增负载使用本机固定回复服务、独立任务和数据目录，不调用付费模型，不读取用户项目或浏览器资料。原生桌面测试实际启动 Tauri 与 WebView2，通过本机调试连接操作正常工作台；不使用 P00 诊断页模拟界面结果。

## 本轮实现与发现

- 已完成任务没有新消息时，“继续任务”改为不可点，并提供发送新要求的提示。此前后台已正确拒绝重复运行，但界面允许点击，显示容易误解的配置错误。修复没有放宽后台执行条件。
- 恢复后保留的排队/引导消息仍可继续；中断、失败后的手动继续保持原行为。原生验证覆盖重复新要求与继续，并回归工作台及多助手恢复。
- 增加独立 P13 打包入口和版本阶段检查，防止新版本打包覆盖旧 P12 交付；新增完整迁移包的 Git 忽略规则。
- 对照源码与历史证据整理 [验收矩阵](P13-验收矩阵.md) 和 [体验清单](P13-用户体验清单.md)。P05 真实协作是同一个 `qwen3.8-flash` 模型的三个协议配置，不能算实际不同模型已验收；P10 合成图片也不能代替真实图片服务。

## 测量口径

使用至少 20 个样本，保存全部原始值，按排序后对应位置计算 p50、p95 和最大值，不只挑最好一次。

- 引擎：1/4/8 个独立任务和 1/3/8 个助手各持续约 10 秒；分别测控制回应、任务列表、详细状态、协作状态。模型等待与本机控制响应分开。
- 停止：20 次真实 Node 父子进程，分别记录取消确认、两个进程实际退出和任务成为中断；实际心跳文件停止写入也核对。
- 桌面：正常工作台的按钮、输入、执行事件显示和停止各至少 20 次。时间截止点是页面实际状态或文字发生变化，不是物理屏幕像素刷新；文字可在页面滚动范围之外，不能将 DOM 更新测量代替滚动位置/屏幕可见性验收。停止反馈测的是任务标题状态，任务侧栏的独立刷新不在这个数值内。事件从引擎保存时间计算，不包含此前模型等待。
- 启动：20 个全新应用/WebView 数据目录，从启动进程到自动化观察到引擎连接和输入可用。包含自动化连接开销，Windows 文件缓存没有清除，因此不能称为真正冷启动或直接判定 3 秒冷启动目标。
- 资源：进程按真实身份归属，以 250 ms 间隔记录内存、CPU、句柄等。多进程界面应按同一时刻合计，不能把单进程最大值冒充整个界面占用。专用网页浏览器与 Office 工具未参与时明确未覆盖。

## 实际结果

### 构建与标准检查

`npm run check`、Windows 正式构建和 `npm run package:p13` 均通过。标准检查实际运行 206 项 Rust、11 项 Node 固定服务/脚本和 3 项 PDF 文字检查；另有 3 个标记忽略的 Rust 入口，保留其原有环境/专用进程边界，不算通过数量。格式、类型、Rust 静态检查和界面构建通过。

最终新增脚本完成后再次检查格式及单文件规模：480 个维护中代码文件，最长 964 行，均未超过 1000 行。界面构建仍有主分块超过 500 kB 的体积提示，没有编译错误；本轮没有通过提高警告阈值掩盖提示。

## 失败与修正

1. 初次桌面脚本取错运行编号字段，没有正确关联已保存事件；修正为实际 `latest_run.run.id`。这是测试脚本错误，见 [原始报告](../../artifacts/workpilot-p13-baseline-2026-10-04/evidence/initial-desktop-field-mismatch/report.json)。
2. 第二次在已完成任务没有新消息时再次点击继续，后台拒绝，脚本超时；同时发现上述界面入口和提示问题。修正脚本为每次提供新要求，产品界面单独修复。见 [原始报告](../../artifacts/workpilot-p13-baseline-2026-10-04/evidence/initial-desktop-continuation/report.json) 和 [原始画面](../../artifacts/workpilot-p13-baseline-2026-10-04/evidence/initial-desktop-continuation/failure.png)。
3. 引擎脚本准备期修正配置修订号、协作等待状态识别及 Windows PowerShell 多目标数组读取；正式结果与短校验分别保存，不把短校验当成 20 样本基线。
4. 审查发现旧安装打包入口未检查阶段，可能把 P13 程序写入 P12 安装目录；已在任何打包写入前增加版本/构建/交付一致性检查。实际运行两个旧入口均按预期拒绝，旧两份清单校验值不变，见 [保护检查](../../artifacts/workpilot-p13-baseline-2026-10-04/evidence/package-guards.json)。
5. 自动测试退出的原超时只包住进程等待，没有包住退出通信；已将整个退出过程纳入超时并清理定时器，同时补观察控制台错误。最终 21 个测试桌面均按正常退出流程关闭。
6. 第一轮 P13 引擎基线的功能检查通过，但 Windows 自然复用了一个已退出工具的进程编号，新增资源守卫将整份报告判为失败。已保留原始记录；修正为进程编号、真实开始时间与程序路径共同识别，再按新口径复测。这不是产品任务未停止，也不把旧进程的资源样本算给新进程。

观察项 T-P13-01：英文停止截图中，任务标题已中断而侧栏仍短暂显示运行；两处使用不同刷新周期。当前停止测量只覆盖标题状态，需要下一批量化并统一侧栏同步。另有滚动范围之外的文字更新，已在上述 DOM 测量口径中说明。
