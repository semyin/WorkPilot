# P05 多助手调度与交付

日期：2026-10-02。实现仍沿用 Rust / Tokio / SQLite / React / Tauri 2。P05 增加团队调度和基础操作界面；正式工作台布局属于 P06。

## 1. 助手与任务的实际关系

每个成员都有自己的内部任务、助手、会话、模型配置、执行记录与检查点。成员不共享一串模型聊天。主助手通过工具分派、等待和检查成果。

```text
主任务 → 主助手（独立会话）
  ├─ 成员 A（独立模型配置、会话、文件成果）┐
  ├─ 成员 B（独立模型配置、会话、文件成果）┴→ 成员 C（等待 A、B）
  └─ 检查每个成员的交付 → 回读实际成果 → 汇总
```

任务列表显示根任务；成员从协作面板进入。`agents.parent_id` 表达助手关系，`team_members` 关联成员任务与根任务。每个成员继续使用 P03 的执行循环、模式和 P04 的工具通路。

schema 5 增加团队设置、运行开关、成员、依赖、分派回执、等待记录。旧数据库通过已有备份机制升级；不能用旧引擎打开新数据库。一次分派的全部成员、依赖、事件与去重回执在同一数据库事务提交。

## 2. 分派、等待与运行数量

执行模式下按需提供五个工具：`delegate_agents`、`wait_for_agents`、`inspect_agent`、`review_agent_result`、`replace_agent`。聊天和规划模式不开放分派。模型必须已确认支持工具；原 P03 受控样本默认不启用团队。

| 设置 | 默认值 | 可设置范围 | 计数含义 |
|---|---:|---|---|
| 全局同时运行数 | 4 | 1—16 | 包括主助手和成员的执行 Run |
| 一个根任务同时运行数 | 3 | 1—8 | 所有层级成员共同使用，含主助手 |
| 累计成员数 | 16 | 1—32 | 接替也计入，旧成员不释放名额 |
| 协作深度 | 2 | 1—3 | 根任务的直接成员为第 1 层 |
| 每项分工接替次数 | 2 | 0—5 | 沿接替关系累计 |
| 内存中的运行/排队作业数 | 32 | 当前固定 | 超出的成员保留在数据库，等有空位再启动 |

引擎每 100 毫秒检查待调度成员。依赖必须已经完成且有交付记录；成员首次启动时获得依赖的摘要和实际成果引用。

主助手调用等待工具时保存等待记录，结束本次 Run，并让出运行名额。成员交付后再接续主助手；因此全局只有一个名额时仍能执行多层协作。成员因等待自己的下级而暂停，不当成需要用户回答的问题通知上级。模型错误会停掉该成员，不重试原请求；独立分支继续。

这些默认数量是工程起点，可在界面修改；本轮功能测试和本机样本不代表跨设备性能目标已达成。运行期间不能修改并发设置，避免新旧限制同时生效。

## 3. 上下文与模型覆盖

成员继承父任务目标、限制、项目规则、用户方向及已授权目录，获得自己的具体职责。成员从新的会话开始，不复制主助手整段模型历史。成员模型可显式选择，也可继承创建时主助手实际使用的配置。

主助手获得精简成员状态和最多 32 个已配置模型的目录；这里没有密钥或系统凭据。用户可在开始前手动添加成员，并修改尚未开始成员的职责、目标和模型。依赖通过已有成员选择；修改已建立成员时不更改依赖，避免把正在执行的关系图改成循环。需要不同依赖时新增明确的分工。

成员标识支持中文；不能空白、含空白/控制字符或超过 64 字节。同一父任务下不能重名。循环依赖、不存在的依赖、超人数或超深度的批次全部拒绝，不留下半个团队。

## 4. 交付、检查与接替

结构化交付包含成员与 Run 来源、状态、摘要、完整结果引用、文件路径与版本引用、近期步骤、错误和用量。摘要最多 8000 个字符，完整内容可从引用读取。模型未返回用量时显示“未返回”，不当作零。

主助手必须先读取成员交付，再对同一份交付编号写入检查结论；完成成员才允许被接受。失败成员可以显式放弃，但不能标为成功。还有未处理成员时，根任务不能直接完成。引擎保证检查动作与来源可追溯；成果内容是否正确仍需要模型检查和用户验收，不声称仅凭一个接受标记就证明答案正确。

失败或中断成员可由主助手或用户显式新建接替。新助手保留同样目标、必要约束、依赖、原错误、原交付与已有成果引用；旧助手和旧错误保留。依赖边改为新助手，之后按旧分工名称添加的依赖也指向最新接替。接替是新会话，不能把旧请求偷偷重发。

成员总数和接替次数同时限制继续创建；不能通过不断更名无限派人。达到上限返回明确错误，由主助手询问用户或结束受限分支。放弃成员会停止该分支的后续调度。

## 5. 权限、文件与停止

成员的有效权限同时受创建时上限和当前父任务限制。父任务收紧权限、取消命令或改变目录，成员不能继续使用旧授权；父任务后来放宽权限也不会自动扩大旧成员的创建时上限。成员不能独立配置更高文件权限。

审批仍绑定成员任务、具体参数、文件版本和权限版本，不能从其他项目借用票据。主助手分派不等于代替用户审批。每次启动真实工具前检查所有父级运行开关。

同一实际目录的受管理写入和命令使用共同的排他执行权，跨根任务也生效。阻塞工作取消后，执行权仍保留到实际工作退出。受管理写入继续要求准确的旧文件哈希；竞争创建、陈旧覆盖和审批期间人工修改都不能静默覆盖。

这保证受管理工具的版本冲突可见，并序列化命令；任意“完全访问”命令的语义和外部影响仍服从 P04 边界，不能把命令前后清单称作完整回滚。P07 继续补全文件历史和恢复。

停止根任务时，在同一持久化停止操作中关闭整棵树的调度，再传播取消。运行中的模型请求取消，工具按 P04 清理自有进程。完成、错误或中断的分支停止继续调度下级。隐藏窗口继续执行；彻底退出停止，重开不自动派人。用户继续根任务时只恢复尚未完成且未放弃/未被接替的分支，已完成成员不重复执行，失败分支不自动重试。

## 6. 当前界面与工程入口

“任务执行”新增协作面板：成员、模型、目标、依赖、状态、错误、接替来源、交付、用量，以及进入成员的过程与审批。新建执行任务可选择“先创建并设置分工”。根任务可以设置团队上限和全局数量；基础页面提供手动添加、覆盖、接受、放弃和接替入口。

关联实现：`contracts/src/team.rs`、`storage/src/team.rs` 与迁移 005、`engine/src/tasks/team_control.rs`、`runtime/src/team.rs`、`runtime/src/mutation.rs`、桌面 `TeamPanel.tsx`。详细证据见 [P05 验证记录](P05-验证记录.md)。
