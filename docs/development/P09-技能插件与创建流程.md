# P09 技能、插件与创建流程

更新日期：2026-10-03。实现基线为 Windows x64；macOS/Linux 的本地进程隔离仍待各平台实机验证。

## 用户可以看到什么

工作台顶部增加“技能与插件”。可搜索已安装项目、检查目录或 ZIP、预览说明及资源、确认启用、停用、卸载、导出和回退历史版本。全局扩展供各项目使用，项目扩展只向对应真实文件夹的任务提供。

“让 AI 创建技能”准备一个规划任务，用户选择自己的模型并启动。流程如下：

```text
描述用途 → 查阅创建指导 → 必要时补充信息 → 生成说明及配套文件
                                                    ↓
实际使用 ← 测试与改进 ← 用户确认启用 ← 检查草稿、资源与权限
```

软件随附 WorkPilot 版 `skill-creator`，位于 [内置技能](../../crates/extensions/builtin/skill-creator/SKILL.md)。它参考本机 Codex `skill-creator` 的编写方法，自行编写适合 WorkPilot 的指导；不依赖 Codex 专用安装位置、初始化器或私有接口。指导通过与普通技能相同的搜索、读取入口按需加载。用户停用或卸载后，重启不擅自恢复。

内置指导强调实际用途、必要的澄清、精简说明、按需引用和真实产物验证。模型生成的技能始终是草稿：格式检查通过也不会自动启用，更不能凭“测试成功”的文字获得权限。真实模型生成质量仍要在用户实际需求中体验。

## 模块边界

| 模块 | 职责 |
|---|---|
| `crates/extensions/package.rs` | 目录/ZIP 读取，清单、SKILL 元数据、路径、数量及摘要校验 |
| `manager.rs` | 安装、范围、版本、依赖、系统凭据、会话生命周期与内置指导 |
| `mcp.rs` / `oauth.rs` | MCP 消息通信及公开客户端浏览器授权 |
| `model.rs` / `runtime/extensions.rs` | 按需提供技能入口及动态工具定义；保持已有模型循环 |
| `workbench/service.rs` | 同一任务的模式、审批、停止、操作记录和文件历史 |
| `storage/migrations/008_extensions.sql` | 安装、版本、草稿、工具目录、凭据引用与操作历史 |
| `ExtensionPanel.tsx` | 用户管理、检查、确认、登录与测试界面 |

`Skill` 是方法及资源，MCP 是外部工具通信方式，扩展包是安装和分发单位。核心任务循环继续由 Rust 控制。

## 包与技能格式

可以直接导入含 `SKILL.md` 的目录/ZIP，或含 `workpilot-plugin.json` 的多技能/服务扩展。清单的实际字段以 [契约](../../crates/contracts/src/extension.rs) 为准：格式号、名称、版本、说明、技能路径、服务定义和依赖。示例见 [报告检查技能](../../examples/extensions/report-checklist/SKILL.md)。

- `SKILL.md` 支持 YAML `name`、`description`，以及 `license`、`compatibility`、`allowed-tools` 等说明。当前名称采用 ASCII 小写字母、数字和短横线。多技能目录要求名称与所在目录一致。
- 脚本、参考资料和二进制模板保留原文件；按需读取或复制。文字草稿最多 64 个文件、合计 512 KiB；AI 草稿入口不生成未知二进制附件。
- `allowed-tools` 只作为说明，不赋予任务权限。`agents/openai.yaml` 等其他产品的私有配置可以作为资源保留，但不承诺解释其私有策略。
- 每包最多 512 个文件，单文件 8 MiB，总计 32 MiB；拒绝链接、路径穿越、大小写冲突和常见凭据文件。已登记凭据不能重新导入为技能正文。
- 网上安装目前要求直接返回 ZIP 的 HTTPS 地址；本机协议测试允许回环 HTTP。不跟随重定向，不接收带用户名、密码或查询参数的下载地址。

先形成独立暂存预览，再校验内容并切换 SQLite 中的生效版本。依赖不满足、内容变化或版本冲突不会替换当前生效版本；不在后台全局安装未知依赖。旧版本保留以便回退。卸载保留项目文件和历史产物；长期缓存回收、整体迁移和完整运行环境交付由 P12 联合处理。

P12 已接续当前安装版本的批量加密备份与迁移，见 [技能插件迁移](P12-技能插件迁移.md)。导入先保存为停用状态，允许随后在本机准备依赖/凭据；启用时重新检查依赖、资源和声明的运行环境，实际执行仍复用原任务审批。原单包 ZIP 流程保留；旧安装版本与草稿的整体迁移、缓存回收继续单列待办。

## MCP 兼容范围

实现本地标准输入/输出消息及远程 Streamable HTTP，支持 JSON、POST 返回的 SSE、初始化、工具分页发现、参数校验、调用、错误、取消通知、会话编号和工具变更通知。协商接受 `2025-03-26`、`2025-06-18`、`2025-11-25`；实际本轮协议样本为 `2025-11-25`。

每次经批准的发现/调用打开一段任务会话，调用前重新发现并核对工具描述摘要，结束即关闭。已安装但未经发现的服务不会凭空产生模型工具。收到工具变更通知清空旧目录，下一次重新检查。新增服务通过动态 `mcp_*` 名称接入，不给每个工具添加执行循环分支。

因此，当前不兼容必须在同一进程或会话内跨调用保留状态的服务，例如依赖内存中浏览器页面句柄的本地服务器。这类服务需要另补受管理的持续会话和相应文件变更观察；不能用一次发现成功声称完整兼容。已实现的 P08 浏览器会话不受此限制。

当前没有实现旧式 2024 HTTP+SSE、GET 长连接订阅/断点重连、采样、资源订阅或交互式表单等可选能力。服务的客户端请求仅支持 `ping`，其他能力明确返回未启用。连接中断或会话失效不重放原工具调用；远端已经发生的效果可能需要人工核对。这些边界不能称为支持所有 MCP 版本和服务器。

## 凭据和授权

HTTP 支持无认证、独立 Bearer 凭据和浏览器 OAuth。后者使用资源/授权服务器元数据、公开客户端编号或动态注册、PKCE S256、一次性 state、issuer 和资源绑定，以及五分钟有效的本机回调。用户在正常浏览器页面授权，令牌进入系统凭据存储；普通数据表只记录引用。失效后显式重新登录，不自动刷新并重放有副作用的调用。

本地服务只接收清单声明、由用户单独配置的凭据环境变量；不会继承模型密钥。安装包导出不包含单独保存的认证信息。正文扫描不能推断所有未知秘密，作者仍不应把账号凭据写进脚本或资料。

本轮真实授权证据来自本机运行的 OAuth 协议测试服务，不等于已验证所有商业服务、企业单点登录或需要客户端密钥的注册流程。

## 权限、停止与记录

- 聊天/规划模式只提供说明读取等入口；规划可保存内部草稿。执行外部工具必须进入执行模式并绑定项目。
- 不采用插件自报的只读/安全标签作为放行依据。未知第三方进程及远端工具按需要人工确认的外部动作处理；“请求审批”和“帮我批准”的此类动作等待人工，完全访问按已有规则直接执行。
- 审批绑定包版本、安装修订、参数、工具结构、真实项目和权限版本。停用、卸载、更新及凭据变化都会使旧调用失效。
- Windows 本地进程复用 AppContainer 和进程组：审批模式限制项目写入及已安装包读取，禁止网络；完全访问使用当前账户权限，同时保持停止和退出时的进程回收。需要联网的本地服务目前需用户明确选完全访问，或改用远程 HTTP 服务。
- Node 使用内容校验过的专属副本；不修改用户安装的 Node 文件权限。遇到无法安全变更的空访问控制边界会拒绝运行。
- 本地进程和脚本的项目变更进入 P07 历史；模板复制也绑定目标文件版本。输入、输出、错误与审批通过原操作记录查看。停止或停用会中止本地进程，远端取消通知不等于撤销已发生的效果。

## 验证入口

```text
npm run test:extensions-engine
npm run test:extensions-model
npm run test:extensions-desktop
npm run check
```

前两个命令使用真正的 Rust 引擎、文件、受管理进程和本机 MCP 协议服务；模型端为固定回复测试服务。桌面命令需要先 `npm run build`，然后操作真实 Windows WebView。详细结果及失败修复见 [验证记录](P09-验证记录.md)。
