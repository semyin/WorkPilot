## 恢复证据

完整进程测试通过 test 通道注入实际退出码 86，随后重新启动同一数据目录：

1. **工具前退出**：保存 prepared，启动不请求模型。手动继续执行未开始工具，再请求下一轮。
2. **工具中退出**：保存 needs_review；继续先暂停，仍不请求模型。确认未执行后允许执行。
3. **效果落盘后退出**：原样本写入与执行凭据已经保存；手动继续采用原结果，写入操作不会重做。
4. **人工提供结果**：不确定动作由用户提交已核对结果，新执行采用该结果；原失败/中断尝试继续保留。

每个恢复样本只发起原工具决定和最终回复两次模型请求。多次人工点击继续若仍缺核对，不额外请求模型。原模型步骤、工具编号、前后执行关联均保留。

这不能证明任意外部工具都能“恰好执行一次”；P03 内部测试记录的原子保存保证不直接推广到 P04 的文件、终端与外部服务。

## 性能样本与限制

六个长任务同时进入调度时，四个运行、两个排队；取消排队项不会请求模型，控制命令没有等待任务槽位。一次本机控制回复观察约 2 ms，原始数值见引擎报告。这只是本机样本，不是跨设备指标、云端延迟或长跑承诺。

单次模型和工具步骤、运行时间、上下文与结果均设有上限。原始结果使用磁盘引用，任务面板只显示最近 64 个步骤，完整事件分页读取。固定目标和要求超过上下文容量时暂停，不丢弃要求来继续。

未验证真实服务多轮复杂推理、4 小时长跑、多助手、外部操作权限、云端服务实际收费、Mac/Linux 实机和远程构建流水线。正式工作台、真实工具和多助手分别见后续 P04—P06。
