## 发现与修复

1. 生成已完成却显示取消：操作结束的清理误设置了共享停止标记。已区分临时解析和外部操作的停止标记生命周期。
2. Windows PDF 字体路径与新版 PDF.js 的释放接口不匹配：改用规范路径和加载任务的释放接口。
3. PDF 字体子集导致实际画面缺字，但文字提取仍正常：查看页面图片后发现，改为完整字体嵌入并检查字形覆盖。原失败页面保留，不把最初的结构检查当作视觉验收。
4. 原生界面首次小文件导入超过测试默认 5 秒：文档处理器改为按需加载库，界面保留进度和取消；测试使用允许后台处理完成的等待，不把等待上限当作性能指标。
5. 图片服务选择框缺少明确的可访问名称：补上选择框名称，继续执行真实桌面路径复测。
6. 文档取消在运行环境校验阶段等了 3262 ms：大块校验改为分块检查取消标记，并在读取上传临时文件前登记取消归属。相同本机样本复测为 12 ms；图片请求取消为 66 ms。这是单次开发测试，不是性能分位数承诺。

## 复现入口

在项目根目录先运行 `npm ci` 和 `npm run documents:prepare`，准备锁定的文档依赖和字体，然后依次运行：

1. `npm run check`：基础检查。
2. `npm run test:media-engine`：实际文件、版本、错误、加密文件和图片协议；生成后续界面测试使用的样本。
3. `npm run test:media-model`：三种模型协议中的实际附件和生成流程。
4. `npm run build`，再运行 `npm run test:media-desktop`：使用正式桌面构建进行原生界面测试。

分发复测将 `WORKPILOT_ENGINE_BINARY` 指向交付包的 `preview/workpilot-sidecar.exe`，将 `WORKPILOT_DESKTOP_BINARY` 指向 `preview/WorkPilot.exe`，直接运行相应测试脚本，不重新编译这两个文件。具体校验值和记录在交付证据中保存。

独立 Office 验证使用 `node scripts/media-office-test.mjs`，前提是本机已在 `.local/p10-office-check/extracted` 解包官方 LibreOffice 26.8.0；它只验证本项目固定生成样本，并非产品日常预览路径。`office_probe` 的两个受限入口失败证据继续保留。
