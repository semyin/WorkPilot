## 发现与修复

1. 生成已完成却显示取消：操作结束的清理误设置了共享停止标记。已区分临时解析和外部操作的停止标记生命周期。
2. Windows PDF 字体路径与新版 PDF.js 的释放接口不匹配：改用规范路径和加载任务的释放接口。
3. PDF 字体子集导致实际画面缺字，但文字提取仍正常：查看页面图片后发现，改为完整字体嵌入并检查字形覆盖。原失败页面保留，不把最初的结构检查当作视觉验收。
4. 原生界面首次小文件导入超过测试默认 5 秒：文档处理器改为按需加载库，界面保留进度和取消；测试使用允许后台处理完成的等待，不把等待上限当作性能指标。
5. 图片服务选择框缺少明确的可访问名称：补上选择框名称，继续执行真实桌面路径复测。
6. 文档取消在运行环境校验阶段等了 3262 ms：大块校验改为分块检查取消标记，并在读取上传临时文件前登记取消归属。相同本机样本复测为 12 ms；图片请求取消为 66 ms。这是单次开发测试，不是性能分位数承诺。

## 复现入口

在项目根目录先运行 `npm ci`、`npm run documents:prepare`、`npm run office:prepare`，准备锁定的文档依赖、字体和固定办公转换环境，然后依次运行：

1. `npm run check`：基础检查。
2. `npm run test:media-engine`：实际文件、版本、错误、加密文件和图片协议；生成后续界面测试使用的样本。
3. `npm run test:media-model`：三种模型协议中的实际附件和生成流程。
4. `npm run build`，再运行 `npm run test:media-desktop`：使用正式桌面构建进行原生界面测试。
5. `npm run test:office-preview`：实际办公版式、缓存分页、跨任务拒绝、停止重开、新旧快照和外部图片链接检查。

分发复测将 `WORKPILOT_ENGINE_BINARY` 指向交付包的 `preview/workpilot-sidecar.exe`，将 `WORKPILOT_DESKTOP_BINARY` 指向 `preview/WorkPilot.exe`，直接运行相应测试脚本，不重新编译这两个文件。具体校验值和记录在交付证据中保存。

早期独立 Office 验证使用 `node scripts/media-office-test.mjs`，前提是本机已在 `.local/p10-office-check/extracted` 解包官方 LibreOffice 26.8.0；它只验证固定生成样本。现在产品日常预览使用下面的新路径；`office_probe` 的早期命令行失败证据继续保留。

### 失败根因与修正

1. 安装目录检查失败：LibreOffice 会枚举安装目录的直接父目录；改为应用专属 `office-runtime/office` 双层目录，只读授权外层，未扩大到用户或项目祖先目录。
2. 命令行入口卡在实例通信：受限 Windows 进程中的常规命名管道启动不适用，改用 LibreOfficeKit 初始化，避开该实例通信路径。
3. 直接调用 LibreOfficeKit 的文件加载接口时，Word 可用，但 Calc 创建窗口跨线程互等；首次集成测试因此超时。改由公开 UNO 主线程回调统一加载、导出和关闭，DOCX/XLSX/PPTX 全部通过。采用官方随附 Python 只是该转换工具内部适配，主执行引擎仍为 Rust。
4. Python 运行时返回的 Windows 长路径前缀导致文件 URL 不正确，已在固定工作进程中规范化。转换保留只读、禁宏、禁止更新与无网络边界。
5. 测试期间运行组件与清单不同步时，被摘要核验拒绝；完成运行环境准备后再启动测试。正式包在同一构建下复测，不把旧运行环境的结果挪作新版本证据。
6. 最后复核补充输出边界：工作进程退出后，宿主仅读取大小受限的普通结果文件，拒绝符号链接或其它重解析文件，避免转换输出把读取重定向到别处。重新构建后的通路通过最终复测。

首次集成失败保存在 [失败记录](../../artifacts/workpilot-p10-layout-2026-10-03/evidence/first-integrated-preview-failed.txt)，原 P10 的两个命令行失败也仍保留。当前 **T-P10-01 已解决，E-P10-01 真实图片服务仍未验证**；其它用户体验和平台条件不变。

## 2026-10-04：P12 迁移复测发现生成 PDF 数字提取问题

新增 **T-P10-03，尚未修复**。使用现有 `create_document` 生成含 `Portable generated output 42` 的 PDF，源文件的文字读取把数字转换为私用区字形。原页预览仍可见 4 和 2，但间距偏宽；Word 对照文档文字读取与预览中的 `42` 正确。

这是源 PDF 已存在的问题，不是迁移后才出现。P12 实测导出和导入的原文件大小、摘要相同，重新解析的文字单元也逐项相同。当前生成器使用完整嵌入字体；字体映射是待核对方向，尚未宣称根因已修复。后续需要同时断言数字原文、中文和页面显示，避免仅切回字体子集而重现早期缺字。

复现与检查脚本为 `scripts/media-transfer-test.mjs`，最终报告和图像保存在 [附件迁移证据](../../artifacts/workpilot-p12-media-2026-10-04/README.md)。既有 P10 历史交付不重写；本补充不改变真实图片、用户体验及其它平台的待验收状态。
