## 关键样本

1. 包预览和摘要确认；项目扩展对其他项目不可见；确认前不能获得技能能力。
2. 实际 Node MCP 进程完成发现和项目写入；写入产生文件历史；读取未授权的私有相邻文件被系统阻止。
3. 技能脚本生成实际文件，模板复制保留目标版本和历史。
4. 停止操作及停用扩展均回收实际进程；排队旧审批不能在停用后执行。
5. HTTP JSON 和分片 SSE、会话及协议头、服务端 ping、工具错误、断流只发一次、取消通知和工具结构变更。
6. 真正运行的本机 OAuth 服务完成发现、动态注册、PKCE、state/issuer/resource 核验和系统凭据保存。错误 state 被拒绝。
7. 认证信息在普通记录中被遮盖，不进入导出包；含已登记凭据的技能正文被拒绝。
8. 缺依赖升级不影响旧版；正常升级后可回退；卸载保留用户文件。内置创建指导的停用、卸载选择在重启后保持。
9. 模型测试服务先搜索并读取内置 `skill-creator`，再保存草稿及资源；确认后在新任务读取并运行脚本。三种协议都能发现新增 MCP 工具、经过审批并继续，实际调用没有因继续而重复。
10. 原生界面完成目录预览、查看 SKILL 内容、确认启用、发现/测试工具、查看完整记录、停用/启用和创建真实模型任务；AI 调用扩展等待审批时，任务内的“查看扩展待批准操作”可打开对应审查入口；中英界面没有横向溢出或脚本错误。

模型测试采用本机固定回复服务，没有使用本轮用户收费模型凭据。因此这些结果证明创建和调用链路，不能证明实际模型写出的技能在所有业务中有效。

## 发现与修复

- 首次本地进程测试暴露 Windows 空访问控制表处理缺陷：给原本不限制访问的 Node 程序添加单项规则，意外丢失原访问范围。普通继承重置没有恢复其特殊原状态；随后通过用户管理员操作恢复原权限。Node 22.23.2 可正常启动，文件摘要与此前交付副本一致。修复后使用私有 Node 副本，并增加空访问控制表不被改写的回归测试。未改变用户程序字节。
- Node 在隔离环境启动时尝试读取卷根目录，导致拒绝访问。对已禁止链接的扩展包采用保留路径的加载参数，实际隔离读写与相邻文件拒绝测试通过。
- 旧插件审批在停用后原先只报错但仍显示等待；现在记录为失败，保留未执行的明确结果。
- 原生界面的测试参数框缺少稳定的可访问名称；补上名称后，实际输入、审批、调用和输出查看通过。
- 原版技能校验脚本最初缺少 PyYAML。仅在 `.test-results/skill-validator-deps` 准备固定版本 6.0.3，再运行校验；没有全局修改用户 Python 环境。
- 第一次分发复测发现直接 `cargo build` 的桌面程序缺少正式网页协议设置，启动后仍寻找开发页面。重新执行项目标准 `npm run build`；增加桌面/引擎构建摘要回执，P09 打包必须核对回执，防止混入未经正式流程构建的程序。
