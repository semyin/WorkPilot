# P12 项目设置与记忆迁移

日期：2026-10-04。当前版本 `0.1.0-alpha.12.4`，数据版本 11。接续 T-P12-03：项目名称和规则、所选模型配置与记忆迁移；新增可选的记忆全历史、候选、已拒绝和已删除记录。此前的设置包与文件历史备份保持可读；完整资料迁移尚未完成。

## 用户操作

1. 设置 → 项目设置与记忆迁移，选择源项目。默认勾选它的默认模型，可以取消或勾选其它模型；记忆需要自行勾选。
2. 默认只选择当前已确认记忆。需要保留旧版本或未生效的记录时，勾选“包含记忆历史与未生效记录”，再选择记忆；切换该开关会清空原选择，便于重新核对。选择新的保存位置，输入两次至少 12 字符的口令，生成 `.wpsettings` 文件。软件不保存口令，遗失后无法解密。
3. 在目标电脑打开同一入口，选择设置包，填写口令、新项目名称和已经存在的目标文件夹，点击预览。
4. 查看项目规则、模型地址、记忆内容与作用范围。遇到同名项目、已绑定文件夹或数量超限时，先调整目标；不能覆盖已有项目。
5. 确认后建立新项目。项目权限为“请求审批”，模型获得新的编号，现有配置与全局默认模型保持原样。使用密钥的模型需在模型设置重新填写凭据，原连接测试结果不作为新机器已验证的依据。

确认导入后，只有当前已确认且未删除的记忆生效；候选仍待确认，已拒绝和已删除的记录保持不生效。通用记忆仍作用于所有项目，项目记忆绑定新项目。预览展示状态和历史版本数量，导入后可在“记忆”中查看、恢复旧版本；恢复候选不会自动确认。旧任务编号只作为来源文字/回执保存，不连接到目标应用中碰巧同名的任务。

源项目文件夹暂时不可用时仍能导出这些已保存的设置，导入不会移动或修改文件夹内的实际文件。不同机器的真实使用仍需补测；本机两个独立数据目录的测试不能代替跨机器验收。

## 范围与冲突规则

- 一个包包含一个项目的名称、规则、旧目录提示、所选模型和记忆；最多 128 个模型、128 条记忆、1 MiB 明文设置。启用历史时，每条最多 256 个已保存版本、全包最多 2048 个版本；超限直接拒绝，不能静默截断。
- 只允许该项目或通用作用范围，历史版本逐条核对。旧版本曾属于其他原项目时拒绝导出，等待后续统一多项目映射；不会将它伪装为通用记忆。默认模式仍拒绝候选、已拒绝和已删除记录，历史模式允许并保留原状态。
- 历史模式保留原版本号、正文、状态、删除标记、时间及来源文字；生成新记忆编号并映射每个版本的项目范围，清除活动的旧任务链接。导入时额外添加一个导入版本；以后修改和恢复继续追加版本，原版本仍可查看。已删除条目需在记忆面板打开“显示已删除”后查看。
- 模型凭据引用、系统凭据、浏览器登录信息都不导出。模型接口沿用三协议配置校验，禁止带用户名、密码或查询参数的服务地址；迁移过程不连接模型服务。
- 新建模型名称增加 `(imported)` 标识，复制参数与用户声明的能力，清除先前实际连接观察。没有把导入等同于模型连接成功。
- 只携带项目显式指定且已勾选的默认模型。未勾选或原先继承全局默认模型时，不改写目标应用的全局默认值；导入后可在项目设置中另行选择默认模型。
- 目标目录按真实目录身份核验；同名项目或已绑定目录拒绝导入。已有同名模型按新的模型配置添加，不覆盖，也不自动复用其密钥。
- 同一包在同一目录只导入一次。再次点击或重启后重试返回原回执；不同备份之间不做含义相近的记忆去重。
- 不包含会话、助手运行状态、技能/插件、定时计划、项目实际文件、附件或文件历史。跨多个原项目的记忆历史、完整会话来源引用与统一选择映射仍在 T-P12-03，未改变 Q41 要求。

## 实现

使用独立 `ProjectTransfer` 管理命令，与文件历史迁移共用后台互斥与退出取消。不会把口令保存成普通操作参数、事件或去重记录，也没有新增模型工具入口。主窗口提供原生保存/打开文件和选择文件夹入口。

外层格式标识仍为 `WPSET001`；默认设置文档版本 1，包含记忆历史的文档版本 2。新版支持旧包，旧程序会明确拒绝版本 2。复用文件历史备份现有的 ring 密码实现和固定参数：随机盐、PBKDF2-HMAC-SHA256 600000 次、AES-256-GCM 验证加密。设置整体加密，未知格式、错误口令、损坏、超限和多余尾部均拒绝。历史文件 `WPHIST01` 的原格式未改变，两个入口不混用。详细密码参数依据见 [历史备份设计](P12-历史备份与恢复.md)。

导出使用加密临时文件，写完同步后才发布，禁止覆盖现有文件。导入先解密校验并预览；确认指纹绑定包内容、目标名称和目录身份，确认时重新检查当前冲突和数量，保存前再次核验目录。项目、模型及其版本、记忆及其版本、来源回执和完成事件在同一数据库事务提交，失败全部撤回。

准备记忆正文时可能留下没有记忆引用的脱敏内容对象；不留下半份项目、模型或记忆。这类对象沿用已有内容存储的回收机制，不在导入失败后贸然删除可能被其它记录共用的内容。没有复制数据库或系统密钥。来源回执保存在现有设置表，不增加数据表版本；已有数据和上一批历史记录保持可读。

主要文件：`crates/contracts/src/project_transfer.rs`、`crates/storage/src/project_transfer.rs`、`crates/workbench/src/transfer/project.rs`、`apps/desktop/src/ProjectTransferPanel.tsx`。

历史校验独立位于 `crates/contracts/src/project_transfer/memory_history.rs`，检查版本顺序、重复/缺失、最后版本与当前条目一致、范围和数量。转换与历史读取位于 `crates/storage/src/memory/transfer.rs`，每个版本的正文均受凭据扫描；项目、模型、所有记忆版本与回执在同一事务写入。`memory_transfer_tests.rs` 覆盖状态、恢复、重启、正文回收保护与故障回滚。

## 验证入口

- `npm run check`：基础检查和新增事务/格式测试。
- `node scripts/project-transfer-test.mjs`：独立源/目标引擎、不可用源目录、作用范围、坏包/错口令、冲突、凭据排除、保留默认模型与文件、重复和重启。
- `node scripts/project-transfer-desktop.mjs`：真实 Windows 桌面的选择导出、口令清空、错误提示、冲突禁用、预览确认、中英界面和退出。用输入框提供测试路径，原生选择框仍待用户体验。
- `node scripts/history-transfer-test.mjs`：复查共用模块修改没有破坏上一批历史备份/恢复。
- `npm run test:memory-history-transfer`：实际引擎导出完整历史、加密核对、预览计数、删除状态、重启去重、作用范围恢复和损坏包拒绝。
- `npm run test:memory-history-desktop`：实际桌面开关、已删除记录选择、历史数量/状态提示、导入后历史可恢复与中英界面。

实际结果和证据见 [P12 验证记录](P12-验证记录.md)。这一批没有生成新的安装器，旧版安装器和旧预览保留原样。
