# P13 用户体验清单

更新日期：2026-10-04。当前体验入口是 `0.1.0-alpha.13.4` Windows 候选版 r3。**这是一份操作清单，还不是“已经体验通过”的记录。** 可以每次只做一小组，按编号反馈。缺少条件的项目直接记“待条件”，不必勉强完成。

代码、模型和自动检查证据在 [验收矩阵](P13-验收矩阵.md)。阶段进度仍看 [P13 计划](../plans/13-Windows首版验收.md) 和 [文档索引](../README.md)。本清单不改变这些文件的验收结论。

## 开始前由开发者准备

以下是体验准备要求，不表示已经为本轮建好。用户不需要运行命令或编写代码。

- 给出本轮准确的程序入口和版本，准备独立的体验数据目录；旧版本与新版本不能同时打开同一份日常资料。
- 准备两个可随意修改的测试项目：“体验 A”和“体验 B”，以及用于比较和迁入的空文件夹。涉及删除、清空、升级和卸载时，只使用这些测试资料。
- 准备小型文档、表格、演示、PDF、图片、可回滚的示例扩展，以及本机测试网页。文件应含容易核对的文字、数字和页数。
- 准备需要时间才能完成的任务和安全的报错样本，方便体验引导、停止和错误。不要让用户靠耗尽模型额度制造错误。
- 升级和清空体验前，先准备独立口令备份、签名测试更新包和恢复说明；这些步骤由开发者陪同。

可运行包的入口在 [P13 r3 使用说明](../../artifacts/workpilot-p13-candidate-2026-10-04-r3/README.md)。这里只提供 Windows 结论。免安装预览必须保留整个文件夹，不能只拿一个程序文件走。真实图片、两种模型协作、技能和记忆已有开发者实测，原报告绑定 alpha.13.3；r3 另补真实公开 MCP 服务，用户仍可照本清单核对交互和实际效果。

## 可以分三批做

| 批次 | 内容 | 需要的条件 |
|---|---|---|
| 第一批 | UX01—UX07：项目、模型、任务、审批、协作、文件 | 可用文字模型和测试项目；不同模型协作还需至少两个实际不同模型 |
| 第二批 | UX08—UX15：浏览器、技能、文档、图片、记忆、托盘和定时 | 浏览器主动授权；图片服务单独配置；睡眠测试安排合适时段 |
| 第三批 | UX16—UX18：迁移、安装更新、清理、长记录 | 独立体验环境；干净 Windows、物理另一台电脑等缺少时明确跳过 |

UX19 用来体验已选定的软件内、Windows 系统与托盘提醒，可以和任意一批一起反馈。密钥只在软件设置或官方授权页面填写，不放进反馈文字、截图或文档。

<a id="ux01"></a>
## UX01：打开软件，找到项目与任务

对应 AT26、AT29。

1. 从开发者给出的本轮入口打开 WorkPilot，确认显示“引擎已连接”。
2. 创建“体验 A”，用文件夹选择窗口选择准备好的测试目录；再创建“体验 B”。
3. 在 A 新建任务，切换到 B 再回来，检查任务和项目名称有没有混淆。
4. 切换 English，再切回中文；调整左右面板，试用深浅主题。重新打开软件后检查这些选择是否保留。

预期：能找到模型、浏览器、技能、文件成果、记忆和定时入口；选错项目不会把 A 的任务放到 B。主要按钮、状态、错误和审批语言一致，窗口缩小时还能操作。

反馈：`UX01：通过 / 有问题 / 待条件；最难找或看不懂的入口是……`。若版本号不清楚，也直接反馈。

<a id="ux02"></a>
## UX02：配置自己的模型并试一次

对应 AT01、AT03。

1. 打开顶部“模型服务”，填写或导入自己的配置；密钥直接填在软件中。
2. 在开发者协助下，分别准备 Chat Completions、Responses、Messages 三种协议。它们是三种连接方式，不要求来自三家公司。
3. 每种配置分别发一次简单要求：“用两句话说明这个软件可以怎样帮助我。”观察文字是否逐步出现，结束状态是否正常。
4. 在声明支持图片的模型上加入测试图片，让它描述颜色和内容；未知或不支持图片的配置应有提示。
5. 新建一个任务手动选模型，另一个沿用项目默认模型；确认界面能看出实际使用的配置。

预期：成功、报错、未配置能力都有明确说明。费用或用量未知时不会显示成肯定的零。导出的模型配置不携带密钥。

反馈：服务名称、模型名称、协议、日期、是否正常；不要贴密钥。开发者另行保存请求/工具续接证据，不能只凭聊天回答就宣布三协议全部通过。

<a id="ux03"></a>
## UX03：聊天、规划、执行的区别清楚吗

对应 AT05。

1. 在“体验 A”选择聊天模式，提出：“帮我考虑一下怎样整理这个测试文件夹。”
2. 新建规划任务，提出：“规划一份项目说明文档，先让我看方案。”查看计划后，先不点击执行。
3. 确认需要实施时再启动执行，要求保存一份测试说明。观察何时出现实际写入和审批。
4. 开发者陪同切换权限后重复关键操作；你只需要核对：聊天和规划是否仍然遵守原来的边界。

预期：聊天不会偷偷修改文件；规划阶段不会因为选了完全访问就提前执行。点击执行后才按当前权限处理实际动作。

反馈：`UX03：我是否分得清“讨论”“看计划”“真正动手”；哪一步让我误以为已经执行？`

<a id="ux04"></a>
## UX04：排队、引导、错误和继续

对应 AT02、AT06。

1. 启动开发者准备的较慢任务。运行中发“完成当前要求后，再整理第二部分”，检查它显示为排队。
2. 再发“接下来改成更简短的版本”，对这条消息点“引导”。检查状态能否让你看懂它会先处理。
3. 试着修改或取消一条尚未处理的排队消息；停止任务，重新打开后核对剩下的内容。
4. 使用开发者提供的错误配置试一次。看到错误后先不要点继续，观察软件是否自己再次请求或换模型。

预期：队列内容不丢失、不重复；引导影响后续安全步骤，不假装已经完成的操作没发生。错误真实可读，只有你明确继续或修改要求后才开始新的尝试。

反馈：哪条消息先处理、哪条取消、是否看到重复动作；附任务名称和出错时间即可。请求次数由开发者核对记录。

<a id="ux05"></a>
## UX05：三档权限和审批能否看懂

对应 AT04、AT10、AT11、AT15。

1. 用默认“请求审批”，要求：“在体验 A 写一份 notes.txt，内容为测试一。”先检查目标、内容和影响，再批准；另做一次拒绝。
2. 让 A、B 两个任务都等待审批，切换任务，只批准 B。检查 A 仍在等，文件没有串到另一个项目。
3. “帮我批准”下查看自动判断或审查的说明；开发者准备一次审查失败/不确定样本，观察它是否交给你决定。
4. 仅在测试项目试一次“完全访问”，看看实际动作和记录。切回聊天/规划后仍不应主动修改。
5. 开发者演示含“忽略审批”文字的文件或网页，检查这些文字没有改变权限。

预期：批准的是当前看到的具体操作；拒绝就不执行。审查出错不会默认放行，完全访问也不应伪造系统权限。

反馈：`UX05：我批准了什么能否一眼看懂；有没有出现批准 A 却执行 B，或拒绝后仍写入？`

<a id="ux06"></a>
## UX06：多个助手分工、失败和停止

对应 AT07—AT09。

1. 给主任务一个小目标：“请两个助手分别整理两份测试资料，再由一个助手汇总。每份成果保存在不同文件中，并说明来源。”
2. 查看成员职责、模型和交付。若有两个实际不同模型，分别指定给成员；只有同一模型时如实记录，不能算不同模型体验通过。
3. 看汇总助手是否等前面的成果，主助手能否打开和核对真正生成的文件。
4. 开发者用安全故障样本让一个成员失败，观察其它独立成员是否继续；显式创建接替成员后，原失败记录应仍可查看。
5. 同时运行一个独立任务 B，停止团队 A，检查 A 及其成员停止，而 B 继续。

预期：你能判断谁在做什么、哪个文件来自谁、为什么在等待；接替是一名新的助手，不是原错误悄悄消失。

反馈：最困惑的成员状态、所用模型、失败与接替是否容易追踪，以及团队停止时 B 是否受影响。

<a id="ux07"></a>
## UX07：文件修改、外部编辑、恢复与代码项目

对应 AT10、AT12、AT28。

1. 打开“文件与终端”，修改一份测试文本并保存，查看修改前后差异。
2. 在另一款软件里再改这个文件。回到 WorkPilot，试用原来的待批准修改，确认旧批准不会覆盖新内容。
3. 选择一个历史版本恢复，先看预览再确认；检查恢复形成一条新记录，当前原文件有保护。
4. 开发者准备一个小型代码项目，请 AI 修改一个可见文字或颜色，并启动运行预览；看实际页面是否改变。
5. 在测试仓库查看 Git（代码修改记录工具）中的差异，只提交指定文件。查看终端输出并停止测试进程；不要求你输入命令。

预期：无关文件和已有未提交修改保留；运行预览来自真实程序。当前终端不支持一直交互输入，不能把这个边界当作已具备的能力。

反馈：差异/恢复是否好懂、外部冲突是否明确、页面是否真有变化、Git 是否只包含选中的文件。

<a id="ux08"></a>
## UX08：随软件提供的专用浏览器

对应 AT13、AT15。

1. 选择测试项目的执行任务，打开“浏览器”，启动随包专用浏览器。
2. 访问开发者准备的测试页面，读取文字、填写一个测试字段、点击按钮并查看结果。
3. 试一次截图和测试文件上传/下载；需要审批时，检查对象和目标文件夹。
4. 如需验证登录保持，在你愿意授权的测试账号上手动登录，再关闭、重开专用浏览器；不复制日常浏览器资料。
5. 遇到登录或验证码时试用“手动接管”，完成后恢复控制并重新读取页面。

预期：操作的是看得到的页面；下载落在测试项目并有历史。专用浏览器的资料独立，关闭重开不会被描述成已经接管日常 Chrome/Edge。

反馈：页面是否正确、审批是否顺手、登录是否保持、手动接管后能否继续。固定测试网页通过不代表所有网站都支持。

<a id="ux09"></a>
## UX09：日常 Chrome 和 Edge 分别授权

对应 AT14、AT15、AT22。需要你在浏览器中主动授权。

两款浏览器分别完成下面步骤，不用一款代替另一款。P00 已经加载过的 Browser Probe 不是这次的 Companion。

1. 打开“设置 → Chrome / Edge 连接设置”，按软件显示的目录配置本机连接；若提示另一安装位置占用，先交给开发者核对。
2. 按该页说明在浏览器的扩展管理页加载本轮 Companion。开发者可以逐步引导，不需要自行查找文件位置。
3. 只打开测试页面，回到 WorkPilot 生成连接码，在扩展里明确连接当前页。
4. 读取页面，填写测试文字，按需要批准操作。确认没有控制其它未授权标签页。
5. 在扩展里断开，再尝试控制；应提示已断开。重新连接后彻底退出 WorkPilot，日常浏览器和原页面应仍保留。
6. 开发者陪同检查扩展停用/更新后的重新连接。浏览器升级当时没有条件就记“未体验”。

预期：只有主动授权的标签页可控；断开后不能继续控制，也不偷偷重连。移除本机登记与立即断开当前页面是不同操作，需要停止任务或在扩展断开当前连接。

反馈：分别写 `UX09-Chrome`、`UX09-Edge`，附浏览器版本、最后完成的步骤和扩展报错；不要截图个人账号资料。

<a id="ux10"></a>
## UX10：安装扩展，让 AI 创建一个技能

对应 AT16、AT17。

1. 打开“技能与插件”，预览开发者准备的本地示例包；看说明、文件、范围和依赖，再确认使用。
2. 试着停用、启用和回退；再看一次预置坏配置或失败升级，原可用版本不应被破坏。
3. 点击“让 AI 创建技能”，描述一个小用途，例如：“每次收到工作摘要，整理为已完成、待办、需要确认三部分。”使用你自己的模型启动。
4. 查看草稿、配套资料和权限。先不确认，检查它没有自行启用；确认后在新任务实际用一次。
5. 如需接入自己的 MCP 服务（把外部工具连接到 WorkPilot 的方式），由开发者先核对兼容范围，你只在正常授权页面登录，再试一次工具。

预期：能看清来源、范围和版本；草稿质量需要你判断。一次本机工具调用成功不代表所有商业服务、持续会话工具都兼容。

反馈：技能是否符合用途、有没有记进不该保留的信息、确认前是否擅自启用、错误和回退是否容易理解；实际服务名称也请记录。

<a id="ux11"></a>
## UX11：附件、办公成果与外部编辑

对应 AT18、AT26。

1. 用文件选择窗口添加样本；再试一次真正拖入文件、从系统剪贴板粘贴测试图片。这里要亲自操作，自动生成粘贴事件不能替代。
2. 要求 AI 根据简单数据生成文档、表格、演示和 PDF：例如 A 为 2×12=24，B 为 3×10=30，合计 54。
3. 在“文件成果与图片”查看内容及原版式，核对标题、数字、表格、页数和来源。
4. 用自己已有的办公软件打开真实文件；修改一个值，回 WorkPilot 刷新，检查新快照出现、旧快照保留。
5. 对 PDF 查看画面并试着复制数字文字，确认不是只“看着像 54”却读不出来。

预期：真实文件可打开，数字和关键内容正确。软件内支持预览和有限文本编辑，不是完整 Word/Excel/PPT 编辑器；复杂模板、宏和全部公式不冒充支持。

反馈：文件类型、预览/外部打开结果、数字和页数是否正确。没有外部办公软件时记“外部打开待条件”，不要把它和生成失败混在一起。

<a id="ux12"></a>
## UX12：真实生成一张图片，再编辑一次

对应 AT19。**目前需要可用的真实图片服务配置；文字模型密钥不自动等于图片服务可用。**

1. 在“文件成果与图片”的图片服务设置中填写自己的服务、模型和凭据。由开发者核对该服务是否返回当前支持的图片内容格式。
2. 生成一个容易核对的图，例如“白色背景上的蓝色杯子”；先看实际请求和保存位置，再批准。
3. 打开真正生成的图片，核对尺寸、来源配置和画面。
4. 以这张图为参考，要求把杯子改成绿色，保存为新成果；检查原图仍保留。
5. 开发者演示一个安全错误样本，确认没有用旧图片或假图片冒充这次成功。

预期：实际服务返回可打开图片；生成和参考图编辑分别有记录。费用没有准确返回时显示未知。停止本机等待不代表供应商一定取消收费。

反馈：服务、模型、生成/编辑分别是否成功、能否打开原图。未配置或服务不兼容就记“待条件”，合成测试图不能代替这一项。

<a id="ux13"></a>
## UX13：记忆先建议，再由你确认

对应 AT20。

1. 在 A 的任务里表达一个长期偏好：“以后这个项目的摘要先写结论，再写待办。”查看“记忆”中的候选和来源。
2. 先不确认，检查它没有作为正式偏好生效；再点击“确认记住”。
3. 在 A 新建任务检查偏好，再到 B 检查项目记忆没有串过去。通用记忆和项目记忆应能区分。
4. 修改、删除该记忆后继续旧任务，观察下一次调用是否采用当前记忆；再从历史恢复一个版本。

预期：你决定记住什么；候选可能需要改写。删除影响之后的使用，不会擦掉旧聊天、备份或已经发出的请求。临时要求不应被误当长期习惯。

反馈：候选是否准确、有没有过度记忆、范围是否明白、修改/删除后新回答是否遵守。

<a id="ux14"></a>
## UX14：关闭窗口、停止和真正退出

对应 AT07、AT21、AT22。

1. 开始一个较慢的测试任务，点击窗口右上角关闭。
2. 从右下角托盘重新打开，查看任务仍在进行或已经完成，没有重新做一遍。
3. 启动另一组测试任务，点任务的“停止”，观察先显示停止中，再显示实际停止结果。
4. 再开始一个任务，从托盘选择退出 WorkPilot；重新打开时，原任务应显示中断，等你手动继续。
5. 开发者提供一个“原操作结果不确定”的隔离样本。先核对已经发生了什么，填写说明，再决定继续；不为制造这种情况强制结束日常工作。

预期：隐藏不等于退出；真正退出后没有本机自有工作悄悄继续。不能把远端已提交操作说成自动撤销。看到“已停止”时，实际所属工具也应结束或明确显示仍待处理。

反馈：托盘是否好找、状态是否真实、继续前是否清楚可能已经做过什么。开发者另行核对进程残留和时间，不只凭画面判断。

<a id="ux15"></a>
## UX15：定时任务、睡眠和时区

对应 AT21—AT23。实际睡眠/时区测试先安排合适时段，保存其它软件中的工作。

1. 打开“定时任务”，建立几分钟后的测试计划，查看项目、目标、模型、权限、时区和下一次时间。
2. 关闭窗口等它到点，再从托盘打开；查看发生历史和对应任务，需要审批时应继续等你。
3. 上一次还在等审批时再次触发，应有跳过或等待原因，不同时写两遍。
4. 彻底退出并错过一次时间，再打开：应记录错过，不自动补跑。需要新运行时由你点“立即运行”。
5. 开发者陪同让整台电脑睡眠跨过一个时间点，再唤醒；检查没有重复或无提示补跑。实际系统时区切换另留记录，并恢复测试前设置。

预期：每次发生有自己的任务；停用/删除计划不抹掉旧历史。计划使用它保存的时区。夏令时边界由开发者自动核对，不要求你反复修改电脑日期。

反馈：计划时间是否看懂、隐藏/退出/睡眠三种情况分别发生了什么、等待审批是否易发现。已选定的通知方式按 UX19 单独体验。

<a id="ux16"></a>
## UX16：迁移到新位置，再检查清理

对应 AT24。删除和清空部分只在独立体验资料中，由开发者陪同。

1. 打开“设置 → 完整资料迁移”，选 A、B 两个测试项目，分别选择模型配置、记忆、任务/助手、技能/草稿和需要的当前文件。
2. 保存口令保护包。读取它后，为每个原项目和历史文件夹选择新的位置，先看冲突和来源，再确认。
3. 检查对话、成员、附件、文件版本和记忆来源是否对应；模型凭据要重新填，技能保持停用。
4. 当前文件应单独等待核对/审批；恢复任务不会自己跑。若有原来未决的操作，逐项核对实际结果后才能手动继续。
5. 再读同一个包，确认不重复建项目/任务。开发者演示坏口令、同名文件和导入中断后的继续。
6. 在测试资料中做一次版本保留清理：先成功保存并核验备份，再删除旧版本。再删除一个已归档的测试任务，检查项目实际文件还在。
7. 有另一台电脑时，把同一包带过去再做一次；没有就把“物理换机”保留待验收。

预期：每个项目位置明确，原审批和未知外部操作不会被重放。删除任务后保留防重复记录；仍被其它任务、独立档案或版本使用的内容继续保留。清空当前资料会移除本机版本密钥，不能把依赖它的旧本地副本当成独立口令备份。

反馈：原项目→新位置、哪些资料正确或缺失、审批是否明确、重复导入是否新增、是否实际换了电脑。口令不要写进反馈。

<a id="ux17"></a>
## UX17：安装、更新、恢复、离线和诊断

对应 AT25、AT27、AT29。由开发者准备独立安装位置、签名测试包和可恢复副本，再交给你操作。

1. 使用指定安装器，核对名称、版本、图标、快捷方式和托盘入口。当前安装器没有 Windows 发布者证书；如遇来源/权限提示，把提示记下来交给开发者核对，不关闭系统防护。
2. 在“设置 → 环境检查与诊断”运行检查，观察进度与错误说明；主动导出一次本机诊断。
3. 在“软件更新”检查开发者提供的测试源或签名包，查看版本和影响；不确认安装时，原程序应继续保留。
4. 确认安装前看清任务停止、备份与恢复入口。开发者在隔离环境演示坏包/中断恢复，你核对提示和恢复后测试资料。
5. 卸载测试安装时先走默认保留路线，再安装核对测试资料。只有准备好独立备份后，才在隔离环境测试明确勾选的清空路线。
6. 在真正断网时打开本机已有资料，观察云端模型不可用会报错；恢复联网后再验证。不要把拦截一个模型地址算整机断网。
7. 有未安装开发工具和 WebView2 的干净 Windows 时，再执行完整安装和内置工具流程；当前开发机通过不替代此步骤。

预期：更新由你触发，失败不毁原资料；恢复入口说明清楚。诊断只保存在本机，不自动上传。默认卸载保留项目成果和资料，明确清空的范围可见。

反馈：安装方式、系统提示、环境结果、更新是否需要主动确认、恢复结果、默认卸载后资料是否还在；注明是否干净系统和真正断网。

## UX18：长记录、多任务和长时间使用

对应 AT28，并补充 AT07、AT26。

1. 打开开发者准备的长记录任务，翻页、搜索末尾文字，复制一段完整长内容到外部记事软件，检查没有只复制当前页。
2. 同时开几个测试任务，尝试输入、切换、展开过程和停止其中一个。
3. 切到英文再做一次关键操作；记录任何挡住按钮、看不见文字或长时间无反馈的地方。

四小时连续测试已按用户在 2026-10-04 的明确要求取消，不再作为本轮体验步骤或自动安排。已完成的短时性能检查保留原始结果，长期连续稳定性仍未验证。

预期：长记录不丢失，界面能继续操作。完整导出可查阅，不因为省内存而删除历史。启动、输入、事件、停止和工具收尾分别测量，模型等待不冒充本机卡顿。

反馈：当时任务数、做了什么、卡了多久、能否停止。一次肉眼感觉顺畅不代替正式性能采样，也不据此宣称长期连续运行已通过。

## UX19：体验任务提醒

对应 O-01 / Q44。用户已于 2026-10-04 确认采用软件内提醒、Windows 系统通知和托盘提示；选择已确认不等于体验已经通过。

使用本轮安装版，确认 Windows 没有关闭 WorkPilot 的系统通知：

1. 运行一个短任务，切到其它窗口，检查完成后的系统通知、托盘提示和应用通知中心。
2. 点击通知，预期打开对应任务，不开始新任务或自动批准。
3. 分别体验模型报错、需要补充输入、需要审批；系统弹窗不应展示任务正文或凭据。
4. 在设置中分别关闭系统通知和托盘提示，检查对应渠道不再提醒，软件内仍能处理。
5. 退出后重新打开，旧结果不重复弹出；新的完成事件继续提醒。

便携预览没有安装身份时，系统通知可能不可用，界面应明确说明并保留软件内和托盘提示。反馈请说明使用安装版还是便携预览，以及系统通知开关；未看到系统弹窗不能直接记为通过。

## 统一反馈模板

每次做完一小组，按下面格式发给开发者即可。只发问题也可以，但没有明确反馈的项目不会自动算通过；未做的项目保持“未体验”。

```text
软件版本：
日期 / Windows 版本：
体验编号：UX__（Chrome 和 Edge 分开写）
结果：通过 / 有问题 / 待条件 / 未体验
我做了哪一步：
我以为应该发生什么：
实际发生了什么：
任务名称、时间、测试文件名：
截图或已导出的记录（如有）：
```

涉及模型/图片/第三方服务时另加服务、模型、协议或浏览器版本，始终不附密钥。开发者根据反馈补定位、自动检查和真实服务证据，再更新既有阶段记录；不用你逐项审批普通修复。
