# P12 附件与成果迁移

程序：`0.1.0-alpha.12.7`；数据版本：11。属于 Q41、T-P12-03 的分批实现；完整会话、多助手和跨包引用仍待接续。

## 使用入口

在任务中打开“文件成果与图片 → 附件迁移”。

1. 勾选当前任务的附件或生成成果，选择新的保存位置，设置并重复至少 12 个字符的口令，导出 `.wpmedia`。
2. 切换到目标任务，选择备份、输入口令和可选名称前缀，先预览文件名、格式、大小、来源及同名提示。
3. 确认导入后，在“附件与成果”查看内容、图片和办公预览。同名附件保留为独立资料，不替换目标已有内容。
4. 要把资料交给模型，点击附件卡片的“加入下一条消息”，再主动保存/发送消息。只导入、预览或加入输入框都不会发起模型调用。

迁移的是应用已保存的原始文件快照。上传文档、图片、曾读取的项目文档以及生成成果均可选，源项目文件夹不在线也能导出。每包最多 64 项、单项 32 MiB、合计 256 MiB、元数据 1 MiB；当前选择界面列出该任务最新 256 项，超出范围不是自动全选。旧版资料缺省没有迁入来源，仍能照常使用。

## 数据、口令和引用边界

`MediaTransfer` 是独立管理命令，口令不进入命令历史、事件和普通日志。外层标识 `WPMEDIA1`、内部版本 1，复用已实现的分帧 AES-256-GCM 与 PBKDF2-SHA256 600000 次派生。包头、帧顺序、摘要、大小和尾部均验证；错误口令、损坏、缺失内容或格式不符拒绝导入。导出只发布完整的新文件，不覆盖已有备份。

仅带原始字节与来源描述；模型设置、系统凭据、浏览器登录信息、原机解密密钥和解析缓存不迁移。导出检查已保存原文和解析结果，导入重新检查原文并重新解析；命中当前应用已登记凭据或常见凭据文件名时拒绝。这不能保证识别任意业务文件中的未知秘密，备份内容仍以用户的选择为准。

每个迁入附件获得新编号，重新绑定当前任务。旧任务编号、旧项目路径、生成操作仅保存为来源说明；当前文件路径、文件版本和活动操作引用清空，因此不会绑定同名任务或改写目标项目文件。重复转存保留最初来源。导入资料采用普通用户附件类型，模型必须收到新编号的明确附件标记才能读取；不能把旧生成成果当成新任务自动可见的工具结果。

原字节在目标机器的加密对象库重新保存。解析通过现有受限文档进程执行，不信任包中提供的解析缓存；Word、Excel、PPT、PDF 等格式仍沿用原有格式支持和预览限制。预览会产生加密暂存对象，但不会增加附件记录；暂存和失败产生的未引用对象清理仍属于版本生命周期待办。

## 一次导入、取消和重复请求

聊天、规划、执行模式均可手动管理附件；正在执行的任务/文件操作和已归档任务阻止新导入。尚未启动的新任务可以导入，不把任务显示的“排队”状态误当成已有执行。

预览绑定当前任务状态、附件集合、库总数以及重新解析的结果。确认前重新核对，数据库获得写锁后再检查；目标或解析内容变化要求重新预览。整批新记录和导入回执在同一数据库事务提交，失败和提交前取消不会留下半批附件。现有附件库 10000 项总限额仍生效。

同一备份与目标任务的重复请求返回原回执；重启、更改名称前缀也不会重复添加。重复预览显示首次导入的名称和时间，明确新前缀不生效；“核对导入状态”只确认原记录。导入后被用户移除的资料不会被重复请求重新带回来。需要另一份独立副本时，应创建新备份或选择另一任务。

取消只作用于当前拥有迁移的任务，其他任务不能取消它。90 秒处理预算到期后请求停止并等待受限工作进程清理；底层 I/O 清理可能延长返回时间，不承诺硬性 90 秒结束。若事务已经提交或完整备份已经发布，仍返回成功事实。应用彻底退出也会请求停止。

## 已知限制及下一步

- 本批不迁移会话消息、多助手执行历史、文件夹全部内容及原会话附件引用，也不整合多个备份的编号/路径映射。源条目的名称和来源可追溯，不冒充原任务仍存在。
- 旧扩展版本/草稿、统一多项目迁移、版本清理、团队永久删除和受签名保护的更新仍未完成。
- **T-P10-03：在本批 alpha.12.7 迁移测试中发现，后续 alpha.12.8 已修复新生成 PDF。** 当时源文件的 `42` 提取为私用区字形，源文件和迁入文件摘要、字节及提取结果一致。后续修复说明见 [P10 验证记录](P10-验证记录.md)；迁移仍忠实保留旧原文，不自动重写旧 PDF 或旧解析快照。
