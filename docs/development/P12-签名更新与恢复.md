# P12 签名更新与失败恢复

本模块落实 Q40 与 AT25：用户主动检查版本、核对变化、准备更新，最后明确确认停止任务并安装。它属于 Windows 私有分发能力；程序内容的签名验证已经实现，尚无公开更新站点或 Windows 发布者证书。两种签名用途不同，不能把本模块称为已经取得微软发布者认证。

## 用户流程

1. 打开“设置 → 软件更新”，选择 `.wpupdate` 本机包，或填写私有 HTTPS 更新源的确切地址。
2. “检查更新”只读取并验证签名清单，显示版本、变更、容量，以及程序和随包工具的影响。
3. “下载并核验完整更新”把新版保存到独立目录，逐项检查内容。原程序与任务此时继续运行。
4. 勾选“我确认停止任务、备份数据并立即安装”，再点击“退出并安装更新”。
5. 桌面结束引擎和其子进程，新定时调度随之停止；独立助手等待桌面退出后才备份和安装。
6. 完成后手动重新打开 WorkPilot。中断的原任务不会自动续跑。上次结果和旧副本位置在更新页面可查。

没有后台轮询、自动下载或自动安装，也没有向模型开放更新命令。界面预览、确认和本机路径控制只允许主工作台调用；网页预览没有该权限。第三方技能和插件继续由原管理页面处理，不夹带在软件更新中。

## 签名与格式

`WPUPDT01` 文件由 8 字节魔数、4 字节小端清单长度、签名信封和顺序文件内容组成。信封中的原始清单字符串由 Ed25519 签名；程序编译时固定信任 `resources/update/trust.json` 中的公钥，不信任下载包自带的公钥，也不从可替换的外部信任文件加载权限。

清单携带目标版本、平台、说明、源数据最低版本、目标数据版本、程序/工具变更及全部文件的相对路径、长度、SHA-256。签名元数据最多 16 MiB，文件最多 100000 项，总内容最多 16 GiB。拒绝版本相等或降级、不适用平台、路径越界、重复目标、文件与目录冲突、链接、摘要不符、截断和额外尾部。确认后再次验证签名与暂存文件，拒绝暂存目录混入额外未签名文件。

网络只接受 HTTPS，拒绝带账号密码的地址及重定向；连接和总传输时间有界。连接失败或下载中断仅留下独立暂存/错误记录，不动现有安装。离线更新使用相同签名与摘要规则。

本机开发签名私钥仅保存在被忽略的本地目录，未打包、未进入源码与测试报告。发布脚本要求明确传入私钥，并验证与固定公钥相符；它拒绝把私钥所在目录或常见私钥/数据库文件打入程序包。生产分发应另行保管发布私钥；密钥轮换需要经过现有可信版本的签名更新，不能直接替换用户机器上的公钥文件绕过信任。

## 数据兼容与恢复

```
停止桌面和引擎
       ↓
独占数据更新锁 + 原引擎锁
       ↓
复制完整数据到同磁盘新目录
       ↓
新版引擎只检查/迁移数据副本
       ↓
保存原程序 → 切换新版程序
       ↓
保存原数据 → 切换已验证的新数据
       ↓
提交升级记录；保留两份旧副本
```

普通存储实例持共享更新锁，升级及离线维护持独占锁。锁文件位于数据目录父目录，数据目录被替换后也不改变锁身份；另一实例仍使用数据时停止安装，而不是强行关闭它。原引擎锁也必须成功取得。

另有固定安装位置的独占锁，防止使用不同数据目录的两个窗口同时更新同一程序。Windows 目录切换前释放位于原目录内的旧锁句柄；父目录中的稳定独占锁一直持有。临时的 `engine.lock` 不是用户数据，不复制其正被锁定的内容，数据副本打开时重新建立。

程序暂存和数据暂存分别位于原目录的同一磁盘，支持程序和数据分处不同磁盘。复制整个应用数据目录，包含数据库、正文、加密对象和已有本机诊断；不复制系统凭据，不访问项目目录，不扫描浏览器个人资料。系统凭据仍留在原操作系统，正式使用的数据路径恢复为原路径。数据副本拒绝链接/特殊文件，最多 250000 个文件、64 GiB，容量或权限不足时停止升级并保留原数据。

新版 sidecar 使用独立 `--check-update-data` 模式：只打开、迁移和检查数据库，不创建执行循环、模型客户端或定时调度器。助手核对新版真实版本、实际数据库版本、完整性与引用关系。迁移异常、超时或签名清单与实际版本不符时，原数据没有被迁移。

每次目录切换前后保存可恢复记录；失败时程序和数据一起恢复。进程中途结束后，下一次启动在打开数据库前处理未完成记录；也可用保留的独立助手执行 `--recover`。已提交的升级不能重复执行，避免回滚到旧数据覆盖更新后的工作。旧程序、旧数据和失败副本自动保留，后续清理必须明确范围，不能以升级成功为由立即删除恢复材料。

旧程序刚移到备份位置、新程序尚未放回时若被强行结束，原快捷方式可能暂时找不到主程序。为覆盖这段窗口，准备更新时就在**安装目录上一级**建立 `WorkPilot-Recover-<本次编号>.exe` 和同名文字说明。界面返回“准备好了”之前，工具必须实际存在且摘要与当前更新助手一致；已有同名文件不会被覆盖。界面显示准确位置，并提供“打开恢复工具所在文件夹”。真正安装前再次核对工具未变化。

用户此时可以直接双击该工具：系统窗口显示此次原程序和资料位置，默认选择“否”；确认后把原程序和原数据一起放回，显示成功或失败。它依据自己的文件名与同级已知事务目录定位记录，不接受任意文件路径，不通过命令行解释器拼接命令。签名清单、编号、目录与状态必须匹配。已经提交或恢复的事务只显示状态，不能回退覆盖之后的新工作。恢复不会主动关闭其它实例，也不会自动重开任务；成功后使用原快捷方式即可。恢复入口、说明和事务记录继续保留，卸载与恢复副本清理不把它们当作可随意删除的旧数据。

安装版保留本机已有 `uninstall.exe` 和已生成的 Companion 连接清单，逐项记录摘要并在切换前复核。下载包不能自行替换这两个本机登记文件。仅当当前用户的安装登记确实指向此次安装时才更新显示版本，失败恢复时不会覆盖属于其它安装的记录。

新版 NSIS 卸载钩子识别已提交的签名更新清单，移除仍与清单匹配的新增文件，再执行原安装器自己的清单卸载。额外文件、修改过的新增文件及旧更新备份保留。更新失败后已经回滚的安装仍能正常卸载；尚未恢复完成的更新先阻止卸载。

卸载页面将“删除桌面网页缓存”和“清空 WorkPilot 历史、设置与已保存的凭据；保留项目文件”分为两个独立选项，默认都不选择。只有交互式卸载中明确勾选后一项，才调用 sidecar 的 `--maintenance-reset-default --confirmed`，失败中止卸载。静默、被动和 `/UPDATE` 均不触发历史清理；路径由引擎的真实默认通道规则定位，不由 NSIS 猜测。生产钩子的分支检查与真正的离线清理引擎一起测试；原生勾选体验仍单列。

## 恢复副本清理

设置的更新页面保留“上次更新与保留副本”位置说明，另有独立“更新恢复副本管理”。预览核对当前安装和当前数据路径，读取同一安装的签名升级记录，列出已提交或已回滚事务留下的原程序、原数据、失败版本与未采用副本。未完成事务不纳入删除，未知目录不删除，链接和越界记录拒绝处理。

用户看到每个目录、文件数和容量后，必须输入 `DELETE`。执行时先停止引擎，取得安装和数据独占锁，重新核对完整文件清单及内容摘要，预览发生变化则不删除。只移除已经列入预览的旧副本文件；当前程序、当前数据、系统凭据和版本密钥保持原样。已导出的 WorkPilot 备份包及常见压缩包保留；除 `.wpmigrate` 等后缀，还检查全部现有 WorkPilot 导出格式的文件头，错误后缀也不会导致备份包被清理。因此含有这些文件的旧目录可能继续存在。升级记录和签名证明也保留，供卸载器识别当前更新文件。

清理完成后需要重新打开软件。失败时不夸称已经全部删除，可按剩余实际文件重新预览重试。设置中的“清空当前数据”和卸载清理均不会顺便删除这些应用更新副本或用户导出包，避免把不同恢复材料混在一次不明确的清理中。

目前应用版本仍为 `0.1.0-alpha.12.15`、数据版本仍为 11；测试使用兼容副本及故意错误的目标版本，不能将测试目标版本当作产品数据库已经升级。

## 开发入口

- 核心：`crates/platform/src/update`；独立助手：`crates/platform/src/bin/workpilot-update.rs`。
- 新版离线验证：`crates/engine/src/update_check.rs`；正常存储和维护锁：`Store::open` / `Store::open_exclusive`。
- 桌面：`apps/desktop/src/UpdatePanel.tsx` 与 `apps/desktop/src-tauri/src/update.rs`。
- 构建：现有 `scripts/desktop.mjs` 构建更新助手，`scripts/package-p12.mjs` 将助手及可读公钥说明加入新包。
- 签名：`node scripts/update-package.mjs <预览目录> <输出.wpupdate> <本机私钥文件> <目标版本> <变更说明>`；输出采用不覆盖已有文件的方式。
- 随包工具版本通过整个签名软件包交付，预览分别列出程序变化与工具变化。第三方扩展继续在原技能与插件入口独立管理；本阶段没有实现任意组件的在线热替换。
- 自动检查：平台库 `update::` 测试；`scripts/update-engine-test.mjs` 使用隔离目录、真实签名助手与引擎。真实桌面确认和最终安装器另行记录。

本轮实际检查、失败修正与交付证据由 [P12 验证记录](P12-验证记录.md) 汇总。干净 Windows、物理换机、macOS/Linux 和用户实际体验保持独立结论，不用本机自动检查代替。

## 重跑前置与命令

普通工作区 Rust 检查包含更新库单测，使用测试中临时生成的签名密钥，不依赖本机发布私钥；这些单测已纳入现有工作区测试和 CI 配置。专用强杀子进程测试默认 `ignore`，因为它必须由父脚本启动并终止，不能把单独启动后永久等待算作普通测试。

下面的完整流程是**本机 Windows 验证入口**，尚未加入通用 CI：需要已构建的桌面、sidecar、更新助手、WebView2、可以显示系统窗口的桌面会话、仓库 Node 依赖及 Rust 工具链。卸载测试还需要 `%LOCALAPPDATA%/tauri/NSIS/makensis.exe`。当前公钥对应的开发私钥必须已经保存在 `.local/update-signing/development-private.pem`；不要为了跑测试改公钥、覆盖现有私钥，或把私钥提交/上传到普通 CI。没有这些前置时应记录“未运行”，不能用库内模拟结果冒充完整流程。

$env:WORKPILOT_UPDATE_TEST_CHILD_BINARY = $testArtifact.executable
