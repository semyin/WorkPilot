# P03 执行引擎与恢复

日期：2026-10-02。这是通用单助手内核与开发预览，不是正式 V1。真实文件、终端、浏览器操作和三档权限执行在 P04 及后续接入。

## 从桌面使用

打开 WorkPilot，点击左下“任务执行”。先在“模型服务”明确配置自己的服务与模型。任务可继承默认模型，也可选择单独配置；工具能力必须已声明或通过连接测试确认。缺失配置时显示错误，不自动挑选别的服务。

新建任务填写目标，可另外写入限制条件与项目规则。默认聊天模式；可选择先规划或直接执行。“启用内置样本工具”默认关闭，勾选后只能读固定样本、计算和保存任务内测试记录。样本写入不创建真实项目文件。

- **聊天**：可回答、询问和只读查询；执行型样本工具不可用。
- **先规划**：可保存步骤并等待用户；必须点击“开始执行计划”才切换执行模式。
- **执行**：模型根据实际工具结果选择下一步；步骤未完成时不会标记任务完成。
- **新消息**：运行时进入持久队列，当前轮结束后处理；点击消息的“引导”会在安全边界调整当前工作。
- **停止**：保存已完成步骤；正在进行且结果未知的工具留下待核对记录。中断/失败后新消息只保存，点击“继续任务”才启动下一次执行。
- **关闭窗口**：隐藏到托盘，任务继续。彻底退出后中断；再次打开不会自动请求模型或重做工具。
- **查看过程**：右侧最近 64 个步骤可展开实际输入/结果；完整事件按 128 条分页，不在界面一次加载全部历史。

等待用户回答时，发送答案表示明确继续本任务。已经完成的任务发送新要求，创建新的执行记录。中断或失败仍保留单独的“继续任务”按钮。

## 实际代码分工

| 位置 | 职责 |
|---|---|
| crates/runtime | 独立于桌面的模型—工具—结果循环、上下文整理、模式边界、停止与引导 |
| crates/engine/src/tasks.rs | 接收命令、选择配置、读取本应用凭据、排队和运行槽位、进程退出 |
| crates/storage/src/execution.rs | 原子保存执行、步骤、检查点、消息交付与恢复凭据 |
| crates/providers | 把多轮模型历史转换成三种协议的原生消息，校验工具调用与结果编号 |
| crates/contracts/src/execution.rs | 桌面与引擎共享的类型和命令 |
| apps/desktop/src/TaskWorkspace.tsx | 任务开发入口和过程检查 |
| services/execution-fixtures | 仅测试使用的本机模拟模型，不属于真实模型接入 |

同一个执行循环只识别模型结果和工具定义，没有针对求和、保存文字等办公流程的分支。测试场景的固定脚本只在模拟服务中。将来工具注册表可接 P04，助手会话可被 P05 复用。

## 保存关系

```text
任务 Task
  └─ 助手 Agent
      └─ 会话 Session：目标、要求、历史、计划、待核对操作
          ├─ 执行 Run 1 → 步骤与检查点 → 中断
          └─ 执行 Run 2 → predecessor 指向 Run 1 → 继续
```

SQLite 升级为 schema 3，仍使用 workpilot.v1 本机通信。升级前保存数据库备份。会话按任务和助手建立，不把数据库限定成“一个任务永远只能有一个助手”；P03 的命令与界面只操作主助手。

模型完整请求、返回、工具参数与结果使用内容对象保存，检查点只保存引用。状态与对应事件在同一个事务里写入；写入成功后才向界面发送。垃圾清理将会话、检查点、步骤、执行凭据和人工核对结果视为有效引用。模型配置快照不包含密钥。

人工继续生成新的 Run，并保留原会话。成功步骤不重放，未执行步骤从持久待执行列表接续。已保存模型历史后不能改为另一协议、模型或地址继续，因为原生工具/推理关联未必兼容；应新建任务。修正同一服务的凭据和普通配置不属于自动回退。

事件外层的 source/agent_id 与事件内容字段分别命名，避免展开 JSON 时字段冲突。旧 AgentChanged 保存内容的 agent_id 可读取，重新输出为 target_agent_id；新客户端和引擎需要配套。

## 中断与恢复

| 中断位置 | 保存证据 | 人工继续时 |
|---|---|---|
| 工具还未开始 | prepared，参数和调用编号已保存 | 可执行该未开始操作，不重做之前模型请求 |
| 工具执行中，没有可靠结果 | needs_review | 先暂停核对；用户确认未执行才允许重试，或填写已验证的结果 |
| 样本操作已落盘，完成事件未写入 | needs_review，但有独立执行凭据 | 采用原结果补记完成，不重复产生效果 |
| 模型出错 | 错误、部分文本、失败执行记录 | 不重试、不切模型；用户处理后手动继续 |
| 程序退出时仍在排队 | 中断记录 | 不自动恢复排队；等待明确继续 |

P03 的样本效果和执行凭据在独立事务内一起保存，随后再写工具完成事件。P04 的任意外部操作未必能提供同样的凭据，必须接入各工具的实际核对方式；没有证据时不假定成功或失败。

停止、交付消息和完成决定都经过同一个保存线程。停止先被接受时，迟到成功不能改成完成。结束前新消息已经排队时，执行继续处理该消息。旧执行的迟到写入无法覆盖新执行。

“引导”会取消当前模型等待，或在工具结束后的边界生效；尚未开始的旧工具被标记跳过并生成对应结果，不再执行。已经完成的效果不撤销，执行中效果也不假装被撤销。普通排队消息不会中途抢占。

## 上下文和资源上限

目标、限制、项目规则、后续用户要求和未完成计划始终保留。超出容量时，将完整的旧模型交互连同来源保存到归档，保留最近来源索引与工具编号；inspect_history 可以按步骤读取本任务历史。原始事件和内容不被摘要覆盖。

这里采用确定性的整理与引用索引，没有额外收费的“摘要模型”，也没有声称自动生成高质量语义摘要。必须保留的要求本身超过容量时明确暂停；可调高容量或新建任务，不静默删掉用户要求。

工程默认值，不是额外用户决定：

| 项目 | 默认值 / 范围 |
|---|---|
| 正式任务并发 | 4 个执行槽位；运行与排队合计最多 32 个 |
| 单次执行步骤 | 32；可设 1—256，模型请求和工具操作均计数 |
| 单次运行时间 | 300 秒；可设 1 秒—1 小时，排队等待不计入 |
| 上下文序列化容量 | 64 KiB；可设 8—512 KiB，不等于模型词元窗口 |
| 单次结果容量 | 32 KiB；接口可设 1—64 KiB |
| 待处理消息 | 每任务最多 128 条，一次交付最多 16 条 |
| 模型设置诊断 | 沿用 P02 独立的 4 个连接操作上限，不占正式任务槽位 |

控制命令不等待任务槽位。当前并发上限作为工程常量，未提供用户设置；运行时间、步骤、上下文可在任务面板调整。时间和步骤上限中断后，人工继续使用一份新的单次预算。

## 可复现开发入口

```powershell
npm run contracts:generate
npm run test:runtime
npm run test:execution-engine
npm run check
npm run build
npm run test:execution-desktop
```

最后一个测试需要 Windows/WebView2，只操控本次启动的 WorkPilot 测试窗口。测试数据库位于独立的 .test-results 目录，不读取用户配置或其他软件密钥。真实进程退出注入只在引擎 test 通道启用；模型参数不能启用它。

结果和未覆盖范围见 [验证记录](P03-验证记录.md)。真实模型服务仍需补齐 [P02 兼容清单](P02-服务兼容清单.md)。
