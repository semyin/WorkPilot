# P11 本机定时任务设计

日期：2026-10-03。与记忆共用自研 Rust 引擎、SQLite 和现有任务工作台。适用于本地预览；不引入云端调度、系统服务或开机自启。

## 入口与用户规则

顶部“定时任务”可新建、编辑、启停、删除、立即运行和查看历史。每个计划明确保存项目、目标、模型、聊天/规划/执行模式、三档权限、独立审查模型、是否允许项目命令、触发规则和时区。默认权限仍为“请求审批”，不会从最近一次任务继承更大的权限。

支持只执行一次、每隔 1—10080 分钟、每天指定时间、每周指定日。间隔从保存/重新启用开始计时；每天/每周按所选时区的当地时间计算。一次性时间支持秒，方便预览测试。默认新计划时间在五分钟后，用户可预览下一次时间。计划的下一次时间标出计划时区；执行历史按电脑当前时区展示并明确标出名称，数据库仍保存实际时间点。

隐藏窗口只改变界面，独立引擎继续运行。彻底退出会终止引擎；重启时记录错过的触发，不立即补跑，不自动继续中断任务。已启动的任务不因计划停用或删除而取消，可在任务工作台停止或人工继续。单次计划到点后没有未来触发，但仍可手动立即运行。

## 一次触发的保存顺序

```text
检查时间、旧任务与配置
           ↓
保存“这次触发已被领取” + 推进下次时间
           ↓
创建普通任务，并在同一次数据库提交中保存计划权限
           ↓
关联任务 → 验证原项目目录 → 启动普通执行流程
           ↓
保存启动结果；后续直接读取普通任务状态
```

每次触发都有独立编号、计划版本、计划原文引用、预定/记录时间、来源、跳过或失败原因、任务链接。原文保留模型编号与设置版本，不包含模型密钥。旧计划修改、删除和未引用对象回收不破坏已发生记录。

定时去重键包含计划、版本和预定时刻；手动立即运行绑定客户端请求编号。领取和推进游标在同一个 SQLite 事务中完成。任务创建/配置/启动分别使用确定的内部请求编号，重复请求不会创建第二个任务。

若在领取后、创建后或开始运行后进程崩溃，重启只标记启动中断。创建后尚未来得及关联的任务可由创建回执找回。权限与任务创建同时保存，避免崩溃后人工继续时误继承项目或全局的另一档权限。这不承诺对任意外部系统提供“绝对只执行一次”；执行中已产生的外部效果继续遵循原工具恢复规则，不能盲目重试。

## 重叠、权限与错误

同一计划只允许一个仍在进行的发生记录。排队、运行、停止中、等待输入、等待审批都算仍在进行；同时检查所有子助手与文件工作区中的操作。即使主任务已结束，子助手仍在工作也不会启动下一次。其它独立计划仍按现有总并发限制运行。

定时遇到重叠会记“跳过”，没有额外积压队列；手动立即运行会显示原因。人工继续一个旧发生任务时也检查同计划是否已有其它发生任务，防止从工作台绕过重叠限制。

三档权限和审批证据与普通任务一致。规划模式等待用户确认，不能借定时触发直接执行。主模型错误直接结束本次，不自动重试或切换服务；主助手可按照既有团队规则决定是否重新委派失败的子助手。

保存计划时冻结模型、审查模型和项目设置的版本。它们修改后，定时启动会失败并在历史提示重新保存计划；不会悄悄采用新端点、新目录或新规则。未指定自动审查模型时固定为计划模型。项目目录仍核对原授权目录身份，不能因为目录被替换而重新授权一个陌生位置。用户手动继续已创建任务时沿用普通任务的可见配置规则。

任务完成、失败、需要审批等仍产生普通任务事件；失败和等待处理进入现有工作台入口，发生历史本身不依赖操作系统通知权限。尚未创建任务的配置错误在定时历史中显示。**Q44 / O-01 已于 2026-10-04 确认软件内、Windows 系统通知和托盘提示**，P13 已接入普通任务实时状态；系统通知不含任务正文，点击只定位，不触发审批或执行。系统实际显示、通知被关闭和用户体验分别留证，不增加邮件渠道。

## 时区、暂停与错过

计划保存明确的 IANA 时区名称（例如 `Asia/Shanghai`）。电脑改系统时区不重解释已保存的计划。采用固定依赖 `chrono 0.4.45`、`chrono-tz 0.10.4`；后者内置时区数据库，接口返回数据库版本供诊断。计算依据见 [chrono-tz 官方文档](https://docs.rs/chrono-tz/0.10.4/chrono_tz/) 与 [当地时间映射规则](https://docs.rs/chrono/0.4.45/chrono/offset/enum.LocalResult.html)。

- 夏令时跳过的当地时间：每日/每周跳过该天；新建一次性计划会提示这个时刻不存在。
- 夏令时重复的当地时间：只选择较早的那一次。
- 引擎每 250 毫秒检查到期，正常调度允许五秒内的运行延迟。
- 距离上次检查超过五秒，或墙上时钟向前跳过五秒以上，按恢复/跳时处理：这一检查时刻之前的所有到期计划记为错过，不补跑。一次最多读取八个计划；检测到暂停后按同一个时间点处理全部批次，不能只跳过前八个。
- 启动恢复没有五秒宽限：凡已过期都记错过。时钟回拨不会倒退已消耗的游标；修改或重新启用也遵守该计划的高水位。
- 一段时间错过多次，只保存范围；一次/间隔计划同时保存次数，每日/每周不逐条展开多年记录。

这是一套基于引擎观测间隔的规则，没有接入各系统的休眠通知。自动验证会暂停测试专用引擎进程并检查恢复，不改变用户系统时钟，也不让整台电脑睡眠。**真实电脑睡眠/唤醒仍是单独待验证项**，进程暂停通过不算其已通过；五秒以内的短暂停按正常调度宽限处理。

## 数据、容量与接续

schema 11 新增计划游标、发生历史及命令回执。原 P01 `schedules` 中没有新游标的占位记录不执行；旧版升级先备份，保留记忆、任务和旧记录。当前最多保留 128 个未删除计划，已删除历史不占可新建额度。计划列表分页，发生历史按编号向前翻页；展开旧记录时暂停该列表自动刷新，重新选择计划回到最新页。

实现入口：`crates/contracts/src/schedule.rs`、`crates/storage/src/schedule.rs` / `schedule_time.rs`、`crates/engine/src/tasks/schedules.rs`、`apps/desktop/src/SchedulePanel.tsx`。

验证命令：`npm run test:schedules-engine`、`npm run test:schedules-desktop`。桌面测试需要先 `npm run build`；也可通过 `WORKPILOT_ENGINE_BINARY` / `WORKPILOT_DESKTOP_BINARY` 指定受测分发文件。实际结果和失败修正统一写回 [P11 验证记录](P11-验证记录.md)。
