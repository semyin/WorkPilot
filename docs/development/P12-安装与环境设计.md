## 随包环境

主程序与引擎同目录携带以下组件，安装不修改全局 PATH，也不替换用户已有软件。

| 组件 | 固定版本 | 内容与边界 |
|---|---|---|
| Node | 22.23.2 | 独立 node.exe 与完整许可证；不附带 npm 包管理器 |
| Python | 3.13.16 | 官方嵌入式包及标准库；含 SQLite、加密摘要等；不包含 pip 或任意第三方包 |
| Git | MinGit 2.56.0.windows.1 | 命令与运行库、组件许可证；不包含 Git Bash |
| 文档工具 | P10 锁文件对应版本 | 固定 npm 依赖、文档生成/解析代码和中文字体 |
| Office 预览 | LibreOffice 26.8.0 | 原版式转换、字体、应用内 C++ 运行库、受限转换进程与许可证 |
| 日常浏览器连接 | 本版 Companion | Chrome/Edge 扩展及本机桥接程序；用户主动加载、注册和连接 |

资产下载地址、压缩包长度、SHA-256 和来源固定在 [Windows 清单](../../resources/runtimes/windows-x64.json)。每次解压前核对摘要，拒绝目录逃逸、重复目标、链接和过大压缩包；缓存发生变化时使用新的目录重新解压，保留旧缓存，不覆盖用户环境。

`scripts/package-p12.mjs` 核对正式构建回执及本次 Office/文档运行清单，再装配新目录。旧交付只作为历史来源记录，不依赖被 Git 忽略的旧程序包；应用自有程序和脚本来自本次构建与源码。未知文件不能混入安装包。清单不包含用户数据库、模型配置、密钥、浏览器个人资料或测试数据。

## 执行时怎样找到工具

```
任务请求 python / node / git
               ↓
      当前程序目录的固定工具
               ↓
         原有审批与执行边界
               ↓
        记录输出与文件版本
```

模型命令支持上述简单名称和明确的绝对路径。终端、Git 与技能/插件运行器共用解析规则。有分发清单时，缺少随包工具明确要求修复，不悄悄使用全局同名工具；开发模式仍保留原 PATH 查找。没有修改模型权限、审批指纹或文件版本规则。

Windows 请求审批模式下，Python/Git 的沙盒只获得当前应用内运行目录的读取权限，以加载动态库和标准库。沿用现有权限日志和恢复流程；不向全局 Python/Git 目录添加权限。Node 插件仍沿用应用数据内的副本，避免修改系统 Node 权限。

捕获子进程输出时固定 `PYTHONUTF8=1`，已核对嵌入式 Python 的初始化会读取此项，避免中文输出被默认单字节编码拒绝。此项不复制用户环境或扩大文件权限。

当前已发现通用 `run_command` 的 Git 在 AppContainer 中不能解析祖先目录，`GetFinalPathNameByHandleW` 和 `GetLongPathNameW` 返回拒绝访问。此兼容项记录为 T-P12-04；不能为它开放项目父目录读取，也不会自动降级为未隔离命令。完全访问 Git 和原有工作区审批 Git 是不同通路，验证结果分别记录。

## 安装与卸载

使用 Tauri 2 的 NSIS 安装程序，仅安装到当前用户目录，可选择中英文。安装资源逐项列入配置，主程序与引擎摘要随包记录。安装器包含微软 WebView2 离线安装器；已有合适运行环境时复用，缺失系统的实际安装仍须干净系统验证。

Office 与 WebView2 的总输入超过默认压缩路径的映射能力，第一次 NSIS 构建报 `error mmapping datablock`。保留 CLI 2.12.1 的原模板和 MIT 许可，只将整体压缩改为逐文件压缩。不能通过漏装 Office 或 WebView2 规避该问题；生成和实际安装结果另行核验。

安装程序当前没有发布签名，属于私有开发预览。关闭降级安装不等于实现签名更新；本批不提供自动下载替换程序或数据库降级。

默认卸载只删除安装清单内的程序文件，保留用户项目和 WorkPilot 数据。后续数据清理必须按范围确认，不能用卸载直接删项目。本机自动测试采用全新的中文/空格目录和独立数据，先检查注册表所有权；发现已有安装或启动项时停止该测试，不覆盖它们。

## 环境诊断

设置中的“环境检查与诊断”向引擎发送只读检查。快速检查只读取路径与长度元数据，不打开文件内容；完整检查分块核对 SHA-256，可识别同长度文件被改动。清单限 16 MiB、24 个组件、100000 个文件；拒绝路径逃逸、重复条目和链接。

`0.1.0-alpha.12.1` 将实际扫描移入随包 `workpilot-runtime-check` 独立程序，固定检查自身安装目录，不接受外部路径，不读取任务数据库或模型配置。引擎拥有其进程生命周期，30 秒没有读取进展或总用时达到 100 秒会结束本次检查；应用彻底退出也终止它。进度管道按行和队列限制大小。超时明确表示“尚未确认文件完整”，不继续显示上一份成功报告；没有把界面原有 120 秒等待延长，也没有省略完整核验文件。该处理隔离并限制系统文件读取卡顿，不能证明系统底层阻塞的来源已经消除。

报告只含应用版本、组件来源/许可、数量、大小和相对问题路径。用户主动导出 JSON，不自动上传，不读取任务正文、用户目录、认证头或浏览器登录资料。该清单用于发现损坏，不能抵御清单和程序同时被替换，不代替更新签名。

## 开发与复现

先执行 `npm run check`。发布构建与打包按以下依赖顺序，不能在构建未完成时使用旧回执打包：

1. `npm run runtimes:prepare`：核对和解压固定版本工具。
2. `node scripts/cargo.mjs build -p workpilot-browser-bridge --bin companion --release --locked`。
3. `npm run build`：生成主程序、引擎、环境检查助手、浏览器连接助手、Office 辅助程序和构建回执。
4. `npm run package:p12`：生成独立预览、组件清单及安装资源映射。
5. `npm run test:installation-engine`、`npm run test:installation-desktop`。
6. `npm run bundle:installer`：生成包含 WebView2 离线组件的安装器；未签名状态写入回执。
7. `scripts/installer-smoke.ps1 -Installer <本次安装器绝对路径>`：新目录安装、运行上述实测、卸载与保留文件检查。

实际检查与限制以 [P12 验证记录](P12-验证记录.md) 为准，不把命令存在当作已执行。

## 接续：Chrome / Edge 连接配置

设置页增加“Chrome / Edge 连接设置”。用户可检查当前配置、配置当前安装、移除当前安装的配置、复制或打开随包扩展目录。状态明确区分“本机已配置”和“浏览器已授权”：没有读取浏览器个人目录，也不声称已经安装扩展或取得某个标签页的控制权。当前私有分发仍需用户在浏览器扩展管理页加载随包扩展。

实现统一放在 `crates/platform/src/browser_setup`；引擎命令、设置界面及随包 `workpilot-browser-setup.exe` 使用同一规则。原注册脚本改为调用此助手，避免脚本与界面规则不同。操作仅修改当前用户的固定 Companion 登记，不改 Probe、系统级登记、全局 PATH 或浏览器登录资料。

- 检查 Chrome/Edge 各自的当前用户和系统级 32/64 位记录；同名记录指向另一目录或类型异常时阻止覆盖，执行时重新读取，不只依赖界面旧状态。
- 当前用户 Software 在 Windows x64 中由两种视图共享，注册写一次；移除对两种视图核对。非空的其它值和子项保持原样，不能递归删除整棵登记。
- Edge 没有自己的登记时可能沿用 Chromium/Chrome，界面提示这一点；配置和移除 Edge 不修改 Chrome 的记录。
- 核对随包扩展实际文件、固定扩展标识和本机桥接程序；文件缺失、改变或目录为链接时拒绝注册。生成文件用不覆盖已有文件的方式建立，未知文件不被修复动作覆盖。
- 路径按系统目录层级拼接，兼容上一版随包脚本生成的同目录 Windows 清单；不能因为显示时混用分隔符误报旧配置损坏。
- 不向模型暴露安装命令；仅主应用界面可打开固定扩展目录，网页预览不能指定任意路径。
- 移除登记阻止通过该记录创建新连接，不伪称已断开活动连接。用户可在扩展中断开，或停止对应任务。
- macOS/Linux 返回未实现状态，等待 P14/P15，不把 Windows 注册方式套用到其它系统。

Windows 卸载器先完成运行中应用检查，随后只清理默认值与当前 `$INSTDIR` 匹配的 Companion 登记。不存在或另一目录的记录保留；删除默认值后检查剩余值与子项，再清理空项。登记删除失败会停止卸载，应用文件尚未删除。最后清理固定的生成清单，遇到被替换为目录链接的安装/连接目录时跳过该清单清理；不递归删除用户额外文件。`/UPDATE` 原位置更新模式保留登记与生成清单，但这只验证卸载钩子行为，不代表签名更新、升级协调或数据库迁移已经实现。

本批比较逐文件 LZMA 与 zlib 后，P12 发布配置选择 zlib，并关闭数据块重复比较：本机一次对比中打包从约 13 分 28 秒缩短到 3 分 55 秒，安装器从约 677 MiB 增至 833 MiB，随包文件内容不变。这是当前机器的一次对比，不是所有机器的性能保证。完整历史/凭据清理仍属于 T-P12-03/T-P12-05，不把现有桌面缓存选项当作完整数据删除。

接续依据：[Chrome 本机消息文档](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)、[Edge 本机消息文档](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging)。登记与浏览器授权是两步；两者的真实验收范围分别记录。

T-P12-01 的新资产为 ungoogled-chromium Windows x64 `154.0.8037.57-1.1`。下载自项目发布页，198766792 字节，SHA-256 为 `d4b8f53e8100e428a6ccea8070a1a909af3022c21070bfcd7dca102990d95d88`，与上游资产摘要及实际下载一致。旧 snapshot 1710726 继续保留为被排除的历史候选，不被重新启用。

实际启动后的 `chrome://credits` 是 8678140 字节的完整组件许可页，包含各组件的许可原文，不是示例页。准备脚本检查浏览器版本、许可页内容、两个根许可证的固定摘要；打包必须具有匹配所选压缩包的许可回执。包内保留 `CREDITS.html`、Chromium 与 ungoogled-chromium 根许可证及源码/发布来源 `SOURCE.json`。浏览器不自行更新，随受验证的应用资源版本更新。

浏览器工作区新增“启动专用随包浏览器”。新增 `chromium` 通道固定启动应用内 `chromium-runtime/chrome.exe`，缺失或被链接到安装目录外时明确失败。它使用当前任务自己的浏览器资料目录；启动、页面权限、审批、人工接管、停止和彻底退出继续沿用原有流程。原专用 Chrome/Edge 与日常连接入口保留；日常连接仍须用户主动授权。

T-P12-04 使用同版本 Git 源码构建的 `2.56.0.windows.1.workpilot.1` 路径兼容版。实际 AppContainer 检查确认：DOS 卷名 API 返回拒绝访问，而同一已打开文件句柄的 NT 路径可读。启动器仅提供项目与应用所在本地卷的名称映射；兼容版转换路径拼写，并从已经可访问的最近父目录开始创建缺少的 Git 子目录。没有开放项目祖先目录、传递额外文件句柄或建立未隔离代执行通道。

只有本应用随包 Git 的受限命令切换到兼容版；原 AppContainer、禁网、审批、停止与 ACL 清理保留。完全访问继续使用官方 MinGit。未知/非本地卷映射、缺少兼容版和目录异常继续失败。兼容构建提供本地 Git 内置命令，未包含 curl、PCRE2、gettext、Git Bash 或 Git LFS；受限通道原本就不允许网络，完整 MinGit 的原通路不变。源码、补丁、固定输入清单、许可证和可复现构建方法随包留存，见 [构建说明](../../resources/git-sandbox/README.md)。编译时核对只依赖 Windows 系统 DLL，不隐含要求用户安装额外 C 运行库。

环境清单新增 `chromium` 与 `git_compat`，合计九个组件。快速检查仍只读取元数据；完整检查核对所有文件。独立检查程序在每次打开组件文件前报告当前尚未完成的相对路径；发生系统读取阻塞时，原 30 秒无进展/100 秒总预算照常终止。该信息不含项目正文、用户路径或凭据。它帮助定位 T-P12-06，再次检查成功不能用来宣称已查明某个系统过滤驱动的根因。

首轮整合包的两次完整核验超出 100 秒，失败报告保留。直接 helper 定位在约 94.97 秒读完 25238 项，其中办公组件约 91.64 秒；观测到的最大单段停顿约 1.572 秒，没有证据证明某个文件停滞 30 秒。随后十轮检查通过，其中第一轮完整核验约 71.75 秒，后四轮约 10 秒；这些后来通过的结果不替代首次失败，也不证明根因是并发压缩、缓存或某个过滤驱动。

接续改为固定四个读取工人，复用同一有界队列并由独立检查程序统一收尾。每项仍重新检查每层目录、文件大小和完整摘要，不缓存目录结论，不跳过慢文件；结果与错误按清单顺序汇总。诊断显示最早尚未完成的读取，较快文件不能掩盖一个较早的慢读取。取消、坏文件、缺失文件、诊断输出失败及原有超时/进程回收检查通过。最终版本的实际计时在独占核验 I/O 的条件下另测，条件与结果写入验证记录。
