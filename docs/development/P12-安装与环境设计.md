# P12 安装与环境设计

本批为 Windows x64 的安装与环境切片，程序版本 `0.1.0-alpha.12`，数据版本仍为 11。P12 仍在实施中：浏览器完整随包、受签名保护的更新、完整数据迁移和版本清理尚未交付。旧 P11 包及其历史清单保持不变。

## 随包环境

主程序与引擎同目录携带以下组件，安装不修改全局 PATH，也不替换用户已有软件。

| 组件 | 固定版本 | 内容与边界 |
|---|---|---|
| Node | 22.23.2 | 独立 node.exe 与完整许可证；不附带 npm 包管理器 |
| Python | 3.13.16 | 官方嵌入式包及标准库；含 SQLite、加密摘要等；不包含 pip 或任意第三方包 |
| Git | MinGit 2.56.0.windows.1 | 命令与运行库、组件许可证；不包含 Git Bash |
| 文档工具 | P10 锁文件对应版本 | 固定 npm 依赖、文档生成/解析代码和中文字体 |
| Office 预览 | LibreOffice 26.8.0 | 原版式转换、字体、应用内 C++ 运行库、受限转换进程与许可证 |
| 日常浏览器连接 | 本版 Companion | Chrome/Edge 扩展及本机桥接程序；用户主动加载、注册和连接 |

资产下载地址、压缩包长度、SHA-256 和来源固定在 [Windows 清单](../../resources/runtimes/windows-x64.json)。每次解压前核对摘要，拒绝目录逃逸、重复目标、链接和过大压缩包；缓存发生变化时使用新的目录重新解压，保留旧缓存，不覆盖用户环境。

`scripts/package-p12.mjs` 核对正式构建回执及本次 Office/文档运行清单，再装配新目录。旧交付只作为历史来源记录，不依赖被 Git 忽略的旧程序包；应用自有程序和脚本来自本次构建与源码。未知文件不能混入安装包。清单不包含用户数据库、模型配置、密钥、浏览器个人资料或测试数据。

## 执行时怎样找到工具

```
任务请求 python / node / git
               ↓
      当前程序目录的固定工具
               ↓
         原有审批与执行边界
               ↓
        记录输出与文件版本
```

模型命令支持上述简单名称和明确的绝对路径。终端、Git 与技能/插件运行器共用解析规则。有分发清单时，缺少随包工具明确要求修复，不悄悄使用全局同名工具；开发模式仍保留原 PATH 查找。没有修改模型权限、审批指纹或文件版本规则。

Windows 请求审批模式下，Python/Git 的沙盒只获得当前应用内运行目录的读取权限，以加载动态库和标准库。沿用现有权限日志和恢复流程；不向全局 Python/Git 目录添加权限。Node 插件仍沿用应用数据内的副本，避免修改系统 Node 权限。

捕获子进程输出时固定 `PYTHONUTF8=1`，已核对嵌入式 Python 的初始化会读取此项，避免中文输出被默认单字节编码拒绝。此项不复制用户环境或扩大文件权限。

当前已发现通用 `run_command` 的 Git 在 AppContainer 中不能解析祖先目录，`GetFinalPathNameByHandleW` 和 `GetLongPathNameW` 返回拒绝访问。此兼容项记录为 T-P12-04；不能为它开放项目父目录读取，也不会自动降级为未隔离命令。完全访问 Git 和原有工作区审批 Git 是不同通路，验证结果分别记录。

## 安装与卸载

使用 Tauri 2 的 NSIS 安装程序，仅安装到当前用户目录，可选择中英文。安装资源逐项列入配置，主程序与引擎摘要随包记录。安装器包含微软 WebView2 离线安装器；已有合适运行环境时复用，缺失系统的实际安装仍须干净系统验证。

Office 与 WebView2 的总输入超过默认压缩路径的映射能力，第一次 NSIS 构建报 `error mmapping datablock`。保留 CLI 2.12.1 的原模板和 MIT 许可，只将整体压缩改为逐文件压缩。不能通过漏装 Office 或 WebView2 规避该问题；生成和实际安装结果另行核验。

安装程序当前没有发布签名，属于私有开发预览。关闭降级安装不等于实现签名更新；本批不提供自动下载替换程序或数据库降级。

默认卸载只删除安装清单内的程序文件，保留用户项目和 WorkPilot 数据。后续数据清理必须按范围确认，不能用卸载直接删项目。本机自动测试采用全新的中文/空格目录和独立数据，先检查注册表所有权；发现已有安装或启动项时停止该测试，不覆盖它们。

## 环境诊断

设置中的“环境检查与诊断”向引擎发送只读检查。快速检查核对路径与长度；完整检查分块核对 SHA-256，可识别同长度文件被改动。清单限 16 MiB、24 个组件、100000 个文件；拒绝路径逃逸、重复条目和链接。检查在后台线程运行，退出信号可取消，避免卡住任务循环。

报告只含应用版本、组件来源/许可、数量、大小和相对问题路径。用户主动导出 JSON，不自动上传，不读取任务正文、用户目录、认证头或浏览器登录资料。该清单用于发现损坏，不能抵御清单和程序同时被替换，不代替更新签名。

## 浏览器候选未进入分发

官方 Chromium snapshot 1710726 的下载文件已核对，实际可启动，版本为 157.0.8086.0。但该构建的 `chrome://credits` 只有示例页，提示需启用 `generate_about_credits`，没有完整组件许可。因此该项标记 `blocked-missing-component-licenses`，正常准备和打包都会排除它。不能把 Playwright 的许可当作浏览器许可，也不能把页面可打开当作可分发验证。

本批仍使用已有 Chrome/Edge。P12 后续需要选择许可材料完整的浏览器构建，或建立可重复的自有 Chromium 构建，再完成随包专用浏览器测试；此项是开发待办，不是要求用户安装软件来替代首版要求。

## 开发与复现

先执行 `npm run check`。发布构建与打包按以下依赖顺序，不能在构建未完成时使用旧回执打包：

1. `npm run runtimes:prepare`：核对和解压固定版本工具。
2. `node scripts/cargo.mjs build -p workpilot-browser-bridge --bin companion --release --locked`。
3. `npm run build`：生成主程序、引擎、Office 辅助程序和构建回执。
4. `npm run package:p12`：生成独立预览、组件清单及安装资源映射。
5. `npm run test:installation-engine`、`npm run test:installation-desktop`。
6. `npm run bundle:installer`：生成包含 WebView2 离线组件的安装器；未签名状态写入回执。
7. `scripts/installer-smoke.ps1 -Installer <本次安装器绝对路径>`：新目录安装、运行上述实测、卸载与保留文件检查。

实际检查与限制以 [P12 验证记录](P12-验证记录.md) 为准，不把命令存在当作已执行。
