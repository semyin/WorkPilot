# P12 历史备份与恢复

日期：2026-10-04。程序 `0.1.0-alpha.12.2`，数据版本仍为 11。本批接续 T-P12-03，实现所选文件历史的完整导出、预览、导入和恢复；完整会话、项目资料、模型配置、技能、记忆迁移及清理仍待接续，不代表整个 P12 已完成。

## 用户怎样操作

在已绑定项目文件夹的任务中打开“文件与终端 → 修改历史 → 备份与导入文件历史”。

1. 勾选要备份的历史记录，选择一个新的保存位置，输入两次备份口令，保存 `.wphistory` 文件。每条记录包括修改前和修改后的版本；不存在的版本也保留其状态。
2. 在目标项目的任务中选择备份、输入口令，先预览记录数量、内容大小和相对路径。已有同名文件会明确列出。
3. 确认后只添加到目标项目的历史列表，不改项目当前文件；再次导入同一份备份到同一实际目录不会重复添加。
4. 在历史列表查看差异并选择恢复。恢复仍要求执行模式、原权限审批及当前文件版本核对；覆盖前保存当前内容，便于再恢复。

口令至少 12 个字符，软件不保存口令，遗失后无法解密。备份按原字节保存用户选中的历史文件，因此文件本身的敏感内容同样在加密备份内。应用模型凭据、认证头、浏览器登录资料和操作系统内的版本库密钥不作为设置或密钥材料导出。这个文件历史备份不包含当前项目所有文件，也不替代完整资料迁移。

导入记录绑定目标目录的实际身份，保留原任务、操作、版本编号、时间与来源。来源来自备份内容，不是外部作者签名。嵌套路径的父文件夹不存在或不可读取时，预览会说明；恢复前需要准备对应文件夹。本批不自动创建整棵项目目录。

本批导出入口需要源任务绑定的项目目录仍能打开。源目录已删除、离线项目、完整目录树与其它资料的统一迁移留在完整迁移部分；保留原应用数据不等于已经完成这些迁移。

## 执行与数据边界

```text
选择已保存的版本 → 解开本机加密版本 → 用独立口令加密备份
                                              ↓
目标项目：完整核验 → 展示预览 → 确认 → 写入目标加密版本库和历史
                                               ↓
                                 另行选择恢复 → 原审批 → 修改项目文件
```

使用独立的 `HistoryTransfer` 管理命令，不把口令放入普通工作区操作参数、模型工具、事件或命令去重表。沿用已有 `SecretInput` 的调试输出脱敏和释放清除。界面只在内存持有口令，成功后清空输入框，不写本地存储。原生选择框仅允许主应用窗口调用。

后台一次处理一个历史迁移，普通任务与界面仍可运行。全局执行设置变化会取消当前操作，下一次显式请求可重新发起；应用彻底退出标记关闭并取消，不能由旧排队请求重新开启。文件访问本身仍受系统响应时间影响，不承诺任意设备上的即时中断。

导出临时文件从第一字节起就是加密数据，完整写入并同步后才发布，目标已存在时拒绝覆盖。P04 旧文本版本逐个读取、核对后进入本机加密版本库，再用统一路径导出；不会把整个数据库复制进包中。

导入先完整校验所有对象，不先插入历史记录；再次读取并验证后用目标本机密钥重新加密。数据库用单次事务登记导入回执、全部历史及事件，失败全部回滚，重启可识别已完成导入。预览指纹绑定备份内容、目标任务、目录身份和有效设置；确认时重新核对。

失败或中断可能留下已经写入、但没有历史引用的加密对象；不会留下只写一半的历史记录或改动项目文件。不在本批自动删除这些对象，避免与已有版本共用对象发生冲突。版本保留、垃圾清理和团队历史删除继续留在 T-P12-03。

## 备份格式与容量

- 固定头 `WPHIST01`，格式版本 1，随机 16 字节盐值；使用现有 ring 0.17.14。
- PBKDF2-HMAC-SHA-256 固定 600000 次，导出密钥只服务当前随机盐值的备份。该参数是本批工程选择，参考 [OWASP 的 PBKDF2 参数说明](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#pbkdf2) 与 [ring 接口文档](https://docs.rs/ring/0.17.14/ring/pbkdf2/fn.derive.html)，不声明取得密码模块认证。
- 清单和每个唯一文件对象分别使用 AES-256-GCM，随机 12 字节 nonce，头与顺序编号作为认证附加数据。清单也加密；不在包外暴露文件名和任务来源。
- 按 SHA-256 去重并核对文件原始字节。读取按单个文件进行，最多 64 MiB；单次最多 128 条历史、256 MiB 去重内容；清单最多 1 MiB。
- 拒绝未知格式、异常长度、重复版本、相对路径逃逸、Git 内部路径、链接或重解析路径、缺失内容、认证失败和多余尾部数据。格式不使用可执行脚本或压缩包路径展开。
- 本地 FileRevision 增加可选 `origin`，旧记录缺失此字段时正常读取。没有删除或迁移旧表，没有把历史原文混入普通脱敏内容对象。

## 实现与复现

主要文件：`crates/contracts/src/history_transfer.rs`、`crates/workbench/src/transfer`、`crates/storage/src/history_transfer.rs`、`apps/desktop/src/HistoryTransferPanel.tsx`。旧版本恢复继续使用 P07 的工作区审批路径。

- `npm run check`：已有基础检查和新增格式/事务测试。
- `node scripts/history-transfer-test.mjs`：两个独立测试数据目录，移动原数据使其不可用，导入后恢复原二进制内容、审批、去重、重启和口令持久化检查。可用 `WORKPILOT_ENGINE_BINARY` 指定本次发布引擎。
- `node scripts/history-transfer-desktop.mjs`：真实 Windows 桌面的双语导出、错误口令、预览、确认导入、审批恢复、重复导入提示和退出。可用 `WORKPILOT_DESKTOP_BINARY` 指定本次程序。

实际通过、失败修正和交付证据写入 [P12 验证记录](P12-验证记录.md)。单机独立密钥验证不等于另一台电脑或 macOS/Linux 实机验收；原生文件选择框和日常使用体验继续集中待用户验证。
