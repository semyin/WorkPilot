# P10 文件输入、成果与图片服务

更新：2026-10-04。本阶段正在实施；本文件只描述已经接入的能力和保留的缺口，不把开发预览当作完整 V1。

## 已接入的路径

用户选择、拖入文件或在任务输入框粘贴图片 → 分片传到本机引擎 → 独立文档进程解析 → 保存原始字节和解析快照 → 随用户消息关联任务。正文不会被直接塞进 16 KiB 的任务指令中；消息只携带附件编号。

新消息尚未交付时，其中的附件不会因此提前进入模型上下文。任务之间不能互读附件。图片只有在所选模型明确支持图片输入时才发送；模型接收有大小限制的预览，原图仍保留。PDF 的文字提取不等于扫描件识字，也不等于模型已经检查过页面画面。

任务顶部新增“文件成果与图片”。可查看附件、生成成果、来源、内容版本、日期和项目内路径；读取项目文件、查看内容及 PDF/图片预览、打开外部软件、刷新外部修改后的版本。刷新创建新快照，旧快照保留。

## 当前格式矩阵

| 格式 | 读取 | 生成 | 软件内预览 | 编辑 |
|---|---|---|---|---|
| TXT / Markdown | UTF-8 文字，带行号 | 实际 UTF-8 文件 | 文字 | P07 文本编辑或外部软件 |
| CSV | 原始文字及行号 | 有引号转义的行列；公式形式的字符串按文本保护 | 文字 | P07 或外部软件 |
| DOCX | 正文与表格中的段落；引用段落位置 | 标题、分节、段落、表格 | 内容预览；从原文件转换的分页版式画面 | 外部办公软件 |
| XLSX | 工作表、单元格地址、保存的公式及缓存值 | 多工作表、数据、受支持的公式及核算缓存、静态柱形图图片 | 内容预览；按工作表打印设置转换的分页画面 | 外部办公软件 |
| PPTX | 按演示顺序读取幻灯片文字 | 多页、标题、正文、表格、可编辑图表 | 内容预览；按原文件转换的幻灯片画面，不播放动画 | 外部办公软件 |
| PDF | 按实际页号提取文字；无文字时说明未做 OCR | 新排版生成的 PDF，分页、中文字体 | 实际文件页面的位图预览 | 原文件交给外部软件 |
| PNG / JPEG / WebP / GIF | 核对实际格式、解码、尺寸 | PNG/JPEG/WebP 通过单独配置的图片服务 | 位图；GIF 首帧 | 图片服务参考图编辑，保存为新成果 |
| HTML / SVG / XML 等文字 | UTF-8 源文及行号 | 原有文本工具可写入 | 显示源文字，不执行脚本或加载外部资源 | P07 或外部软件 |

XLSX 内置公式只支持四则运算，以及 SUM、AVERAGE、MIN、MAX 的单表范围。拒绝不能核算的公式，而不是捏造缓存值。XLSX 图表是图片；PPTX 图表是演示文件里的实际图表，两者不混称。复杂办公模板、全部公式、宏和完整 Office 编辑不属于当前实现。

PDF 新生成与把已有 DOCX 转成 PDF 是两种行为。当前 `document_create` 的 PDF 路径是**新生成**，回执明确 `conversion=false`。使用固定、可再分发的 Noto 字体；发现字形缺失会报错。修复字体子集显示缺字后，当前使用完整字体嵌入，简单中文 PDF 也可能约 13 MiB，后续再优化体积。

2026-10-04，`0.1.0-alpha.12.8` 修正完整字体嵌入时的数字文字映射：固定简体中文字体禁用 `locl` 地区字形替换，避免英文上下文的数字被替换为缺少 PDF 文字映射及宽度的备用字形。使用现有库公开的字体特性选项，不改第三方源码、不切回此前缺字的字体子集。标题、正文、表格、长行与跨页数字纳入回归；旧 PDF 原文和已保存解析快照不会追改，需要重新生成。实际验证见 [P10 验证记录](P10-验证记录.md)。

## 模型和统一操作

模型可用 `document_list`、`document_read`、`document_import` 读取本任务资料；用 `document_create`、`image_services`、`image_generate` 生成成果。文件读取按范围补读；模型需要引用文件名、编号和返回的页/表/段落位置。大结果原文保存在执行记录中。

文件和图片生成复用 P07 的实际目录身份、修改锁、具体参数审批、停止、文件前后版本和成果登记。聊天与规划不执行生成；两种审批模式中的此类手工/模型操作需要具体批准，完全访问按现有规则执行。修改图片配置或目标文件后，旧审批失效。生成期间被外部改动的目标也会再次核验，不静默覆盖。

模型发起的操作审批完成后，继续原任务读取已保存回执，不再调用一次生成服务。图片调用失败使本次 AI 任务失败；请求不自动重试、不切服务。文本模型可以调用图片工具，但没有收到图片像素时不得声称看过结果。

## 图片服务

采用独立的 Images API 适配：`images/generations` 和 `images/edits`，后者发送实际参考图文件。配置包含服务地址、模型、支持的尺寸/质量/格式、数量上限和参考图能力，不继承文字模型的密钥或图片能力。

密钥保存到系统凭据库。服务请求不跟随跳转，HTTPS 为默认要求；本机测试地址可使用 HTTP。仅接收实际 `b64_json` 图片内容，只有 URL 的返回当前会明确报错，不自动下载未知链接。校验数量、编码、实际格式、可解码性和具体尺寸后才写入成果。用户声明的服务能力仍须用自己的服务验证，保存配置不代表连通性测试通过。

模型用量与图片服务用量分别记录。图片服务没有返回可信的准确费用时显示未知，不写成零费用。取消只能停止本机等待和后续写入，不能承诺服务已撤销收费。

## 保存、进程与容量

- `crates/contracts/src/media.rs` 定义命令；SQLite schema 9 保存附件和图片配置。原始文件与解析快照复用加密版本库，普通记录保留脱敏元信息。
- `crates/workbench/src/media` 管理导入、解码、图片服务和成果；`services/documents` 是独立、禁止网络的文档处理程序，不接收任意脚本或任意磁盘路径。
- Node 程序使用应用自己的校验副本，不修改用户 Node 安装文件的权限。工作目录只含本次输入、固定任务参数及输出；任务结束回收目录和所属进程。父任务停止也覆盖文档处理所属的子任务。
- 单文件上限 32 MiB；提取文字上限 4 MiB、20000 段；Office 解压总量 64 MiB；PDF 最多 500 页；图片最多约 3200 万像素。
- 每条消息最多 16 个附件；模型每次至多接收 4 张附件图片，单张预览最长边不超过 1024 像素。UI 附件列表展示最近 256 个快照，模型上下文提供有限目录和摘要，可按编号补读，不承诺一次读完全部文件。
- 处理器当前串行执行，最多 4 个在处理/等待的文件任务；排队处理支持取消。普通文本和 DOCX 读取按需加载组件，避免为小文本初始化整个办公库。
- `scripts/prepare-documents.mjs` 准备锁定依赖和字体；标准桌面构建携带文档环境。完整安装、运行环境精简及迁移仍在 P12。

## Office 原版式预览补充

在“查看内容”后选择“查看原版式预览”：引擎从当前附件的加密原始快照取出实际文件，由独立 LibreOffice 工作进程转为 PDF，再用既有 PDF 处理器显示页面。回执包含 `conversion=true`、原文件摘要、转换器版本、实际总页数和缓存命中情况；这与 `document_create` 重新排版生成 PDF 的路径不同。

转换器使用官方未修改的 LibreOffice 26.8.0 与随附 Python 3.13.15。Rust 小型启动器加载固定组件，LibreOfficeKit 启动后通过 UNO 主线程回调执行加载/保存，避开 Windows 命令行实例通信及 Calc 跨线程死锁。不能联网；只读应用自己的转换资源，只能写单次临时目录。宏关闭、外部更新关闭、只读加载，不改原文件。输入文件夹中的脚本、用户 Python 环境和模块不参与加载。

原版式表示转换实际文件，不承诺与 Microsoft Office 像素一致。缺失字体、复杂对象、打印设置和公式兼容性可能影响结果；表格解析仍读取保存的公式/缓存，版式转换器可能重新核算其支持的普通公式。转换失败明确报错，不用重建文字冒充成功。

转换串行执行，缓存仅存于当前引擎内存，按文件摘要和转换组件清单区分，最多 4 份、共 64 MiB。输入与中间 PDF 均最多 32 MiB，页面最多 500；工作进程最长 90 秒，整个预览最长 110 秒。停止、移除附件、关闭面板会取消所属预览；停止确认与进程/权限清理完成的耗时分开记录。外部刷新产生新快照，新旧文件分别预览。

环境采用 `office-runtime/office` 两层目录，LibreOffice 需要读取安装目录的直接父目录，因此只对应用自己的外层目录授权。标准构建自动准备完整运行环境和许可证；当前约 1.58 GB，仍待 P12 精简与干净机器验证。完整工程入口见 [固定预览进程](../../services/office/README.md)。

### 深目录兼容与临时文件（2026-10-04）

T-P10-04 的同一字节样本在短工作目录可转换，工作目录增长至 170/210 字符时于 Office 初始化阶段以 `0xC0000409` 退出，文档尚未加载。已改为当前用户系统临时目录内的独立短工作区；原数据目录、项目文件和加密附件库不迁动，也不通过链接或扩大系统权限绕过限制。工作目录保守限制为 120 个 Windows 路径字符，给第三方组件的内部子路径预留空间。特殊系统临时位置超过限制时，在写入原文前明确失败；并未修改或宣称修复 LibreOffice 内部原生函数。

工作目录按数据根目录摘要分组。每次预览持有目录外的独占登记文件，清理只能回收自己这一数据根下、没有活动持有者且登记相符的目录；不触碰未知文件、重定向目录和其它运行中的预览。正常完成、失败和取消都清理原文副本及 PDF；宿主崩溃后由下一次预览回收残留。这个清理只处理预览临时副本，不是 P12 尚未实施的资料保留/永久删除策略。

错误信息包含固定退出编号和最后已知转换阶段，不再将缺少结果报告误报为原文件丢失；任意标准错误、报告文本和本机路径不直接暴露。另将文档工具私有缓存规范化为 Windows 扩展路径，修复深数据目录中的首次准备失败。复现和实际检查结果见 [P10 验证记录](P10-验证记录.md)。
