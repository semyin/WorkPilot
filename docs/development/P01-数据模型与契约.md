# P01 数据模型与通信契约

更新日期：2026-10-01。适用于当前工作区的 P01 实现。本文描述已经存在的接口，并标出尚未接入的业务行为。

## 1. 数据由谁管理

~~~text
React 界面
  │ 发送有编号的命令，按序号读取记录
  ▼
Tauri 宿主（只接受主界面调用）
  │ 本机管道；等待对应编号的答复
  ▼
Rust 引擎
  │ 有容量限制的队列
  ▼
独立保存线程
  ├─ SQLite：任务、状态、命令回执、事件与引用
  ├─ objects：按内容校验值命名的文字对象
  └─ backups：升级之前的独立数据库备份

模型凭据 → 系统凭据库；SQLite 只保存查找编号
~~~

只有 storage 模块拥有可写数据库连接。界面不接收数据库连接、SQL 语句或任意文件路径读取接口。开发检查工具使用只读连接，不执行迁移和恢复。浏览器预览网页仍不能调用主界面的引擎接口。

同一数据目录只允许一个引擎写入，使用操作系统文件锁；进程退出后锁由系统释放。第二个引擎会报“目录正在使用”，不会同时执行恢复逻辑。开发、测试、发布目录继续按 P00 的通道规则隔离。

## 2. 版本和权威来源

| 项目 | 当前值 |
|---|---|
| 管道事件协议 | workpilot.v1 |
| SQLite schema | 1，以 PRAGMA user_version 保存 |
| 事件导出格式 | workpilot.events，version=1 |
| 前后端类型来源 | crates/contracts/src/lib.rs、model.rs |
| 界面生成文件 | apps/desktop/src/generated/contracts.ts |

通过 npm run contracts:generate 生成界面类型。Rust 测试比较生成结果与已保存文件，字段变化而未更新界面类型会失败。大整数在 JSON 中用安全范围内的数字表示；事件序号上限为 2^53−1，不能任意突破后依赖 JavaScript 的舍入结果。

数据库是状态的权威来源。界面重新连接后只补读，不把旧缓存写回数据库。收到命令不等于完成任务，界面上的“进行中”和“已中断”依据实际事件更新。

P00 的 JSONL 是原型诊断镜像，不能作为任务恢复的数据源。P00 旧日志仍保留在原位置，不伪造成已经存在于 P01 数据库的任务；P00 本来没有正式任务数据库，不存在要升级的旧业务表。

## 3. 数据对象与字段

以下是当前 Rust 类型的字段责任。时间字段使用 UTC 毫秒，路径使用当前平台的绝对路径，编号是不可解释的关联标识。

| 对象 | 主要字段 | 当前落实程度 |
|---|---|---|
| Project | id、name、root_path、default_profile_id、permission、created_at_ms | 可保存项目文件夹绑定；不自动改动该文件夹 |
| Task | id、project_id、title、state、mode、permission、profile_id、created_at_ms、updated_at_ms、last_sequence | 已有创建、查询、状态更新和受限删除 |
| Run | id、task_id、agent_id、state、started_at_ms、ended_at_ms、result、failure_code | 固定验证任务实际写入；完成必须有结果引用和结束时间 |
| Message | id、task_id、role、state、queue_position、content、created_at_ms | 排队、引导请求持久化；P03 才交付模型执行 |
| Agent | id、task_id、parent_id、replaces_id、role、profile_id、state、attempt | 类型与表已预留；P05 才实现协作调度 |
| ProviderProfile | id、label、protocol、base_url、model、credential、supports_tools、supports_images | 可保存基础配置和凭据引用；P02 扩展认证、能力及配置版本 |
| ToolCall | id、task_id、run_id、agent_id、name、state、input、output、approval_id、started_at_ms、ended_at_ms | 内部接口可记录开始/结束，恢复时识别不确定操作；本阶段不启动真实工具 |
| Approval | id、task_id、action_hash、scope、rule_version、state、decided_by、decided_at_ms | 类型与表预留；P04 实现真正审批判断 |
| Artifact | id、task_id、path、latest_revision_id | 类型与表预留；P07/P10 负责真实文件操作 |
| Revision | id、artifact_id、content、predecessor_id、created_at_ms | 类型与表预留；删除任务时级联清理索引，不删除 path 指向的项目文件 |
| Schedule | id、project_id、task_template、rule、timezone、enabled、last_trigger_id、mode、permission、profile_id | 类型与表预留；没有运行定时器 |
| Memory | id、project_id、source_task_id、content、state、confirmed_at_ms | 类型与表预留；没有自动写入记忆 |
| ContentRef | object_id、bytes、media_type | 引用实际落盘内容；object_id 是 SHA-256 校验值 |
| CredentialRef | id | 系统凭据库中的查找编号，没有密钥字段 |
| Usage | input_tokens、output_tokens、cost_microunits、currency | 未知值为 null，不能冒充为 0 |

尚未实现业务流程的对象，表中使用受 JSON 格式校验的数据字段保留结构。项目、配置中的跨对象默认值、助手树、审批作用范围等业务检查，会在对应阶段接入；有表不等于功能已经可用。

## 4. 命令、回执和去重

请求外层是 request_id 和 command。每次新的用户意图使用新编号；因连接故障重发同一意图时复用原编号。

| 命令 | 当前作用 |
|---|---|
| ping | 验证引擎连接，保存对应回执 |
| start_probe | 创建固定验证任务及执行记录；返回 accepted，计数结束后才写 completed |
| stop | 停止当前固定验证任务；重复编号不影响后来开始的任务 |
| shutdown | 宿主退出控制，不作为可由网页发送的普通任务命令 |
| create_task | 创建排队状态任务，不调用模型 |
| enqueue | 保存用户文字和队列顺序 |
| steer | 把尚未处理的消息标成 steer_requested，保留原顺序与历史 |
| cancel | 保存取消意图；固定验证任务会实际停止，正式执行传播在 P03/P04 接入 |
| delete_task | 删除任务数据；存在运行中的执行或待核对工具时拒绝 |
| read | 分页读取事件、任务或文字对象，不改变状态、不写入命令回执 |

命令记录保留请求编号、内容指纹、类型、状态、任务关联及时间，不保存原始命令正文。规则如下：

1. 相同编号、相同内容：返回原回执，duplicate=true，不再次产生操作。
2. 相同编号、不同内容：返回 conflict，不猜测哪一次是用户本意。
3. 不同编号、相同内容：分别接受，不按文字内容吞掉新要求。
4. 删除任务后，仍保留不含任务正文的去重记录，防止迟到请求把已删任务重新创建出来。
5. accepted 只代表请求已保存。completed、interrupted 等最终状态由实际处理结果产生。
6. 宿主等待超时不会自动重新发送命令，也不会宣称原操作没有执行。

start_probe/stop 的接受与最终结果是分别提交的记录；短小的创建/入队命令可以在同一事务里同时保存接受记录和完成记录。数据库提交后才向界面发送事件。

## 5. 事件和补读

每个事件具有 protocol、event_id、sequence、task_id、task_sequence、agent_id、source、at_ms、request_id，以及明确的 kind 和载荷。

- sequence 是数据库全局序号；删除任务后允许有空号，不复用编号。
- task_sequence 是任务内部连续序号。
- source 区分用户、引擎、工具、模型和恢复程序。
- 请求补读时传 after，返回序号严格大于 after 的事件。
- 即使按 task_id 筛选，after 和 next_after 仍是全局序号。
- 返回 high_watermark 和 has_more；无更多事件时把游标推进到本次高水位，避免在已删除的空号处反复读取。
- 界面同时只显示最近 200 行；右侧历史每页 128 条；保存层最多返回 256 条。

载荷分别覆盖命令接受/结束、任务状态、排队/引导/取消、文本、工具开始/结束/待核对、审批、助手、成果、错误和用量。工具参数和大输出使用 ContentRef，不能塞入一个无限大的事件。

当前传输外层分为 type=event 和 type=reply。reply 用 request_id 对应原请求，避免把查询结果再次当作新事件保存。宿主内存环只作短缓存，engine_snapshot 已从数据库补读。

## 6. 事务、崩溃和恢复

SQLite 使用 WAL 和 FULL 同步。WAL 是先把修改记入附属日志的方式，SQLite 据此恢复尚未合并到主文件的提交；不能手工只复制正在使用的主数据库来假称完整备份。

- 状态、结果引用、事件和回执在同一个事务里提交；任何中途失败都回退整个事务。
- 固定任务完成时，执行记录必须有结果对象和结束时间；未核对的工具不能被当作已经完成。
- 工具开始写入成功后才允许后续执行层启动外部操作；没有结束记录的工具在重启后变为 needs_review。
- 运行、停止中、等待输入/审批的执行分支在重启后记为 interrupted；排队消息和引导意图保留。
- 重启不启动模型、不重放工具、不自动继续任务。
- P01 的恢复是恢复“记录和不确定状态”；真正点击继续并重新构造模型上下文属于 P03。

故障注入测试在修改状态之后、写结束事件之前直接终止测试子进程，退出时不运行 Rust 清理代码。另有真实引擎与桌面宿主强制退出检查。

## 7. 迁移、备份和导出

升级路径集中在 migrations 目录。升级前使用 SQLite 自己的备份接口，生成唯一命名的 before-vN-*.sqlite3，并确认备份已经写盘。随后在事务中运行迁移、更新版本、核对完整性和关联关系。

迁移失败时事务回退，原数据仍可用，独立备份不覆盖。高于当前支持版本的数据库被拒绝，不降级覆盖。测试包含迁移中途改写任务、创建半成品表后故意报错，并在新目录从备份副本恢复读取。

当前开发工具可导出事件 JSONL：

- 第一行为 ExportHeader，声明格式、schema/version 和 credentials_included=false。
- 后续每行一个事件，以一致的只读事务导出，边读边写。
- 这是开发诊断事件导出，不是含附件、技能、记忆和成果文件的整机迁移包。
- P12 的完整导入必须先校验格式/版本与内容校验值，未知较新版本拒绝；在临时目录构建和检查，成功后才切换，不在原唯一副本上边读边覆盖。
- 完整迁移不带模型密钥，迁移后凭据引用保持未配置，重新填写。

完整迁移包和用户导入界面尚未实现，不能把当前 events 导出文件当作可以直接恢复整台电脑的备份。

## 8. 内容对象和删除边界

P01 对象接口处理 UTF-8 文字。内容先脱敏、写到同目录临时文件、确认写盘，再按校验值保存，最后才允许数据库引用。相同内容可以共用对象。

当前工程上限：单行 64 KiB、单对象 256 MiB；超过时明确报错，不悄悄截断。32 MiB 流式输入已经测试。多字节中文的分页位置不会停在一个字符中间。图片及其他二进制对象在 P07/P10 接入，不能把本阶段文字接口当成任意附件处理器。

回收只扫描专用 objects 目录中的合法校验值文件，先核对仍被引用的内容。引用所有者包括事件、消息、执行结果、工具输入/输出、文件版本、记忆和定时模板。对象缺失或校验失败则中断清理并报错。

删除任务不调用用户项目路径的文件删除；不能删除用户文件夹、浏览器目录或项目源码。目录链接和对象链接会被拒绝。此处是受管理对象目录的保护，不等于 P04 的通用工具沙箱，也不防御另一个恶意本机进程同时换文件的所有竞态。

暂时没有用户界面的批量清理、保留期限或磁盘限额管理。诊断镜像与迁移备份保留在原目录，P12 再实现统一保留和清理界面。

## 9. 凭据和脱敏

系统凭据接口使用 Windows Credential Manager、macOS Keychain、Linux Secret Service。当前只在 Windows 用本次创建的临时假密钥实测；不读取其他软件凭据。Mac/Linux 的功能开关已配置，实机和系统解锁状态尚未验证。

Secret 类型不支持序列化，调试输出固定隐藏内容，释放时清零其主要字符串内存；当前接受 1—4096 字节、不含控制字符的模型凭据。系统存储不可用时返回错误，不退回普通配置文件。读取到的密钥须先注册到保存层脱敏器，再使用于请求和错误处理。

已实现注册密钥的精确替换，以及认证头、API key、密码、cookie 等字段的隐藏；测试扫描数据库、附属日志、对象、备份和导出，检查假密钥没有以明文出现。无法从任意自然语言中推断全部未知秘密；P02 必须在请求入口注册凭据，不能只依赖日志关键词猜测。

## 10. 队列和错误分类

| 位置 | 上限 / 行为 |
|---|---|
| 标准输入单条命令 | 64 KiB |
| 引擎输入队列、输出队列 | 各 32 条 |
| 保存线程队列 | 32 个操作 |
| 宿主未完成请求 | 最多 64 个，默认 10 秒超时，不自动重发 |
| SQLite 缓存目标 | 4 MiB；这是页缓存目标，不是整个进程内存硬上限 |
| 事件分页 | 1—256 条 |
| 文字读取 | 1—64 KiB，必要时多读一个完整 UTF-8 字符 |

保存线程独占 SQLite 连接。等待磁盘的代码不在处理异步工作的线程上执行；调用方通过等待形成限流。磁盘异常或拥塞仍可推迟“记录已完成”的回执，不能把有界队列描述成停止时延的绝对保证。

错误类别包括 invalid_request、not_found、conflict、busy、storage、credential_unavailable、unsupported_version、internal。错误显示不得包含原始认证值；未知命令和畸形 JSON 使用固定错误说明，不回显输入。更完整的用户友好错误文案由 P02/P06 继续完善。
