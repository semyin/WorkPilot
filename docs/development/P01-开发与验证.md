# P01 开发与验证

更新日期：2026-10-01。前置环境沿用 [P00 开发与验证](P00-开发与验证.md)。当前实际平台是 Windows。

## 普通开发

从项目根目录执行：

~~~powershell
npm ci
npm run contracts:generate
npm run build
npm run check
npm run test:ui
npm run test:desktop
~~~

只修改普通代码不必反复生成类型；修改 contracts 中的字段后需要生成。检查会发现生成文件是否过期。构建只生成本机预览程序，仍不是安装包。

## 独立数据检查

~~~powershell
npm run test:storage
npm run test:credentials
npm run data:inspect -- "D:\实际绝对路径\development" events 0
npm run data:inspect -- "D:\实际绝对路径\development" export
~~~

最后两条路径是用法示意，不能原样执行。填入包含 workpilot.sqlite3 的通道目录，不是它的父目录。events 返回最多 256 条及 next_after；继续读取时替换游标。还可在游标后加 task_id 只看一个任务。

正式预览默认沿用 development 目录；自动测试使用独立临时 test 目录。不要让两个引擎共享同一目录。原 P00 的打包预览保留不动，新 P01 预览在自己的交付目录中。

test:credentials 仅在 Windows 运行可见的系统存储测试：使用唯一测试命名空间写入假密钥，读取核对后删除。普通 engine:test 跳过这个会接触系统凭据库的检查；本阶段已经单独实际执行。

workpilot-data 检查工具也可以编译为独立程序：

~~~powershell
node scripts/cargo.mjs build -p workpilot-storage --bin workpilot-data --release --locked
~~~

工具只读，不迁移、不恢复、不改状态。当前 export 输出事件诊断 JSONL，不包含正文对象文件，也不是 P12 完整迁移包。

## 故障与容量检查

- Rust 保存测试自动启动一个测试子进程，在状态/事件写入之间直接退出，父进程验证回滚和待核对标记。
- 迁移失败样本修改数据后故意触发 SQL 错误，验证原记录、版本和独立备份。
- 大输出样本边生成边保存 32 MiB 文字，避免测试程序自己先分配整个输入。
- 事件容量样本写入 100,003 条事件，每批 100 条，按 256 条分页读取并导出到输出丢弃器。
- 保存线程故意停顿 350 毫秒时，在单线程异步运行环境测量定时工作仍能前进。

可在已运行 engine:test 后，使用 [采样脚本](../../scripts/storage-metrics.ps1) 指定本次生成的 workpilot_storage 测试程序，重测工作集。测试程序位于 target/debug/deps，具体文件名以构建输出为准。采样记录放在 .test-results/storage-metrics。

工作集是系统当时统计的进程内存占用，不等于净物理内存增量。保存层样本不包含桌面和网页组件；完整程序占用由桌面测试单独采样。

## 桌面体验步骤

1. 打开 P01 预览，点击“开始验证”，等待结束或点击停止。
2. 左侧出现“已保存任务”。点击后在右侧查看分页历史；展开一条记录可核对来源、顺序和状态。
3. 点击“彻底退出”，重新打开。之前的任务和过程仍可查看。
4. 关闭窗口只隐藏到托盘，行为与 P00 相同。

本阶段没有模型对话、真正执行工具或“继续任务”按钮，后续分别在 P02—P04 接入。自动测试已经覆盖异常退出，用户不必为了体验手工强制结束进程。

用户本轮要求集中确认：上述体验可以之后一起做，不把每一步变成新的确认弹窗。通知方式 Q44 仍保留到 P06，不因此阻断本阶段。
