## P01 验收逐项对应

| 计划验收 | 实际证明 |
|---|---|
| 状态与事件间崩溃，不留下假完成 | 测试子进程退出码 86，事务未提交；重新打开后执行为 interrupted，工具为 needs_review，没有 completed 结束事件 |
| 同编号去重、不同编号不误吞 | 创建、重开重发、同编号不同正文冲突；额外验证重复停止不能停止之后的新任务 |
| 中间序号重连不漏不重 | 任务内多页读取、删除造成的全局空号、真实引擎中断后补读，以及桌面历史第 1/129 条分页 |
| 大输出和大量事件有界 | 32 MiB 生成式输入；100,003 条事件最多每页 256 条；保存队列 32 个操作、SQLite 页缓存目标 4 MiB；实际工作集采样 |
| 删除任务不删项目源码 | 临时用户项目文件逐字节保留；无引用对象清理；仍被记忆引用的对象保留 |
| 假凭据不进入普通文件 | 注册密钥、认证头和 API key 样本，扫描数据库、附属文件、对象、备份与导出；另测系统凭据库清理 |
| 迁移失败不覆盖唯一副本 | 迁移修改数据后故意报错，原数据与版本保持；独立备份可复制到新目录并读取 |

## 资源和响应样本

测试机沿用 P00 的 Windows 11 x64。数值是当前样本，不作为全平台或最终 V1 的保证。

| 保存层样本 | 实测 |
|---|---|
| 100,003 条事件，批量写入、分页读取、流式导出 | 约 12.4 秒，测试进程采样峰值工作集 12.28 MiB，主数据库约 30.5 MiB |
| 32 MiB 文字流式写入和中文分页 | 测试进程采样峰值工作集 6.94 MiB |
| 保存线程故意阻塞 350 毫秒 | 同一个单线程异步运行器上的 15 毫秒定时等待约 23 毫秒返回，没有等待保存线程停顿结束 |
| 单页和缓存 | 最多 256 个事件；SQLite 页缓存目标 4 MiB，队列容量 32 |

以上包含 Rust debug 测试程序的自身开销，不是桌面总占用，也不是最大内存的硬保证。采样文件保存被测程序校验值；后续界面标签修正不改变这些保存算法。

桌面报告另含 20 次停止的反馈/结束时间、1 万条事件下界面最多 200 行，以及引擎、宿主、WebView2 各进程工作集。网页组件的共享页可能重复统计；不把 Rust 引擎的低占用宣传成整软件占用。启动观察值包含自动测试连接，不等于冷启动 p95。

## 测试中发现并修正的问题

1. Windows 在只读方式打开的备份句柄上确认写盘返回“拒绝访问”。改为可写句柄再确认，重新运行保存和凭据检查。
2. 协议切换后，停止必须先查请求去重，再取消执行。增加重复停止不会影响新任务的真实进程回归测试。
3. 大量已保存任务使侧栏撑高窗口。限制网格行高度、侧栏滚动，桌面测试增加窗口布局断言。
4. 第一次新增桌面测试用精确文字匹配带图标的“开始验证”按钮，定位不到；修正脚本定位，保留 [第一次失败报告](../../artifacts/workpilot-p01-2026-10-01/evidence/desktop-first-failure.json)。
5. 复核截图发现，启动补读旧事件时会暂时显示旧的“进行中”。增加“正在读取已保存记录”状态，补读完成前禁用启动/停止，再展示最终状态；增加恢复完成断言。保留 [修正前报告](../../artifacts/workpilot-p01-2026-10-01/evidence/desktop-before-replay-label-fix.json) 和截图，避免只保留看似成功的旧结果。
