# P02 模型配置与适配

更新：2026-10-02。本文描述已实现的接口和边界，不代表某家真实模型服务已经通过验收。

## 1. 桌面使用入口

打开 Windows 预览，点击左下方“模型服务”。

1. 添加服务，填写名称、接口类型、服务地址。
2. 填写该服务提供的密钥。可先不填模型，保存后点击“读取模型列表”，也可直接手填模型名称。
3. 保存配置后，分别测试文字、工具请求、图片输入。
4. 右侧显示实际回复、公开推理内容、完整工具参数、结束状态、用量和配置快照。
5. 可设置全局默认，或导入、导出不含密钥的配置。

一次测试会调用真实配置的服务，可能产生费用。工具测试只读取模型提出的调用，不执行电脑操作；图片测试发送内置的 1×1 PNG，不读取用户文件。测试要求留空时使用固定提示词。

没有提供真实服务配置时，程序不会自动寻找其他软件中的账号。密钥在本机设置页输入，不需要发到聊天里。关闭设置页或隐藏窗口不停止请求；“停止调用”取消当前请求；彻底退出结束引擎，重开仅恢复记录。

## 2. 代码分工

| 模块 | 责任 |
|---|---|
| crates/contracts/src/provider.rs | 三协议共用的配置、调用、结果、能力、诊断类型 |
| crates/providers | HTTP 请求、分片解析、工具参数组装、续接字段、取消、诊断 |
| crates/storage/src/providers.rs | 配置版本、默认继承、调用快照、事件、结果和恢复 |
| crates/engine/src/models.rs | 命令路由、系统凭据读取、并发控制、流式事件保存 |
| apps/desktop/src/ModelSettings.tsx | 中英文设置、导入导出、连接测试和结果查看 |
| services/provider-fixtures | 只监听本机的协议模拟服务 |

HTTP 使用锁定版本 reqwest 0.13.5，明确设置 retry::never、关闭重定向、保留证书校验。不使用会自行重试的模型 SDK。ModelBackend 是后端替换边界，可后续加入独立本地模型后端；当前实现只有 HTTP 后端。

## 3. 配置及地址规则

一个配置绑定一个服务和模型：id、名称、协议、地址、模型、认证方式、参数、能力、可选价格、配置版本。可建立多个配置使用同一服务的不同模型。

| 输入地址示例 | Responses 的最终地址 |
|---|---|
| https://example.com | https://example.com/v1/responses |
| https://example.com/v1/ | https://example.com/v1/responses |
| https://example.com/proxy/v1 | https://example.com/proxy/v1/responses |
| https://example.com/v1/responses | 保持不变 |
| https://example.com/api | https://example.com/api/responses |

已有自定义路径时不猜版本。接口后缀不匹配、重复 /v1、userinfo、查询参数、片段标识会被拒绝。远程地址要求 HTTPS；本机 localhost/回环地址允许 HTTP。保存后的实际请求地址在界面展示。提供方枚举模型使用相同前缀下的 /models；只取首个返回页，最多 1000 项，更多页会明确提示。模型列表不能证明访问权限或模型能力。

认证可选协议默认、Bearer、x-api-key、无密钥。Messages 的默认认证使用 x-api-key，另发送可配置的 anthropic-version；其他两种默认 Bearer。输出长度、温度、推理强度、超时和价格均可配置；不支持的组合直接报错，不偷偷删除参数重发。

## 4. 密钥与配置迁移

- 请求可短暂携带密钥；SecretInput 的 Debug 隐藏内容，释放时清零；引擎读取管道的原始行也使用清零缓冲。前端保存成功后清空输入框。
- 密钥由系统凭据库保存，使用本应用数据目录派生的命名空间及随机引用；不允许界面指定任意系统凭据引用。
- SQLite 只保存引用；界面配置列表、调用快照、配置导出均不返回引用或密钥。底层开发数据库仍包含应用自有的引用。
- 当前调用使用的密钥会注册到保存层脱敏器。流式文字和公开推理另做跨片段遮盖；HTTP/流式错误先遮盖后截断。
- 配置导出格式 workpilot.profiles，版本 1；导入生成新 ID、版本归 1、不覆盖旧配置、不导入凭据、不导入“已经测试”的观察结果。已有全局默认保留。
- 更新配置先保存新凭据、提交数据库，再清理旧凭据。清理失败会明确提示；本阶段没有后台凭据清理重试队列。
- 当前尚无桌面删除配置按钮。后端删除接口会拒绝正在使用或仍有任务/项目/助手/全局绑定的配置，必须明确解除绑定后再删除，不通过删除悄悄改用上级模型。

本阶段不是完整的数据备份与跨机恢复工具；系统凭据迁移仍需要用户重新输入。

## 5. 模型选择、版本与能力

选择顺序：显式调用选择 → 助手覆盖 → 任务覆盖 → 项目默认 → 全局默认。缺失的是“具体选中的配置”时直接失败，不转用其他配置。不同层级的写入与解析已在保存层实现并测试；当前设置页提供全局默认，项目/任务/助手的正式选择器随 P03/P05/P06 接入。

配置修改使用乐观版本检查；同时修改旧版本会被拒绝。每次请求开始时保存实际配置快照及 revision，即使请求中途修改服务，已有调用仍使用原快照。启动命令通过 request_id 去重，重复命令不额外调用模型。

文字、流式、工具、图片输入、用量分别记录：未知、用户声明、实际调用观察。自动观察只在调用完整成功后写入，绑定同一配置版本。配置改变不会沿用旧观察。用户声明优先；图片测试成功只证明接口接受这张图片，不证明视觉理解质量。没有返回工具请求不能标为工具支持。

正常调用时图片/工具未知或声明不支持会被拒绝；点击对应的明确能力测试允许一次探测，不静默丢掉输入。用量被动记录实际返回；Chat Completions 只有在声明/已观察支持用量时发送 stream_options.include_usage。

## 6. 协议差异与续接

| 协议 | 流式处理 | 续接保存 |
|---|---|---|
| Chat Completions | choice 0、tool index、content/reasoning_content、完整结束原因和 [DONE] | assistant 消息、tool_call_id、原始参数、reasoning_content、工具 extra_content |
| Responses | 创建事件、文本/工具参数增量、输出项、最终 completed | 完整 output 项、call_id、加密推理项；store=false；工具结果用 function_call_output |
| Messages | message_start、内容块及增量、块结束、message_delta/message_stop | 完整内容块、thinking/signature、tool_use_id、tool_result |

工具参数只在完整结束后交付：名称必须已声明，编号唯一，参数必须是完整 JSON 对象，续接结果与上一轮编号一一对应。不会在参数未收齐时执行。正式的 JSON Schema 参数校验、权限、执行与审批属于 P04；P02 不执行任何工具。

未知的生命周期事件不视为成功；缺少终止标志、长度截断、格式错误、未闭合内容块等形成错误。保留服务公开返回的推理/续接数据，不承诺获取服务未公开的内部思考。Messages 的服务端 fallback 内容会被拒绝；客户端从不请求自动切换模型。未识别的服务私有字段不能笼统保证兼容。

## 7. 错误、用量和容量

401、403、429、5xx、网络失败、整体/空闲超时、流式错误、断流和不完整结束都有统一中英文说明，并保存脱敏详情。失败不重试、不切换。取消后先提交结束状态，保存层拒绝迟到文字和成功结果；请求启动前、读取响应时和发送更新时均检查取消标记。

用量只采用服务实际返回值，缺失是 null/“未知”，不是 0。价格由用户填写，按输入/输出词元估算，缺少任何一项不估算。缓存、阶梯价、折扣、税费不单独核算，结果不是服务账单。保留原始 usage 供后续核对。

工程默认值及限制：

- 最多 128 个配置；最多 4 个同时进行的连接操作（包含模型列表）。
- 默认总超时 90 秒、空闲超时 30 秒；列表读取 15 秒；宿主命令等待上限 20 秒，模型执行本身异步进行。
- SSE 每帧 512 KiB；一次网络响应累计 16 MiB；文字 4 MiB；工具参数 256 KiB；保存后的完整 JSON 8 MiB。
- 命令最大 1 MiB；事件仍是引用内容的 64 KiB；查询每次读取内容不超过 64 KiB。
- 设置页显示最近 32 次调用，选中项按事件分页读取；长输出允许滚动。更完整检索在后续工作台阶段。

## 8. 数据升级与开发命令

SQLite schema 从 1 升到 2，增加 settings、profile_versions、model_calls、capability_observations；升级前独立备份，旧字段以默认值读取。协议名保持 workpilot.v1，新客户端与新引擎成对分发；旧 P01 程序不能打开 schema 2，应使用原阶段备份。

~~~powershell
npm run check
npm run test:providers
npm run test:storage
npm run build
npm run test:models-desktop
npm run test:desktop
npm run test:ui
~~~

桌面测试只使用自己创建的临时数据目录、WebView2 和假密钥，并清理这些假密钥。不连接用户日常浏览器或真实模型账户。

实际测试结果和剩余外部条件见 [P02 验证记录](P02-验证记录.md) 与 [兼容清单](P02-服务兼容清单.md)。

## 9. 接续 P03

复用 ModelBackend、ModelInput/ModelOutput 和持久化事件，不在 UI 增加第二套模型客户端。把 P02 的连接诊断与正式任务执行循环分开；P03 实现上下文、队列、引导和人工继续，P04 接工具执行，P05 接多助手。

三种真实协议仍需要用户在设置页明确配置服务并完成真实调用。模拟样本不能代替这项验收。
