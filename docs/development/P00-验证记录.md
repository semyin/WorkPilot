## 已发现和处理的问题

1. Windows 1 毫秒定时器使用跳过模式时，长日志输出超过预期耗时。改为对固定验证事件补发，并保持停止命令优先；1 万条事件已能完成。
2. Windows 同步创建子网页可能卡住。改为异步创建；独立诊断已读取到实际外部网页内容。
3. example.com 当前页面不再有旧测试假定的标题元素。页面实际加载成功，调整验证为页面标题与真实正文。
4. 浏览器标签页未提供地址时，旧版直接构造 URL 导致用户收到 Invalid URL。0.1.1 增加地址检查、当前标签页展示和中文提示；未通过检查不连接本机程序。
5. Playwright 下载的 Chrome for Testing 启动返回 spawn UNKNOWN。未修改系统防护或伪造自动验证通过，日常浏览器按用户授权的真实路径补测。
6. 补充的“打开子网页后关窗再恢复”测试发现，窗口已经变为多网页容器，原有单网页窗口查找不能恢复它。统一改为查找所属窗口，复测通过。
7. 网页创建改为异步后，切换预览页需串行处理创建与关闭，避免遗留页面。已加入顺序处理，并通过快速切换验证。

保留了 [第一次长日志失败](../../artifacts/workpilot-p00-2026-10-01/evidence/desktop-report.first-failure.json)、[同步网页创建失败](../../artifacts/workpilot-p00-2026-10-01/evidence/desktop-report.second-failure.json)、[网页定位断言失败](../../artifacts/workpilot-p00-2026-10-01/evidence/desktop-report.third-failure.json)、[多网页窗口恢复失败](../../artifacts/workpilot-p00-2026-10-01/evidence/desktop-report.fourth-failure.json)，以及 [测试浏览器启动失败](../../artifacts/workpilot-p00-2026-10-01/evidence/test-browser-launch-failure.json)。最终桌面报告为 passed。

## 当前性能样本

环境：当前 Windows 11 x64，约 31.3 GiB 内存、16 个逻辑处理器。版本见锁文件和构建记录。数据规模：单个合成验证任务、20 次停止循环，加隐藏恢复场景，随后连续 1 万条事件；界面最多 200 行。

| 测量 | 最终样本 | 口径 |
|---|---:|---|
| 停止按钮状态反馈 p95 | 4.6 ms | 网页点击事件至显示“正在停止”的 DOM 更新；不是物理屏幕绘制时延 |
| 显示引擎已中断 p95 | 103.1 ms | 点击事件至界面显示真实中断状态 |
| 采样事件展示 p95 | 91 ms | 最近一条可见事件时间至 DOM 更新，不等于每个被批量合并事件的逐条延迟 |
| Rust 引擎工作集 | 6.89 MiB | 本次采样时该进程的工作集 |
| 桌面宿主工作集 | 27.97 MiB | 不含 WebView2 和引擎 |
| WebView2 各进程工作集之和 | 656.15 MiB | 含自动调试与截图环境；共享页可能重复计算，不是净物理内存增量 |
| 含辅助进程的工作集之和 | 698.47 MiB | 如实保留完整进程表，不用引擎占用代替整软件占用 |
| 启动至自动测试可操作 | 2,658 ms | 单次、含测试连接等待，不作为冷启动 p95 达标结论 |

三层自有进程的清理检查要求 2 秒内完成，实际测试通过。原型目标只覆盖当前样本，不代表未来多模型、多助手和第三方工具的性能承诺。

启动样本包含调试连接与自动测试等待，不能直接当作产品冷启动指标。完整并发、10 万条历史和长时间运行留给后续阶段。
