# P00 开发与验证

版本：0.1.0-alpha.0。当前是工程原型，不包含真实模型调用、完整任务执行或正式安装器。

## 开发环境

本机已验证 Windows 11 x64、Node.js 22.23.2、npm 10.9.8、Rust 1.99.0、Visual Studio Build Tools 2022 17.14.41、Windows SDK 10.0.26100.0。Rust 工具链由 rust-toolchain.toml 固定，依赖由 Cargo.lock 和 package-lock.json 固定。

Windows 需要微软 C++ 构建工具及 WebView2；macOS 需要 Xcode 命令行工具；Linux 需要 WebKitGTK 等依赖。具体步骤见 [Tauri 官方前置条件](https://v2.tauri.app/start/prerequisites/)。macOS/Linux 尚未在实机执行这些命令。

## 从项目根目录运行

~~~powershell
npm ci
npm run dev
~~~

开发命令先构建独立引擎，再启动界面和桌面宿主。结束开发时用托盘“彻底退出”，再结束开发命令。关闭窗口只隐藏到托盘。

生成可直接运行的 Windows 开发版本：

~~~powershell
npm run build
~~~

结果为 target/release/workpilot-desktop.exe 和同目录的 workpilot-engine.exe。两者必须一起保留。P00 不生成正式安装包，不要求用户安装 Rust 才能运行这两份已编译程序；电脑仍需具备 WebView2。

构建脚本支持 CARGO_TARGET_DIR，用于在单独的空目录检查重新构建；没有这个变量时使用项目 target 目录。

## 检查命令

| 命令 | 检查范围 |
|---|---|
| npm run format:check | 新增前端、脚本、配置的格式 |
| npm run ui:typecheck | 界面的类型检查 |
| npm run test:fixtures | 三种模型样本流、故障样本及扩展地址校验 |
| npm run rust:fmt | Rust 格式 |
| npm run engine:test | 真实引擎进程、消息、退出、目录边界和桥接协议 |
| npm run rust:check | Rust 静态检查，警告视为失败 |
| npm run ui:build | 生成界面资源 |
| npm run test:browser | 已安装 Chrome、Edge 的独立测试目录；不访问日常资料 |
| npm run test:ui | Chromium 中的界面预览，不冒充桌面实测 |
| node scripts/desktop-smoke.mjs | Windows 实际桌面、独立引擎、长日志、退出和性能样本 |

npm run check 汇总主要检查。第一次运行前先执行 npm run build，确保桌面构建需要的引擎资源已经准备好。没有安装 Chrome/Edge 的环境不能把对应浏览器检查记为通过。

桌面自动测试只对自己启动的 WebView2 开放本机调试端口，使用单独的临时数据目录；正常启动不会由 WorkPilot 添加调试端口。网页呈现检查访问 example.com，需要网络，页面内容不能假定永远保持同一布局。

## 源码位置

~~~text
apps/desktop/             React 界面与 Tauri 宿主
crates/contracts/         P00 命令和事件样本
crates/engine/            独立验证引擎
crates/platform/          数据目录、进程组、Windows Job Object
crates/browser-bridge/    Chrome/Edge 本机消息桥接原型
extensions/browser/      用户安装的本地测试扩展
services/fixtures/       模型流和浏览器的本机固定样本
tests/                    自动检查
scripts/                  构建与验证入口
~~~

contracts 目前仅为 P00 验证协议，正式任务与持久化事件在 P01 实现。不要把 JSONL 验证日志当作完整任务数据库。

## 数据隔离

- 开发、测试、发行分别使用 development、test、release 子目录。
- 预发行版本默认写入 development；正常稳定版使用 release。
- 测试必须显式提供临时数据根目录，否则拒绝启动 test 模式。
- WORKPILOT_DATA_DIR 可指定绝对的数据根目录；WORKPILOT_CHANNEL 可指定当前通道。
- 引擎只向自己的数据目录写验证日志，不修改用户项目文件。

## 浏览器原型

参见 [扩展验证步骤](../../extensions/browser/README.md)。独立浏览器测试通过不等于日常浏览器连接已通过；Chrome 和 Edge 的用户授权、消息桥接、网页动作与断开需要分别留证据。

Chrome for Testing 的自动扩展验证入口为 scripts/browser-extension-smoke.mjs，需要预先准备本机桥接、注册 Chrome 主机，并安装 Playwright 的浏览器。当前本机该浏览器启动曾返回 spawn UNKNOWN，不能将这条自动验证记为通过。

## 适用范围

Windows Job Object 已用于拥有的进程树清理，但它不是文件访问沙箱。已有文件路径校验覆盖父目录逃逸及 Windows 目录联接；任意终端、第三方脚本的强隔离仍须 P04 实现。

右侧多网页组件依赖 Tauri 2 的 unstable 功能，集中封装在桌面宿主中。Windows 创建子网页必须使用异步命令；已按 [Tauri 的限制说明](https://docs.rs/tauri/latest/tauri/window/struct.Window.html#method.add_child) 调整。
