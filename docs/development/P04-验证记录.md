## 2. 工具与审批场景

完整引擎使用本机模拟模型，工具操作是真实临时目录/文件/命令。这部分故意使用稳定样本，不冒充真实模型。

1. 新文件实际写入前暂停；错误审批指纹、跨任务借用、重复决定被拒绝；正确批准后读写/搜索/目录/成果全过程完成，保存准确版本。
2. 等待期间人为写入同名目标，旧审批不能覆盖；随后拒绝仍明确暂停。
3. 批准后撤销目录授权，旧票据失效，继续任务也未写文件。
4. 独立审批返回拒绝、不确定、无效格式或 HTTP 429，全部转人工，目标不存在；人工拒绝后停止。
5. 独立审批批准，只执行对应动作；审查输入、输出与用量有引用。
6. 审查中断后手动继续不会自动重新审查；等待人工，未产生文件。
7. 完全访问不弹人工审批；聊天和规划仍不执行文件修改。
8. 越界路径、不完整写入参数、伪造权限工具、文件中的“忽略权限”文字均不能获取权限。
9. 真实 Windows 命令在审批模式启动 AppContainer，退出码 7 保留为工具失败；完整输出落盘，read_command_output 实际分页回读通过。
10. 在真实写入前与写入后未保存完成的边界终止引擎，重新启动不自动执行；手动继续使用版本核对，只保留一次实际写入和一份修改记录。

单元测试另覆盖：审批各字段绑定、一次消费、配置命令完成事件与去重；schema 3→4、旧版本回滚备份；长单行日志 150 KB 存储；日志与版本引用回收保护；目录身份、硬链接/目录联接、已打开写句柄冲突；丢弃异步调用后等待真实阻塞工作完成。

## 3. 本轮发现、修复与保留的失败

- 真实 Chat 工具流后续分片包含空 id。旧解析器拒绝，现跳过空占位；不同非空 id、最终缺失 id 仍失败。已补回归并重新跑三协议。
- 阿里云不接受旧 1×1 图片，换为校验有效的 64×64 PNG；实际回复识别为蓝色。
- 通用脱敏误处理 `api_key` 认证枚举，造成配置不能恢复。保留有限枚举并兼容旧标记，真实凭据仍被遮盖。
- 真实界面发现“文件已变更后拒绝”可能被当作普通工具校验失败而继续。将已拒绝判定前移，原生与引擎重测通过。
- 系统隔离测试校正等待点：等待真实三级进程已启动再取消；以实际连接结果及完全访问对照判定网络拒绝，不强依赖单一 Windows 错误码。
- 数据库故障测试由“故意执行坏版本 4”改为版本 5，避免新 schema 已是 4 而跳过故障。完整迁移/备份不变量重测通过。
- 最后人工查看截图时发现右侧还留有 P03 样本工具说明，已改为当前真实工具规则；审批主视图展示新建/替换和完整写入内容，底层参数放在可展开依据里。

## 4. 平台与产品范围

本轮 Windows 11 x64 本机测试。普通 AppContainer 能限制项目外私有文件与网络，但允许系统授予该身份的公共资源；完全访问没有文件/网络沙箱。插件共用的独立进程边界经过实际二进制测试，不等于 P09 的插件加载/协议/安装已完成。

当前文件工具限定 UTF-8，单文件读取 1 MiB、单次写入 64 KiB；命令项目清单 1024 文件/64 MiB，不支持链接。认证内容的受管理版本保存需后续加密方案；目前明确拒绝，不保存脱敏假版本。命令输出非 UTF-8 标为错误。完整回滚、办公二进制、多助手、浏览器、MCP、正式安装包、Mac/Linux 实机、4 小时稳定性与统一性能 p95 未覆盖。

原桌面脚本保留其本机性能样本，但本轮没有为 P04 建立跨设备性能结论。并行运行的开发测试可能影响这些数值，不能据此声称正式性能目标达标。
