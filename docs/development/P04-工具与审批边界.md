# P04 工具与审批边界

更新：2026-10-02。本文描述本次实际实现，Windows 11 x64 已测试；macOS/Linux 的进程隔离尚未实现，不计为通过。

## 1. 数据如何经过引擎

```text
用户选择目录、模式和权限
          ↓
模型提出工具名称和完整参数
          ↓
工具注册表 → 参数检查 → 目录句柄 / 文件版本检查
          ↓
规则判断 → 必要时独立模型审查 → 必要时人工审批
          ↓
再核对权限版本、参数、目标文件版本
          ↓
持久化动作记录 → 实际工具 → 保存结果与文件版本
          ↓
结果回到原会话；界面可展开完整记录
```

`crates/tools` 负责实际工具；`crates/policy` 负责规则与审批指纹；`crates/platform` 负责系统文件标识和进程；`crates/runtime/src/real_tools.rs` 把它们接入既有任务循环。引擎接收用户配置/审批命令，模型工具列表没有修改权限或批准自己的接口。

## 2. 首批工具与限制

| 工具 | 实际行为 | 当前限制 |
|---|---|---|
| list_directory | 列出目录项，指出链接与截断 | 单目录最多 256 项 |
| read_file | 读取普通 UTF-8 文件、返回版本哈希和下一页位置 | 单文件 1 MiB；每页最多 32 KiB |
| search_files | 在授权目录内按文字搜索 | 最多 256 文件、100 结果；报告跳过和截断 |
| write_file | 新建或替换文件，保存前后版本 | 本次写入最多 64 KiB；父目录必须已存在；覆盖必须携带读取时的哈希 |
| run_command | 指定完整程序路径及参数数组，工作目录为授权目录 | Windows .exe；100 ms—5 分钟；最多 32 个自有进程；输出每通道 4 MiB |
| read_command_output | 按页读取本会话命令的标准输出/错误输出 | 每页最多 32 KiB；不能跨任务借用步骤编号 |
| register_artifact | 将已有文件登记为成果并记录当前版本 | 当前支持普通 UTF-8 文件，不改变原文件 |

每项注册包含输入/输出结构、作用范围、风险、取消和重复执行说明。浏览器、办公二进制文件、MCP、Skill、原生鼠标键盘未在 P04 开放。

结果超过模型上下文预算时返回摘要和内容引用。桌面展开结果可继续展开日志引用，并按 64 KiB 分页查看；不会把 4 MiB 日志一次塞进界面。列表显示最近 64 条审批/文件修改；更早事件与内容仍通过完整事件分页保存。

## 3. 三档权限

| 模式 | 授权目录读取 | 普通文本写入 | 命令 |
|---|---|---|---|
| 请求审批（初始默认） | 直接执行 | 人工确认具体内容 | 人工确认；Windows AppContainer |
| 帮我批准 | 直接执行 | 规则检查后，调用独立审批步骤 | 仍转人工；Windows AppContainer |
| 完全访问 | 直接执行 | 参数和版本有效即可执行 | 用户系统账户权限；仍管理进程树、输出和停止 |

聊天、规划模式始终不开放修改。文件工具仍限定在选定目录；完全访问命令可能访问该账户允许的其他位置，界面明确显示。

有效权限顺序：任务覆盖 → 项目设置（存在时）→ 全局默认。审批模型：任务覆盖 → 全局默认 → 使用该任务模型进行一轮独立审查。这是预先选择规则，不是故障后的自动换模型。

独立审批收到原始用户目标和准确动作，不能调用工具。要求严格返回 `decision` 与 `reason`。拒绝、不确定、格式错误、服务失败、中断都停在人工处理，不执行原动作，不自动重试审批。脚本/可执行文件、注册表文件、.git、.ssh、.env 等规则识别的敏感写入直接转人工；该规则清单不是“能识别所有危险代码”的承诺。

## 4. 审批绑定与撤销

审批指纹包含规则版本、任务/步骤编号、完整参数、规范目录与目录身份、目标、目标内容哈希/身份/大小、工作模式、有效权限配置版本和执行范围。不是仅按工具名称批准。

- 再次点击同一请求编号返回原回执，不能重复保存或停止后续新任务。
- 审批决定与执行分别核对；已消费的审批不能再次使用。
- 修改文件、换目录、换权限、改参数或借用其他任务的审批都会使旧授权不能执行。
- 修改任务权限会停止该任务；修改全局权限停止当前任务并使旧审批失效。界面说明这一行为，之后手动继续。
- 拒绝优先于后续文件校验。即使文件在等待期间变化，拒绝仍明确暂停，不把拒绝变成可忽略的文件错误。
- 新运行沿用旧会话中未完成的动作；消费审批后、动作启动前退出，只能重新取得有效审批，不能依赖已消费票据。

## 5. 实际平台边界

| 入口 | 真正限制 | 实测证据 / 限制 |
|---|---|---|
| 文件工具 | cap-std 目录句柄、相对路径、文件身份和哈希、链接/硬链接/重解析点检查 | 越界、目录联接、硬链接、目录换绑、已有写入句柄冲突均测试 |
| 审批模式的 Windows 命令 | 每次独立 AppContainer，未授网络能力；只给选定目录增加该唯一身份的文件权限 | 实测能写项目，不能读取私有兄弟文件；本机监听服务拒绝访问，完全访问对照可连 |
| Windows 自有进程生命周期 | 挂起创建 → 加入 kill-on-close Job → 恢复；显式标准句柄继承；最多 32 子进程 | 取消三级进程树、超时、输出溢出、拥有者崩溃杀后代均实测 |
| 拟供插件复用的进程入口 | 与命令共用 ProcessSpec / AppContainer / Job；测试用独立二进制模拟不受信进程 | 已测文件/网络/环境/取消；没有宣称已验收 P09 插件安装、MCP 协议或第三方包 |
| 完全访问命令 | 系统账户现有权限，只限制生命周期和输出 | 不标成文件/网络隔离；不会自动带入模型密钥或宿主环境凭据 |
| macOS / Linux 命令 | 目前返回明确“不支持此平台执行边界” | 不退回不受限启动；后续 P14/P15 实现并实机测试 |

AppContainer 使用常规模式，**不是 LPAC，也不是完整虚拟机**。系统或用户明确授予 AppContainer 的公共资源仍可能可读；不能宣称“整个系统只看得到工作目录”。凭据不自动注入命令环境，工具只能拿到系统路径和位于项目中的临时目录。第三方程序需显式给出可执行路径，Node/Python 环境随包准备仍属 P12。

ACL（系统文件权限）修改使用跨进程互斥锁，避免两个命令互相覆盖权限。每次使用独立身份，先记录将修改的路径再授权；结束时只撤销该身份的权限，不覆盖用户后来改过的完整权限表。异常退出后按本应用日志清理。清理失败保留日志并报告，启动恢复失败不继续假称隔离有效。

## 6. 文件历史与不确定结果

受管理写入先保存真实前像和期望后像，再取得独占写句柄、重新核对版本、写入并同步。写入成功后保存实际文件身份和哈希。中途退出不保证磁盘文件原子替换；恢复时用实际文件哈希核对期望后像，匹配才确认完成，不匹配要求核对，不盲目重写。

为避免将脱敏文本误当成可恢复原件，包含已登记密钥或被认证字段规则判定为受保护的内容暂不执行受管理覆盖/成果登记，显示需要加密版本存储。普通源码也可能触发此保守检查；这项限制保留给 P07 的加密版本设计，不能悄悄丢行后写回。

命令在审批时绑定程序内容和项目清单，执行前再比较；完成后记录清单。当前清单限制为 1024 文件/64 MiB、目录 256 项，不允许链接。清单是前后哈希核对，**不能代替可还原所有命令修改的完整项目快照**；P07 仍需补完整快照、差异和回滚。

非零退出、超时、取消、输出溢出和清理失败都是工具错误。当前输出契约为 UTF-8；其他编码会被标为错误并提供可见的有损诊断文字，不冒充完整成功。命令效果不确定时沿用 P03 的人工核对入口。停止信号发出后，等待自有阻塞工作实际结束，避免界面已停而文件继续被写。

## 7. 持久化与兼容

数据库升级到 schema 4，保留 P01—P03 数据并先备份。新增工具设置、审批内容引用、文件版本和工具日志所有权表。审批、独立审查输入/输出/用量、文件前后内容和完整命令结果均可追溯；引用对象不会被误回收。客户端与引擎必须成套更新，旧预览不应打开新版数据库。
