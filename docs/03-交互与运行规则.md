# WorkPilot 交互与运行规则

更新日期：2026-10-05

本文把用户选择转化为可实现、可验收的行为。未特别标明的数值默认值是工程建议，不是用户承诺。

本文维护有效交互规则；当前候选为 `0.1.0-alpha.13.4`。实现状态与待验收条件统一见 [文档索引](README.md) 和 [P13 计划](plans/13-Windows首版验收.md)，不按旧交付版本推断当前进度。

## 1. 工作模式与权限模式是两个维度

| 工作模式 | 允许的行为 |
|---|---|
| 聊天 | 对话、理解附件和已授权的只读资料；不主动启动修改、提交或外发任务 |
| 先规划再执行 | 允许必要的只读了解，产生计划；用户明确启动执行后才进入实质操作 |
| 直接执行 | 在用户任务目标和有效权限内直接组织工具执行 |

改变工作模式不自动提升权限。对话文字中声称“已批准”不等于平台收到有效审批。

| 权限模式 | 平台行为 |
|---|---|
| 请求审批（默认） | 对需要授权的动作展示对象、范围和影响；已授予范围内的普通读取不反复弹同一问题 |
| 帮我批准 | 先匹配明确规则，再由审批助手审查；高影响、不明确、审查出错时转用户处理 |
| 完全访问 | 在当前操作系统账户和外部服务已有权限内放开应用层审批限制，仍保留参数检查、执行记录与停止能力 |

完全访问不能绕过操作系统或第三方账户认证。权限建议支持全局默认、项目覆盖、单次任务覆盖；有效范围在执行界面可见。

审批绑定实际动作、参数、目标和规则版本。参数改变必须重新判断。子助手、脚本和插件不能从说明文字中得到更高权限；工具结果也不能替用户修改权限。

## 2. 任务状态

| 状态 | 意义 |
|---|---|
| 排队 queued | 等待运行名额或用户消息的处理时机 |
| 运行 running | 正在请求模型或执行工具 |
| 等待输入 awaiting_input | 等待用户补充资料 |
| 等待审批 awaiting_approval | 已形成具体操作，等待有效批准 |
| 停止中 stopping | 已发出取消，仍在收集工具结束情况 |
| 已中断 interrupted | 用户停止、应用退出或崩溃造成中断，允许人工继续 |
| 失败 failed | 当前执行因模型或不可处理错误结束，保留原因与已有成果 |
| 已完成 completed | 执行结束并记录结果和能够完成的核验 |

界面断开不是任务状态改变。应用重新打开先还原记录，再决定显示运行中任务或已中断任务，不能一律重跑。

## 3. 新消息、排队和引导

1. 当前任务运行时，新消息默认进入队列，明确显示“尚未开始处理”。
2. 每条排队消息可点击“引导”，将其提升为当前执行的调整要求。
3. 引擎在可安全切换的步骤边界交付引导内容，取消尚未开始且已不适用的动作；不把已完成操作伪装成未发生。
4. 对正在请求模型的情况，适配器可取消当前请求，在保存已接收内容后按新要求继续；这是用户引导，不是故障自动重试。
5. 对不可立即中止的外部操作，显示正在等待安全结束，不能先向用户声称“已经停止”。
6. 队列内容、顺序和处理状态需要持久化；崩溃后不能重复执行同一条已处理消息。

## 4. 错误处理

| 错误位置 | 行为 |
|---|---|
| 主助手模型请求 | 提示真实原因并结束本次执行，不自动重试或更换模型 |
| 子助手模型请求 | 停止该助手，其他独立分支继续；依赖该助手的步骤等待主任务处理 |
| 主任务决定接替 | 新建明确可见的助手/尝试，引用原目标、进度与错误；原失败记录不覆盖 |
| 审批助手请求失败 | 本次审查停止、显示错误，原工具不执行，转人工审批 |
| 工具返回可处理错误 | 保存真实错误；主助手可以根据错误选择不同办法，不能伪造工具成功 |
| 工具执行结果不确定 | 先查询或核对结果，再允许用户继续；不能盲目重放有外部影响的操作 |
| 界面与引擎通信中断 | 用事件序号重连和补读，不重新提交已经接受的命令 |

所有协议适配器、HTTP 客户端或引入的 SDK 均需检查并禁用模型请求自动重试。模型故障的测试必须核对请求次数。

主任务可以决定是否接替子助手，但需要受调度上限约束；接替同样失败时不能无上限创建新助手。上限在 P05 验证后确定并可配置。

## 5. 关闭、退出、睡眠与恢复

| 用户动作/系统事件 | 任务行为 |
|---|---|
| 点击窗口关闭 | 隐藏到托盘，运行任务与定时任务继续 |
| 从托盘重新打开窗口 | 显示现有状态，不重复启动正在运行的任务 |
| 点击停止某个任务 | 停止该任务及其子助手、所拥有的工具工作；不影响其他独立任务 |
| 托盘选择彻底退出 | 停止接收新工作，取消运行、保存检查点、结束引擎及受管理工具进程 |
| 强制结束、崩溃、关机 | 不保证最后一条未落盘事件；重启后核对已记录状态并标明不确定操作 |
| 重新启动应用 | 恢复列表，已中断任务由用户点击继续 |
| 睡眠与唤醒 | 软件不能在系统睡眠时保证执行；唤醒后核对运行及错过的调度，不重复执行 |

退出时不关闭用户原有浏览器，不删除已生成文件。若某个远端操作已提交，断开连接不等于远端已撤销，需记录这一状态。

## 6. 定时任务

- 由本机应用中的调度器运行，支持查看下一次执行和历史结果。
- 关闭窗口仍执行；彻底退出、关机或睡眠期间无法保证到点执行。
- 创建计划时记录项目、目标、模型、工作模式、权限、时区与是否启用。
- 定时启动不能绕过三档权限；需要审批时等待用户，不能因为无人看窗口而自动提升权限。
- 工程建议：同一计划默认不重叠运行，错过的触发只记录、不自动补跑；提供手动“立即运行”。
- 应保存触发发生的唯一标识，处理时钟回拨、夏令时和应用重启导致的重复触发。
- 不自动恢复之前因故障中断的运行；计划未来一次新触发是独立运行，历史错误保留。

通知方式 Q44 已于 2026-10-04 确认：软件内提醒、Windows 系统通知及托盘提示。三种方式可分别关闭；系统通知被拒绝或环境不支持时，仍可在应用内处理。系统通知只显示通用提示，点击后定位对应任务，不会自动批准或继续执行。

## 7. 文件、版本与人工修改

工具修改前记录目标版本，成功后保存新版本与来源。查看差异时，文本提供内容对比，二进制文件先提供版本和可用预览，不宣称能自动解释所有二进制差异。

用户在外部软件修改文件后，旧版本上的 AI 写入必须检查冲突。恢复旧版本也是一次新修改，需要保护当前文件，不能把用户的新改动直接覆盖掉。

脚本、终端、浏览器下载及插件可能产生文件变化。应用应对所管理项目的工具执行做快照/变更跟踪。只靠文件监听无法保证每一次瞬间改写都被捕获；完整性边界必须经过 P07 验证。

P07 实际入口为任务上方“文件与终端”。保存、恢复、重命名、删除、命令和 Git 提交进入操作记录；手工工作区在请求审批/帮我批准下均需确认，完全访问直接执行。审批与当前文件和权限版本绑定，内容变化后旧确认失效。详情保留具体参数与完整结果。恢复是新版本，原历史不被抹掉。

受管理命令保存执行前后字节；单文件、总量及排除目录有明确限制。长命令运行时该项目其它写入排队，停止后释放。关闭文件工作区或主窗口不停止命令，彻底退出才停止；运行预览随文件工作区关闭而关闭。外部软件的瞬间变化不承诺全部保存，具体边界见 [P07 设计](development/P07-文件历史与开发工作区.md)。

## 8. 完整执行过程

必须可查看：用户指令与排队状态、主/子助手、工具名称和输入输出、权限决定、文件版本、成果、错误、时间、可获得的模型用量。

大输出保存为本地内容对象，界面分页或按需加载，不能为节省界面内存把历史永久丢弃。凭证、认证头等在记录前脱敏；诊断导出不包含密钥。

显示的是服务实际返回的公开内容与应用执行事件，不填造模型未返回的信息。不支持用量或价格的服务应显示“未知/未配置”，不能写成零费用。

## 9. 首次使用与日常路径

首次使用：打开应用 → 选择语言 → 配置模型服务 → 测试连接 → 建立项目 → 选择工作模式和权限 → 开始任务。

日常使用：选择项目 → 新建或继续任务 → 查看过程/审批/成果 → 发送排队消息或引导 → 在需要时停止、恢复或导出。

文件历史备份位于“文件与终端 → 修改历史”。用户选择历史、保存位置并设置口令；导入时先完整核验并展示相对路径与同名文件，再由用户确认添加历史。确认导入不覆盖项目文件，恢复具体版本继续遵守当前模式、权限与一次性审批。成功后清空口令输入；口令不存入本地设置或执行记录。这一入口仅处理所选历史；需要一起迁移项目、任务、附件、记忆、扩展和所选当前文件时，使用“设置 → 完整资料迁移”，见第 13 节。

“技能与插件 → 技能与插件迁移”可选择已安装扩展、已卸载但保留记录的扩展和未安装草稿。“包含所选扩展的历史版本”默认勾选，也可只备份当前版本；历史版本不再受最近 64 条操作记录的显示范围限制。独立入口的项目扩展映射到当前任务绑定的目标目录，全局范围保留；多个原项目的分别映射使用完整资料迁移入口。

扩展导入前查看依赖、入口/参数、权限、资源和保留版本，同名冲突阻止批次导入。确认后已安装扩展停用、已卸载项保持卸载、草稿保持待确认；重新填写凭据并按依赖顺序手动启用。草稿可另存修订后再确认安装，旧草稿保留。原启用状态和权限声明不自动放行执行；重复导入不重置用户之后选择的版本，不重新启用或复活卸载项。详见 [技能插件迁移](development/P12-技能插件迁移.md)。

图片生成需要可用的图片服务配置，不能因为文字模型已接通就假设已经可以生成图片。连接真实浏览器需要用户完成浏览器侧授权。

P12 安装版可先在设置的“Chrome / Edge 连接设置”中配置本机连接，再按页面说明在浏览器加载随包 Companion。界面展示另一安装位置占用时，不覆盖原记录。本机配置完成不等于标签页已授权；卸载只清理自己的本机登记。移除本机登记不强制断开正在运行的页面，停止任务或在扩展中断开才结束当前控制。

## 10. P08 浏览器工作区实际入口

选择绑定项目目录的执行任务，点击顶部“浏览器”。可以启动专用 Chrome/Edge，或生成连接码并在日常浏览器 Companion 扩展中明确连接当前页。连接后选择标签页，读取页面再操作；网页不能自己改变权限。页面变化后的旧目标会拒绝执行。

需要审批时，操作记录显示目标和具体参数；确认后手工操作直接完成，AI 发起的任务点击“确认完成后继续 AI 任务”接续。截图在本地显示；发送给模型前核验其图片能力。上传/下载填写项目内路径，下载可在文件历史恢复。

登录或验证码用“手动接管”，完成后点击恢复并重新读取。关闭窗口继续运行；彻底退出关闭专用浏览器，只断开日常浏览器。停止任务/相关权限变更撤销控制，不自动重连和重放未知外部操作。安装与当前文件大小限制见 [P08 说明](development/P08-浏览器双通道.md)。

## 11. P11 记忆入口与生效时机

工作台顶部“记忆”可查看通用或当前项目记忆。AI 只提出带来源的候选；用户点击“确认记住”，或手工填写后点击“保存并确认”，才成为正式偏好。拒绝的候选仍保留来源，不参与检索。

P12 的设置迁移默认选择当前已确认记忆，也可打开“包含记忆历史与未生效记录”，选择候选、已拒绝、已删除条目及全部历史。预览显示范围、状态和版本数；确认后只有已确认且未删除的记忆生效，其他条目保留原状态。每个旧版本独立核对作用范围，不能混入其他项目。项目设置导入建立新项目，冲突先调整目标，原配置与文件不被覆盖；权限为请求审批，模型密钥由用户重新填写。此入口不自动开始任务。

修改/删除从下一次模型调用生效，已经发出的请求不会撤回。默认列表隐藏已删除项，可勾选“显示已删除”后从历史恢复。恢复待确认版本仍需确认；恢复会新增历史记录，不抹掉之前的修改。记忆面板的文字导出仍只包含当前有效的已确认记忆；需要迁移全部历史时，使用设置中的加密迁移入口。

记忆面板中的删除保留撤销历史，不擦除旧对话或备份；明确清空当前应用数据是另一个独立入口，见第 14 节。项目记忆与其它项目隔离，不能改变权限或审批规则。

## 12. P11 定时计划入口与发生历史

顶部“定时任务”提供一次、按间隔、每天和每周计划；配置所用项目、目标、模型、模式、权限与时区，保存前可预览下一次时间。新计划默认请求审批。模型或项目配置修改后，应重新保存计划，确认新的设置用于未来执行。

每次运行形成独立任务，可从历史打开完整过程、审批和结果。停用/删除只停止未来触发，已开始任务继续；删除保留历史。同一计划上次仍在运行或等待输入/审批、子助手或文件操作尚未结束时，本次触发跳过并留下原因，手动立即运行也遵守此规则。

关窗后继续，真正退出后停止。再次启动只记录错过，不自动补跑，不继续启动中断的发生任务。手动“立即运行”会创建新任务；用户在历史任务中点继续，则恢复该任务，且仍检查是否与同计划其它任务重叠。

电脑的时区变化不重解释计划时区；夏令时缺失的每日/每周时刻跳过，重复时刻只取较早的一次。调度宽限、暂停观测与未验证的实际睡眠行为见 [P11 定时设计](development/P11-定时设计.md)。查看更早发生记录时暂停历史自动刷新，重新选择计划恢复最新列表。

应用内发生历史、任务结果和审批入口继续保留。通知组合 Q44 已确认；不能将系统通知未开启理解为允许越过审批。通知仅提示新发生的完成、失败或待处理状态，软件重启不重新弹出历史结果。

## 13. P12 完整资料迁移与任务恢复

“设置 → 完整资料迁移”把已选择的多类资料放进一个口令保护包，不是复制整台电脑，也不自动带上未选择的文件、空目录和原文件权限。

1. 先停止准备导出的运行任务。选择原项目，再勾选模型配置、记忆、主任务、技能/插件和草稿，填写需要带走的当前文件相对路径。主任务会带上其助手、附件原文和已保存的文件历史。
2. 选择新的保存位置，设置至少 12 个字符的口令。已有包不覆盖，口令不保存；遗失后无法解密。模型密钥、插件凭据、浏览器登录和系统凭据不随包迁移。
3. 读入包后，为每个原项目填写新名称和现有目标文件夹，并为历史原文件夹选择对应的新项目。不同原项目使用不同目标目录；一个任务用过多个目录时分别核对，不按同名路径猜测。
4. 预览配置、任务、历史、附件、文件、扩展和冲突；确认后分步导入。界面区分已经完成、等待文件审批和发生错误的部分。相同包重试使用原来保存的映射继续，不重复创建资料，也不把部分成功说成全部撤回。
5. 当前文件进入新的“迁入项目文件”任务；核对目标和内容，通过现有审批后才写入。目标已有文件或预览后变化时拒绝静默覆盖。只导入任务、附件或历史不会改写项目当前文件。
6. 重新填写模型等凭据，检查项目规则、记忆和扩展。导入的任务采用请求审批、命令关闭；需要工作时手动继续。只有已确认且未删除的记忆生效，扩展仍需手动启用，草稿仍需确认安装。

任务带有未决调用、旧审批、协作等待或不确定结果时，恢复界面先逐项显示原操作和原结果。用户需要说明实际已发生什么、允许怎样处理；没有核对完，排队消息、重启和主任务都不能启动这些任务。保存说明只留下核对结论，不立即请求模型或执行工具；之后仍需手动继续，新操作重新检查目标并按当前权限审批。旧审批和旧操作不会因迁移重新执行。

恢复后的任务、助手、附件和版本有新编号，同批来源重新关联；未选择的来源保留文字说明，旧对话中的绝对路径不会被静默改写。历史命令仍可分页查看，但只允许原记录所属任务读取。重复导入不覆盖之后的用户修改；恢复目标已被永久删除时，显示“目标已删除”，保留防重复记录，不重新创建。

独立的文件历史、项目设置、附件、任务档案和扩展迁移入口继续保留，各自范围不因此扩大。统一包的范围、容量和故障边界见 [统一迁移与人工核对](development/P12-统一迁移与人工核对.md)。本机独立目录和密钥已经检查，物理另一台电脑上的迁移、原生路径选择及用户体验仍需集中验收。

## 14. P12 数据清理与恢复初始状态

“设置 → 数据清理与恢复初始状态”先要求暂停运行中的工作，再预览数量、范围和影响。预览不删除数据。一般清理输入 `DELETE`，清空当前数据输入 `RESET`；确认后会停止引擎及其工具，处理完需重新打开软件。

| 选择 | 实际处理及保留范围 |
|---|---|
| 回收未引用内容 | 仅回收已经没有有效记录使用的普通内容和加密文件；任务、附件、档案及待审批文件计划仍需使用的内容保留。 |
| 备份并清理旧文件版本 | 按每个文件保留数量与版本年龄筛选；先在应用数据目录外保存至少 12 字符口令保护的备份，并验证确实能解开，再删除选定版本。备份失败就不删。当前项目文件不变。 |
| 永久删除已归档任务组 | 删除所选根任务和全部助手的会话、运行、附件与文件历史；独立导入档案需另外选择删除。保留防重复回执，解除记忆/定时历史指向已删任务的链接，但保留文字出处。 |
| 移除只读导入档案 | 删除所选独立档案及其引用；已经恢复出的任务单独保留，不连带删除。 |
| 清空本机 WorkPilot 数据与凭据 | 清空当前应用资料及其登记的凭据和本机版本密钥。项目和独立任务文件夹、用户导出包、其它数据目录、更新恢复副本保留。 |

清理会重新核对预览内容，数据有变化时要求重新预览。删除任务后，仍被其它任务、版本、独立档案或有效文件计划引用的内容继续保留；因此不承诺删除一个任务就马上物理擦除全部共享内容。已删迁入文件任务释放失效的暂存引用，其防重复记录不再保留无用原文。

清空前检查项目及独立任务文件夹是否位于应用数据目录里面，存在这种情况就先拒绝处理。清空不是物理磁盘安全擦除，也不清理任意系统账号。删除本机版本密钥后，依赖它的旧本地副本可能无法解密，所以先把需要的资料导出为独立口令包。更新恢复副本的删除另见第 15 节。

处理结果分别说明记录是否已删除、文件是否回收完成、凭据是否还有待重试项，不能把部分失败显示成全部成功。已经确认的清空若中途停止，下次启动会接续剩余清理；这不会启动原任务。具体规则见 [版本保留与数据清理](development/P12-历史备份与恢复.md#版本保留与数据清理alpha1215)。

Windows 卸载默认保留资料。只有在交互式卸载中另行勾选“清空历史与凭据”才处理当前数据；静默卸载、被动卸载和更新卸载均不自动清空。网页缓存是另一个独立选项。数据被占用或清理失败时停止卸载，保留可再次处理的程序入口。

## 15. P12 软件更新与恢复副本

“设置 → 软件更新”支持选择本机 `.wpupdate` 签名包，或填写私有 HTTPS 更新源的确切地址。没有默认公共更新地址，没有后台自动检查、下载或安装；模型和插件不能替用户发起软件更新。

1. 点击“检查更新”，核对目标版本、变化和容量。软件先验证发布签名；相同版本、降级、不适用平台和坏包会拒绝。
2. 点击“下载并核验完整更新”，逐个核对文件并准备新版。此时旧程序和任务继续运行。准备完成后页面显示安装目录外的恢复工具位置，可打开所在文件夹。
3. 勾选“我确认停止任务、备份数据并立即安装”，再点击“退出并安装更新”。软件停止任务及工具后退出；更新助手先保留原资料，并只在数据副本上检查新版兼容性。
4. 程序和数据协调切换。失败或中途结束时使用记录恢复原程序与数据，不运行旧任务。若原快捷方式暂时打不开，双击此前准备好的恢复工具，核对位置后明确确认恢复；已经完成的更新不会借此回退覆盖新工作。
5. 完成后手动重新打开软件，查看上次更新结果和旧副本位置。原任务仍须人工继续，不自动补跑。

“更新恢复副本管理”与“清空当前数据”分开。它只列出本次安装已经完成或回滚的更新所留下的旧程序、旧数据和失败副本。看到目录与容量后输入 `DELETE`，软件先停止引擎并再次核对清单；发生变化就要求重新预览。未完成更新、当前程序/数据、系统凭据、用户导出包及升级证明记录保留；含有被保留文件的旧目录可能不会消失。完成后需重新打开软件。

更新包有真实签名验证，Windows 安装器目前仍无发布者证书，二者不能混为一谈。现有证据覆盖本机签名包、独立数据与恢复流程，不代表公共更新站点、干净 Windows 或用户实际升级已验收；macOS/Linux 仍属于后续平台阶段。详见 [签名更新与恢复](development/P12-签名更新与恢复.md)、[P12 整合交付](../artifacts/workpilot-p12-complete-2026-10-04/README.md)。
