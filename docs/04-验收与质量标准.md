## 1. 什么算完成

每个阶段都要有可运行交付物、明确的验证记录和已知限制。测试结果区分：

- 模拟验证：本地固定响应或错误样本，用于重复测试程序行为。
- 真实服务验证：真实模型、浏览器、文件和操作系统上的验证。
- 用户体验验证：用户实际检查界面、工作方式与成果。

模拟服务通过不能代替实际模型兼容。编译成功不能代替 macOS/Linux 实机测试。AI 文字声称成功不能代替真实成果。

## 3. 测试层次

### 引擎和协议

对任务状态、事件排序、模型流解析、权限决定、调度去重编写行为测试。覆盖正常路径、取消、异常和崩溃点，不写仅复述实现代码的测试。

模型录制样本使用合成或脱敏内容。断流位置覆盖文本中途、工具参数中途、工具已完整但最终状态未收到等情况。保存调用标识与结果之间的关联。

### 集成

在临时工作目录中运行真实子进程、数据库迁移、浏览器和工具服务。注入进程崩溃、连接中断、文件冲突和磁盘写入失败。对有副作用的任务检查“已执行但结果未保存”场景，不能简单自动重试。

### 桌面与真实成果

使用真实窗口检查双语、输入、长列表、审批、托盘、退出和恢复。工具浏览器与 WorkPilot 自己的界面分别验证。桌面测试工具是否覆盖各系统由 P00 验证，未覆盖项安排人工检查。

办公文件既检查结构和数据，也做实际打开/预览；不能用同内容重建冒充原文件转换。

## 4. 性能验证口径

优先级来自 Q47：交互、停止和合理资源占用优先，之后扩展并发。模型网络等待、浏览器、文档工具与引擎自身分别计时。

以下为工程目标。P00 已记录部分原型基线，数值、测量口径与未覆盖项见 [验证记录](development/P00-验证记录.md)；未覆盖的目标继续保留，不以一次最好样本宣称全部达标：

| 项目 | 初始目标及口径 |
|---|---|
| 常用按钮反馈 | 本机点击到界面状态更新的 p95 不超过 150 ms |
| 停止反馈 | 点击到显示停止中的 p95 不超过 200 ms；实际工具结束单独记录 |
| 工具停止 | 可取消的本地自有进程树以 2 秒内结束为初始目标；不可立即撤销的外部操作如实显示 |
| 本地事件展示 | 引擎发出事件到界面可见的 p95 不超过 250 ms，不包含模型生成时间 |
| 冷启动 | 本地数据下达到可操作界面以 3 秒为初始目标，不等待云端模型连接 |
| 资源占用 | 记录引擎、界面、浏览器、工具各自占用；先建立真实基线，不虚构统一内存承诺 |

p95 指至少 95% 的测量结果在该时间内。记录机器、版本、数据规模、是否启用浏览器及测量次数，不能只取一次最好结果。

压力样本建议包含 1/4/8 个任务、1/3/8 个助手、10 万条事件的历史任务及持续 4 小时运行。并发上限按真实结果调整；这些是测试规模，不是对模型服务配额的承诺。

## 5. 发布门槛

- 核心验收场景通过，阻断启动、数据损坏、越权执行、无法停止、跨任务串数据等问题不得带入正式可用版。
- 普通缺陷有清单和影响说明，不能把缺失的首版功能改称“后续优化”。
- 三类模型协议至少各有真实服务验收记录；暂缺服务条件时明确待验收，不宣称全兼容。
- 已登录通道分别验证 Chrome、Edge；专用浏览器另有证据。
- Windows 实机之外，安装包要在干净系统或等效隔离测试环境检查依赖。
- macOS/Linux 在对应阶段通过实机或等效真实操作系统环境测试。仅有 Windows 测试时，发布说明不得写成三端功能均已验证。
