# WorkPilot 总体架构

更新日期：2026-10-02
性质：面向实现的架构方案。技术基线已获用户认可，具体模块边界为开发设计。

## 1. 分工

~~~text
React 中英双语工作台
  对话 / 项目 / 完整过程 / 文件和网页 / 设置
                    ↕
Tauri 桌面宿主
  窗口 / 托盘 / 通知 / 安装更新 / 本地通信
                    ↕
独立 Rust 执行程序
  任务与队列 ─ 会话与上下文 ─ 多助手调度
  模型适配 ─ 权限审批 ─ 工具调度 ─ 定时任务
                    ↕
工具进程与系统适配
  文件 / 终端 / Git / 浏览器 / MCP / 办公与图片
                    ↕
SQLite 元数据 + 文件成果与版本 + 系统凭据存储
~~~

核心引擎不依赖某个界面框架。桌面窗口隐藏时，宿主和引擎继续存在；选择彻底退出时，由宿主协调引擎和子进程退出。首版不另装一个会在应用退出后继续工作的系统服务。

## 2. 建议的源码布局

以下为目标布局。P00 已建立 desktop、contracts、engine、platform、browser-bridge 和浏览器扩展/测试样本；P01 增加 storage、共享类型生成与系统凭据接口。providers、policy、tools、agents 等正式业务模块仍按后续阶段实现。

~~~text
apps/desktop/          React 界面与 Tauri 宿主
crates/contracts/      命令、事件、数据版本及跨语言类型
crates/engine/         主执行循环、队列、调度和恢复
crates/providers/      三种模型协议及能力适配
crates/storage/        SQLite、迁移、事件记录和文件索引
crates/policy/         权限、审批、执行范围
crates/tools/          工具注册、参数验证与进程管理
crates/agents/         主助手、子助手、依赖与接替
crates/platform/       Windows/macOS/Linux 系统差异
crates/browser-bridge/ P00 本机浏览器消息桥接原型
services/browser/      专用浏览器驱动与统一浏览器工具
extensions/browser/    连接用户 Chrome、Edge 的扩展及桥接
services/documents/    文件解析、生成与预览转换
resources/runtimes/    随包运行环境的清单与来源
tests/fixtures/        可重复的模型流、文件、网页和异常样本
docs/                  本次计划及后续实现记录
~~~

模块可以先作为 Rust 工作区中的库，不把每个模块拆成网络微服务。浏览器和办公处理使用独立进程，是为了复用工具生态和处理故障，不代表这些进程天然具备访问隔离。

## 3. 核心数据对象

| 对象 | 责任和关联 |
|---|---|
| 项目 Project | 一个主要文件夹、项目规则、模型默认值和权限覆盖 |
| 任务 Task | 用户目标、状态、工作模式、队列、成果集合 |
| 执行 Run / Turn | 一次实际运行或继续，明确开始结束及失败原因 |
| 助手 Agent | 角色、父任务、模型配置、职责、上下文与当前状态 |
| 模型配置 ProviderProfile | 协议类型、服务地址、模型标识、能力与凭据引用 |
| 工具调用 ToolCall | 参数、执行范围、审批、开始与结束记录、操作标识 |
| 审批 Approval | 具体动作、参数摘要、规则版本、批准者、有效范围 |
| 成果 Artifact / Revision | 实际文件、来源任务、版本、前后变化、校验信息 |
| 定时计划 Schedule | 触发规则、时区、目标项目、授权和执行历史 |
| 记忆 Memory | 内容、来源、适用范围、确认状态、修改历史 |
| 事件 Event | 顺序号、任务/助手标识、事件类型、时间和内容引用 |

SQLite 保存索引和状态；大型日志、图片、文件版本保存为磁盘对象并用引用关联。通过事务把状态变化与事件记录一起保存，避免界面显示成功但记录未落盘。

## 4. 界面与引擎的通信

- 命令包括：开始、排队、引导、停止、继续、批准、拒绝、修改设置。
- 事件包括：文本片段、工具开始/结果、状态变化、子助手变化、审批请求、成果生成、错误、用量。
- 命令带唯一请求编号；回执只表示命令被接受，不能当作任务已经完成。
- 事件带单调递增序号。界面断开后从最后序号补读，防止漏进度或重复显示。
- 文本可以分片到达，但工具参数必须完整、验证成功、通过审批后才能执行。
- 限制队列和日志缓冲容量；界面渲染跟不上时采用批量更新和按需加载，不无限占用内存。
- 首版优先验证本机子进程消息通道；控制接口不默认暴露在局域网或公网。

通信形式、进程退出和崩溃恢复在 P00/P01 做原型验证。业务模块依赖统一契约，不直接依赖 Tauri 的窗口对象。

P01 实现本机管道、独立保存线程、SQLite 事务和按序号补读；基础契约见 [数据模型与契约](development/P01-数据模型与契约.md)。P03 在其上实现会话、执行步骤、检查点、人工继续和不确定操作核对，见 [执行引擎与恢复](development/P03-执行引擎与恢复.md)。当前真实文件与终端工具仍待 P04。

## 5. 模型与执行循环

执行循环：读取目标及上下文 → 发起模型请求 → 解析响应 → 执行已验证工具 → 保存结果 → 请求下一步。

三个模型适配器输出统一内部事件，但保存恢复任务需要的提供方原始字段和关联标识。不要把三种接口简化成同一个地址模板。

能力按“服务配置＋模型”记录：文本、图片输入、工具调用、流式输出、上下文限制、用量返回、原生文件或图片生成等。未知能力明确标为未知；不自动把不支持的参数发给服务。

所有模型请求默认禁止自动重试和自动切模型，包含使用的库或 SDK 内置重试。服务返回错误、断流或终止不完整时保存已收到内容并中断当前调用所属的执行分支。

模型提供的完成结论与任务检查项共同决定结果。不能验证的语义结论标明依据和范围；文件存在不等于内容正确。

P03 的实际执行循环位于独立 workpilot-runtime 库，桌面通过引擎命令驱动。默认 4 个任务并发、最多 32 个运行或排队项；控制命令独立处理。用户要求与原始目标固定保留，旧历史按完整交互归档并保存来源。P02 三协议真实服务验收仍待配置；受控样本成功不能代替真实模型成功。

## 6. 工具、权限与环境

工具须声明输入、输出、读写范围、外部影响、取消能力和是否可安全重复。调用统一经过：

~~~text
参数完整性 → 权限与作用范围 → 审批 → 执行记录
          → 实际工具 → 结果校验 → 状态与成果
~~~

文件工具验证解析后的真实路径和链接；终端、MCP 与脚本可能拥有更广泛能力，不能靠文件工具的路径检查约束它们。P04 必须验证对应操作系统的执行边界，并向界面报告实际限制能力。

外部网页、文件和工具结果都是任务资料，不能因此获得新增权限。扩展的说明不能代替实际执行检查。

## 7. 多助手与文件协作

- 主助手创建子任务，显式记录成员职责、模型、依赖、结果交付要求。
- 子助手权限不超过任务已经授予的范围；继承模型凭据引用而非复制到提示词中。
- 独立分支可并行；同一文件的写入需要协调、版本前提检查和冲突提示。
- 子助手失败只停止该分支。主助手可创建新的接替尝试，但原失败记录必须保留。
- 接替采用有上限的调度策略，不能通过不断新建助手无限重复失败。具体默认上限作为工程参数记录。
- 停止父任务会向其子助手、模型连接和所拥有的工具进程传播。

## 8. 浏览器与桌面边界

Tauri 的界面网页组件和自动化浏览器不是同一层。Windows 与 macOS/Linux 的网页组件不同，不能把某一平台上的试验成功当作三端成功，参见 [官方资料](06-资料与依据.md)。

浏览器工具统一包含导航、读取结构、点击、填写、截图、上传、下载和标签页管理。底下接两种驱动：

1. WorkPilot 管理的专用浏览器与独立用户目录。
2. 用户授权连接的 Chrome/Edge，通过浏览器扩展和本机桥接控制获准标签页。

不使用复制日常浏览器凭据或修改其默认用户目录的办法冒充接入。嵌入右侧工作区的呈现方式在 P00 单独验证；若必须调整外壳或展示方式，属于重要体验决定，需要给用户具体比较。

原生电脑操控放到后续版本，不能用模拟全桌面鼠标键盘作为首版浏览器连接失败的隐含替代。

## 9. 生命周期、定时与更新

窗口关闭事件只隐藏窗口。任务和本地定时器由仍运行的引擎持有。应用彻底退出时停止接收新任务、取消执行、保存状态并结束应用拥有的进程；不得关闭用户原有的 Chrome/Edge。

重启后展示中断任务，由用户选择继续。定时计划只安排未来触发，错过的执行先记录而不批量自动补跑；这是工程建议，见 [待办](05-决策与待办.md)。

更新须由用户决定安装时间。更新前协调任务和数据迁移，失败时不能破坏现有数据库与工作文件。

## 11. 阅读用语

| 用语 | 大白话解释 |
|---|---|
| 进程 | 电脑上实际运行的一份程序；多个进程可分别启动和结束 |
| 协议 | 两个程序交换消息时约定的格式和规则 |
| 流式返回 | 内容逐段传回来，界面可以边接收边显示 |
| 契约 | 前后模块事先约定好需要什么输入、返回什么结果 |
| 事务 | 几笔相关记录一起保存，失败时一起撤回，避免只保存了一半 |
| 检查点 | 把工作做到哪一步存下来，之后据此判断怎样继续 |
| 并发 | 多件工作交替或同时推进，不代表它们一定都在同时计算 |
| 沙箱/隔离 | 通过实际系统机制限制程序能触达的文件、网络或系统能力 |
| 迁移 | 软件升级后，把旧数据转换成新版本能够读取的形式 |
| 回归测试 | 改动后重新检查原有重要能力，确认没有被破坏 |


## 12. P04 实际落地

当前目录新增 `crates/tools` 和 `crates/policy`。真实工具经过输入校验、权限规则、独立审批、目标版本复核后执行；文件权限由目录句柄维护，命令权限与进程归属由平台层处理。SQLite schema 4 保存审批、修改前后文件和完整日志引用。桌面显示有效权限、具体审批、独立审查依据和版本。

Windows 审批模式命令使用 AppContainer，生命周期使用 Job。两者职责分开，不能仅靠 Job 声称隔离。完全访问使用系统账户权限；macOS/Linux 的实际进程隔离尚未实现。插件随后接入相同工具与权限通路，不绕过审批。P07 仍需完成命令/插件修改的完整项目快照；P04 的哈希清单不能代替回滚。

当前精确限制与恢复语义见 [P04 实际设计](development/P04-工具与审批边界.md)。用户明确提供的阿里云真实三协议已经补测，原样本服务仍用于确定性回归，不替代真实服务证据。

## 13. P05 实际落地

每个成员拥有独立内部任务、助手、模型会话与检查点，团队关系通过 schema 5 保存。主助手使用明确的分派、等待、交付检查和接替工具；等待时释放运行名额，成员交付后再接续。调度同时执行全局和根任务数量限制；模型失败不自动重试，接替次数与累计人数有上限。

成员权限同时受当前父级和创建时上限限制。同一实际目录的文件写入与命令共享排他执行权，受管理文件仍以旧版本为前提。根任务停止覆盖整棵协作树，重启不自动执行，手动继续保留已完成分支。桌面基础入口已加入成员、依赖、交付、审批及接替，正式布局按 P06 推进。

实际字段、调度边界、默认数量、团队历史保留与工程入口见 [P05 多助手设计](development/P05-多助手调度与交付.md)，测试范围见 [P05 验证记录](development/P05-验证记录.md)。

## 14. P06 实际工作台

schema 6 保存项目规则与目录身份、任务归档、工作台偏好和导出回执。React 使用 Workspace 查询得到有界展示数据，原始执行上下文仍由引擎维护。对话来自真实交付事件，搜索/导出由独立只读作业完成，不阻塞任务调度；完整正文以已登记内容引用组织，不追随模型伪造的引用。

工作台按项目/任务、对话、权限/协作/成果/记录三栏呈现。语言和外观与权限变更分别保存；通知数据接口已具备，系统通知策略仍待 Q44。技术预览从普通首页移到显式诊断入口。详见 [P06 工作台与记录](development/P06-工作台与记录.md)。

## 15. P07 实际文件与开发工作区

crates/workbench 接入现有引擎，负责工作区命令、单次审批、加密文件版本、真实终端、Git 与运行预览归属。schema 7 保存操作与版本来源；已有 P04 文本版本继续按原引用读取。模型文件工具与手工工作区共享实际项目目录的写入锁，受管理命令开始前持久化字节快照，结束后记录变化；重启只补记观察到的变化，不重跑命令。

原始文件版本与脱敏执行日志分开保存：版本库使用认证加密和系统凭据密钥，普通记录以内容引用保留完整可读输出及脱敏输入。完整记录导出不等于跨机器文件版本备份，P12 必须处理加密对象及密钥迁移。

独立运行预览窗口没有桌面命令能力；引擎核验监听端口属于当前受管理进程。终端停止沿用 Windows Job/AppContainer 边界。容量、排除目录、长进程锁和其它平台未验证项见 [P07 设计](development/P07-文件历史与开发工作区.md)。P08/P09 应复用此通路补齐浏览器下载与插件文件变更来源。
