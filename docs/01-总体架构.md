# WorkPilot 总体架构

更新日期：2026-10-04
性质：面向实现的架构方案。技术基线已获用户认可，具体模块边界为开发设计。

当前实现对齐 P12 整合版 `0.1.0-alpha.12.15`，数据版本为 11。后文标明 P04—P11 的“实际落地”章节保留各阶段当时的结构和边界；当前迁移、清理和更新以第 9、10 节为准。开发与本机自动检查完成不等于干净系统、物理换机或用户体验已经验收，详见 [P12 整合交付](../artifacts/workpilot-p12-complete-2026-10-04/README.md)。

## 1. 分工

~~~text
React 中英双语工作台
  对话 / 项目 / 完整过程 / 文件和网页 / 设置
                    ↕
Tauri 桌面宿主
  窗口 / 托盘 / 通知 / 安装更新 / 本地通信
                    ↕
独立 Rust 执行程序
  任务与队列 ─ 会话与上下文 ─ 多助手调度
  模型适配 ─ 权限审批 ─ 工具调度 ─ 定时任务
                    ↕
工具进程与系统适配
  文件 / 终端 / Git / 浏览器 / MCP / 办公与图片
                    ↕
SQLite 元数据 + 文件成果与版本 + 系统凭据存储
~~~

核心引擎不依赖某个界面框架。桌面窗口隐藏时，宿主和引擎继续存在；选择彻底退出时，由宿主协调引擎和子进程退出。首版不另装一个会在应用退出后继续工作的系统服务。

## 2. 源码布局

以下为 P12 已有的主要目录。任务循环与多助手调度实际放在 runtime，独立 engine 程序负责通信和生命周期；文件、浏览器、迁移等协调放在 workbench，未另设 agents 库。

~~~text
apps/desktop/          React 界面与 Tauri 宿主
crates/contracts/      命令、事件、数据版本及跨语言类型
crates/engine/         独立引擎入口、命令通信和离线管理入口
crates/runtime/        主执行循环、队列、多助手调度和恢复
crates/providers/      三种模型协议及能力适配
crates/storage/        SQLite、迁移、事件记录和文件索引
crates/policy/         权限、审批、执行范围
crates/tools/          工具注册、参数验证与进程管理
crates/workbench/      文件、浏览器、资料迁移与数据清理协调
crates/extensions/     技能、插件、版本与草稿管理
crates/office/         受管理的 Office 转换辅助程序
crates/platform/       Windows/macOS/Linux 系统差异
crates/browser-bridge/ P00 本机浏览器消息桥接原型
services/browser/      专用浏览器驱动与统一浏览器工具
extensions/browser/    连接用户 Chrome、Edge 的扩展及桥接
services/documents/    文件解析、生成与预览转换
resources/runtimes/    随包运行环境的清单与来源
tests/fixtures/        可重复的模型流、文件、网页和异常样本
docs/                  本次计划及后续实现记录
~~~

模块可以先作为 Rust 工作区中的库，不把每个模块拆成网络微服务。浏览器和办公处理使用独立进程，是为了复用工具生态和处理故障，不代表这些进程天然具备访问隔离。

源码维护按 [AGENTS.md](../AGENTS.md) 的 1000 行上限执行。2026-10-04 将命令定义/校验和类型生成、存储层的命令/模型步骤/工具动作/成员创建、工作区准备/请求/执行、扩展管理分别拆为模块；React 工作台拆分标题栏、新建任务、详情、消息队列和文件历史视图。公开接口、事件和数据库结构保持原状，界面状态仍由原工作台持有，子组件接收有明确类型的数据与回调。模块对应关系和验证见 [P12 验证记录](development/P12-验证记录.md)。

## 3. 核心数据对象

| 对象 | 责任和关联 |
|---|---|
| 项目 Project | 一个主要文件夹、项目规则、模型默认值和权限覆盖 |
| 任务 Task | 用户目标、状态、工作模式、队列、成果集合 |
| 执行 Run / Turn | 一次实际运行或继续，明确开始结束及失败原因 |
| 助手 Agent | 角色、父任务、模型配置、职责、上下文与当前状态 |
| 模型配置 ProviderProfile | 协议类型、服务地址、模型标识、能力与凭据引用 |
| 工具调用 ToolCall | 参数、执行范围、审批、开始与结束记录、操作标识 |
| 审批 Approval | 具体动作、参数摘要、规则版本、批准者、有效范围 |
| 成果 Artifact / Revision | 实际文件、来源任务、版本、前后变化、校验信息 |
| 定时计划 Schedule | 触发规则、时区、目标项目、授权和执行历史 |
| 记忆 Memory | 内容、来源、适用范围、确认状态、修改历史 |
| 事件 Event | 顺序号、任务/助手标识、事件类型、时间和内容引用 |

SQLite 保存索引和状态；大型日志、图片、文件版本保存为磁盘对象并用引用关联。通过事务把状态变化与事件记录一起保存，避免界面显示成功但记录未落盘。

## 4. 界面与引擎的通信

- 命令包括：开始、排队、引导、停止、继续、批准、拒绝、修改设置。
- 事件包括：文本片段、工具开始/结果、状态变化、子助手变化、审批请求、成果生成、错误、用量。
- 命令带唯一请求编号；回执只表示命令被接受，不能当作任务已经完成。
- 事件带单调递增序号。界面断开后从最后序号补读，防止漏进度或重复显示。
- 文本可以分片到达，但工具参数必须完整、验证成功、通过审批后才能执行。
- 限制队列和日志缓冲容量；界面渲染跟不上时采用批量更新和按需加载，不无限占用内存。
- 首版优先验证本机子进程消息通道；控制接口不默认暴露在局域网或公网。

通信形式、进程退出和崩溃恢复在 P00/P01 做原型验证。业务模块依赖统一契约，不直接依赖 Tauri 的窗口对象。

P01 实现本机管道、独立保存线程、SQLite 事务和按序号补读；基础契约见 [数据模型与契约](development/P01-数据模型与契约.md)。P03 在其上实现会话、执行步骤、检查点、人工继续和不确定操作核对，见 [执行引擎与恢复](development/P03-执行引擎与恢复.md)。P04 随后接入真实文件与终端工具；P12 的迁移、清理和更新沿用明确的管理入口，不把管理权限或口令交给模型工具。

## 5. 模型与执行循环

执行循环：读取目标及上下文 → 发起模型请求 → 解析响应 → 执行已验证工具 → 保存结果 → 请求下一步。

三个模型适配器输出统一内部事件，但保存恢复任务需要的提供方原始字段和关联标识。不要把三种接口简化成同一个地址模板。

能力按“服务配置＋模型”记录：文本、图片输入、工具调用、流式输出、上下文限制、用量返回、原生文件或图片生成等。未知能力明确标为未知；不自动把不支持的参数发给服务。

所有模型请求默认禁止自动重试和自动切模型，包含使用的库或 SDK 内置重试。服务返回错误、断流或终止不完整时保存已收到内容并中断当前调用所属的执行分支。

模型提供的完成结论与任务检查项共同决定结果。不能验证的语义结论标明依据和范围；文件存在不等于内容正确。

P03 的实际执行循环位于独立 workpilot-runtime 库，桌面通过引擎命令驱动。默认 4 个任务并发、最多 32 个运行或排队项；控制命令独立处理。用户要求与原始目标固定保留，旧历史按完整交互归档并保存来源。P04 已补用户提供的阿里云三协议真实调用，范围见 [P04 验证记录](development/P04-验证记录.md)；受控样本成功不能代替真实模型成功，也不代表其它模型或供应商已验证。

## 6. 工具、权限与环境

工具须声明输入、输出、读写范围、外部影响、取消能力和是否可安全重复。调用统一经过：

~~~text
参数完整性 → 权限与作用范围 → 审批 → 执行记录
          → 实际工具 → 结果校验 → 状态与成果
~~~

文件工具验证解析后的真实路径和链接；终端、MCP 与脚本可能拥有更广泛能力，不能靠文件工具的路径检查约束它们。P04 必须验证对应操作系统的执行边界，并向界面报告实际限制能力。

外部网页、文件和工具结果都是任务资料，不能因此获得新增权限。扩展的说明不能代替实际执行检查。

## 7. 多助手与文件协作

- 主助手创建子任务，显式记录成员职责、模型、依赖、结果交付要求。
- 子助手权限不超过任务已经授予的范围；继承模型凭据引用而非复制到提示词中。
- 独立分支可并行；同一文件的写入需要协调、版本前提检查和冲突提示。
- 子助手失败只停止该分支。主助手可创建新的接替尝试，但原失败记录必须保留。
- 接替采用有上限的调度策略，不能通过不断新建助手无限重复失败。具体默认上限作为工程参数记录。
- 停止父任务会向其子助手、模型连接和所拥有的工具进程传播。

## 8. 浏览器与桌面边界

Tauri 的界面网页组件和自动化浏览器不是同一层。Windows 与 macOS/Linux 的网页组件不同，不能把某一平台上的试验成功当作三端成功，参见 [官方资料](06-资料与依据.md)。

浏览器工具统一包含导航、读取结构、点击、填写、截图、上传、下载和标签页管理。底下接两种驱动：

1. WorkPilot 管理的专用浏览器与独立用户目录。
2. 用户授权连接的 Chrome/Edge，通过浏览器扩展和本机桥接控制获准标签页。

不使用复制日常浏览器凭据或修改其默认用户目录的办法冒充接入。嵌入右侧工作区的呈现方式在 P00 单独验证；若必须调整外壳或展示方式，属于重要体验决定，需要给用户具体比较。

原生电脑操控放到后续版本，不能用模拟全桌面鼠标键盘作为首版浏览器连接失败的隐含替代。

## 9. 生命周期、定时与更新

窗口关闭事件只隐藏窗口。任务和本地定时器由仍运行的引擎持有。应用彻底退出时停止接收新任务、取消执行、保存状态并结束应用拥有的进程；不得关闭用户原有的 Chrome/Edge。

重启后展示中断任务，由用户选择继续。定时计划只安排未来触发，错过的执行先记录而不批量自动补跑；这是工程建议，见 [待办](05-决策与待办.md)。

P12 已提供用户主动检查、准备和安装更新的入口，支持本地 `.wpupdate` 包和指定的私有 HTTPS 源，没有默认公共更新站点或后台自动安装。更新清单由编译时固定的公钥验证 Ed25519 签名，完整包逐文件核对后暂存；不信任包内自带公钥或未签名文件。

用户确认安装后，宿主停止引擎和自有工具，独立更新助手等待桌面退出并取得安装、数据的独占锁。先复制应用数据，再由新版引擎的离线检查模式验证副本；检查过程中不创建模型连接、任务循环或定时调度。程序与数据通过可恢复记录协调切换，失败恢复原程序和原数据，已提交更新不重复回退。项目目录和系统凭据不复制到更新包，也不因更新而改写。

准备阶段在安装目录外生成可双击的恢复工具和说明，覆盖主程序在切换中途暂时不可用的情况。旧程序、旧数据和失败副本保留，由单独的“更新恢复副本管理”预览和确认删除；未完成更新的恢复材料、当前程序/数据和用户导出包受保护。实现位于平台更新模块、引擎离线检查与桌面更新入口，边界见 [签名更新与恢复](development/P12-签名更新与恢复.md)。更新包签名不等于 Windows 安装器已有发布者证书。

## 10. 资料迁移、恢复与清理（P12 当前实现）

### 10.1 统一选择与目录映射

“完整资料迁移”统一选择多个项目及其模型配置、记忆、任务与助手、附件原文、文件历史、所选当前文件、技能/插件和草稿，形成口令保护的 `WPFULL01` 包。它组合已有迁移结构，不复制整个数据库或磁盘；未选择的文件、空目录结构和文件系统权限不因此自动复刻。任务档案保存的历史不要求原项目在线，读取当前文件则需要原目录可访问。

导入必须明确映射每个原项目和历史原目录，校验目标实际目录身份并预览冲突。新项目、任务、成员、附件、版本与记忆重新编号；团队依赖和同批资料来源重建，未选来源仅保留文字出处，不猜测同名对象。当前项目文件另建“迁入项目文件”任务，经过当前文件核对和审批后才写入；恢复会话、附件或版本本身不覆盖项目文件。

迁移不携带系统密钥、模型/插件凭据、浏览器登录或旧执行权限。会话正文进入目标内容库，文件版本与附件原文使用目标本机密钥重新加密；扩展资源校验后写入目标版本目录。口令不进入普通设置、事件或模型输入。各组件保留自己的事务，统一流程用持久的分步回执记录已完成项；中途失败可以按原映射继续，不能声称整包跨文件与数据库全部原子回滚。结构、容量和故障规则见 [统一迁移与人工核对](development/P12-统一迁移与人工核对.md)。

### 10.2 历史、记忆与扩展

独立文件历史、项目设置、附件、任务档案和扩展迁移入口继续保留。文件历史完整核验后一次登记回执和版本；恢复具体版本仍经过 P07 当前文件核对和审批。设置文档版本 2 包含所选记忆的历史及未生效记录，兼容旧版本 1；候选、拒绝和删除状态不会因导入自动生效。统一迁移还能把同批记忆的任务来源关联到新任务。见 [历史备份与恢复](development/P12-历史备份与恢复.md)、[项目设置迁移](development/P12-项目设置迁移.md) 和 [任务与助手档案迁移](development/P12-任务与助手档案迁移.md)。

扩展 `WPEXT001` 内部文档版本 2 已支持当前版本、所选扩展保存的旧版本、已卸载记录和未安装草稿，继续兼容版本 1。管理器重新验证每个版本的资源摘要、所属扩展、依赖和作用范围；安装记录、版本、草稿与回执在同一事务保存。已安装扩展导入后停用，已卸载项保持卸载，草稿保持待确认；凭据、发现缓存和运行会话不复制。重复导入不改变用户之后选择的版本或启停状态。版本查询不受最近 64 条操作记录分页限制，详见 [技能插件迁移](development/P12-技能插件迁移.md)。

### 10.3 任务恢复与未知结果

任务档案可恢复会话、团队关系、附件、文件历史及完整过程，历史命令输出按原任务归属分页读取；正文中的任意旧编号不能充当跨任务读取许可。恢复目标固定为请求审批、命令关闭、手动继续，原审批不进入活动审批表，旧命令和协作等待不重新排入执行队列。

包含未决调用、待审批、协作等待或未知效果的任务会设置持久的人工核对闸门。界面逐项展示原操作和原结果，用户说明已发生什么、允许怎样继续后才解除；保存说明本身不调用模型或执行工具。排队消息、主任务启动子助手、重启都不能绕过核对。后续新动作仍要读取目标状态并重新审批，迁移不自动重放外部副作用。

永久删除恢复目标后保留防重复回执，旧确认返回“目标已删除”，不重新创建任务。迁入文件任务的已删回执只留去重身份，释放失效的清单与内容引用；查询历史索引随目标删除，完整原档案在未被另行删除前继续独立保留。

### 10.4 数据保留、清理与凭据

数据清理提供未引用内容回收、按数量和年龄保留文件版本、归档根任务及全部助手永久删除、独立档案移除和当前数据/凭据清空。预览绑定实际记录；确认后桌面停止引擎，离线维护助手持数据独占锁执行，不创建模型、定时或插件工作。版本删除前必须在应用数据目录外生成口令备份，完成落盘和解密核验，再删除选定记录。

回收同时核对普通记录与加密版本的合法引用，包括活任务、待审批文件计划、附件、独立导入档案和迁移记录。只删除任务不等于立即删除仍被其它资料引用的内容。数据库处理成功但文件回收失败时，结果区分“记录已处理”和“回收待重试”，不报告虚假的全体回滚。

清空仅处理当前应用数据及其登记的模型、图片、扩展凭据和本机版本密钥，保护项目与独立任务文件夹；若这些文件夹位于应用数据目录内，先拒绝清空。根目录未知文件、用户导出包、其它数据目录和更新恢复副本不随之删除。未完成的已确认清空保存重试日志，重启只接续该清空，不恢复原任务。删除本机版本密钥可能使依赖它的旧本地副本无法解密，因此应先导出独立口令包；这不是物理磁盘安全擦除。详见 [版本保留与数据清理](development/P12-历史备份与恢复.md#版本保留与数据清理alpha1215)。

上述迁移、清理和更新已通过 P12 最终 Windows 包的本机自动流程，证据见 [P12 验证记录](development/P12-验证记录.md)。真实换机、干净 Windows、原生授权与用户体验继续单列；没有把这些结果计作 macOS/Linux 验收。

模型、浏览器、Tauri 和 MCP 的官方资料集中在 [资料与依据](06-资料与依据.md)。这些资料证明接口和约束存在，不证明 WorkPilot 已兼容或已达到性能目标。

## 11. 阅读用语

| 用语 | 大白话解释 |
|---|---|
| 进程 | 电脑上实际运行的一份程序；多个进程可分别启动和结束 |
| 协议 | 两个程序交换消息时约定的格式和规则 |
| 流式返回 | 内容逐段传回来，界面可以边接收边显示 |
| 契约 | 前后模块事先约定好需要什么输入、返回什么结果 |
| 事务 | 几笔相关记录一起保存，失败时一起撤回，避免只保存了一半 |
| 检查点 | 把工作做到哪一步存下来，之后据此判断怎样继续 |
| 并发 | 多件工作交替或同时推进，不代表它们一定都在同时计算 |
| 沙箱/隔离 | 通过实际系统机制限制程序能触达的文件、网络或系统能力 |
| 迁移 | 把所选资料搬到新位置并重新关联；升级时也指把旧数据转换成新版能读取的形式 |
| 回归测试 | 改动后重新检查原有重要能力，确认没有被破坏 |


## 12. P04 实际落地

当前目录新增 `crates/tools` 和 `crates/policy`。真实工具经过输入校验、权限规则、独立审批、目标版本复核后执行；文件权限由目录句柄维护，命令权限与进程归属由平台层处理。SQLite schema 4 保存审批、修改前后文件和完整日志引用。桌面显示有效权限、具体审批、独立审查依据和版本。

Windows 审批模式命令使用 AppContainer，生命周期使用 Job。两者职责分开，不能仅靠 Job 声称隔离。完全访问使用系统账户权限；macOS/Linux 的实际进程隔离尚未实现。插件随后接入相同工具与权限通路，不绕过审批。P07 仍需完成命令/插件修改的完整项目快照；P04 的哈希清单不能代替回滚。

当前精确限制与恢复语义见 [P04 实际设计](development/P04-工具与审批边界.md)。用户明确提供的阿里云真实三协议已经补测，原样本服务仍用于确定性回归，不替代真实服务证据。

## 13. P05 实际落地

每个成员拥有独立内部任务、助手、模型会话与检查点，团队关系通过 schema 5 保存。主助手使用明确的分派、等待、交付检查和接替工具；等待时释放运行名额，成员交付后再接续。调度同时执行全局和根任务数量限制；模型失败不自动重试，接替次数与累计人数有上限。

成员权限同时受当前父级和创建时上限限制。同一实际目录的文件写入与命令共享排他执行权，受管理文件仍以旧版本为前提。根任务停止覆盖整棵协作树，重启不自动执行，手动继续保留已完成分支。桌面基础入口已加入成员、依赖、交付、审批及接替，正式布局按 P06 推进。

实际字段、调度边界、默认数量、团队历史保留与工程入口见 [P05 多助手设计](development/P05-多助手调度与交付.md)，测试范围见 [P05 验证记录](development/P05-验证记录.md)。

## 14. P06 实际工作台

schema 6 保存项目规则与目录身份、任务归档、工作台偏好和导出回执。React 使用 Workspace 查询得到有界展示数据，原始执行上下文仍由引擎维护。对话来自真实交付事件，搜索/导出由独立只读作业完成，不阻塞任务调度；完整正文以已登记内容引用组织，不追随模型伪造的引用。

工作台按项目/任务、对话、权限/协作/成果/记录三栏呈现。语言和外观与权限变更分别保存。Q44 已确认软件内、Windows 系统通知和托盘提示，P13 桌面宿主筛选实时任务状态并保存有界通知记录，失败不影响引擎执行；只读定位和审批/执行分开。通知设置与收件箱属于本机桌面数据，不随跨机任务档案继承旧任务定位；版本更新整份数据副本会保留，恢复初始状态会清理。技术预览从普通首页移到显式诊断入口。详见 [P06 工作台与记录](development/P06-工作台与记录.md) 与 [P13 验证记录](development/P13-验证记录.md)。

## 15. P07 实际文件与开发工作区

crates/workbench 接入现有引擎，负责工作区命令、单次审批、加密文件版本、真实终端、Git 与运行预览归属。schema 7 保存操作与版本来源；已有 P04 文本版本继续按原引用读取。模型文件工具与手工工作区共享实际项目目录的写入锁，受管理命令开始前持久化字节快照，结束后记录变化；重启只补记观察到的变化，不重跑命令。

原始文件版本与脱敏执行日志分开保存：版本库使用认证加密和系统凭据密钥，普通记录以内容引用保留完整可读输出及脱敏输入。完整记录导出不等于跨机器文件版本备份，P12 必须处理加密对象及密钥迁移。

独立运行预览窗口没有桌面命令能力；引擎核验监听端口属于当前受管理进程。终端停止沿用 Windows Job/AppContainer 边界。容量、排除目录、长进程锁和其它平台未验证项见 [P07 设计](development/P07-文件历史与开发工作区.md)。P08/P09 应复用此通路补齐浏览器下载与插件文件变更来源。

## 16. P08 实际浏览器接入

Rust workbench 继续掌管任务、权限、一次性操作及加密文件版本；自有 Node.js 工具进程通过匿名调试管道管理专用 Chrome/Edge，通过一次性本机配对与 Rust native messaging 转发连接用户授权的 Companion 扩展。两种通道共用固定 DOM 动作与页面引用检查，不向模型暴露任意脚本或全浏览器访问。

模型执行循环与手工面板使用同一浏览器操作记录，审批后继续按原步骤回执恢复，避免重放外部效果。截图只发给明确支持图片的模型。上传核对实际项目文件版本，下载进入 P07 文件历史和成果来源。schema 保持 7；连接码不保存，活动连接不随重启自动恢复。Windows 进程归属、仅断开日常浏览器和启动取消竞争已有实测；其它系统仍待对应阶段。详细边界见 [P08 设计](development/P08-浏览器双通道.md)。

## 17. P10 实际文档预览

Rust 引擎核验附件所属任务，从加密快照取出原始内容，调度固定的 Node 文档处理器与 Office 转换进程。DOCX/XLSX/PPTX 的页面来自原文件转换后的 PDF；React 只显示图片，不直接执行文档、宏或网页。独立 Images API 继续由 Rust 配置、审批和核验，真实供应商验收仍待条件。

Office 专用进程由 Rust 小型启动器加载官方随包 Python 和 LibreOffice，使用公开主线程回调处理文件；该辅助工具不承担任务执行引擎职责。Windows 采用 AppContainer/Job、只读资源目录、可写单次目录和禁止网络；取消终止所属进程树并回收权限。转换 PDF 以内存缓存限制到 4 份/64 MiB，绑定文件和组件摘要；外部刷新生成新快照，不复用旧文件页面。

Office 单次目录位于当前用户的系统临时位置，使用独占登记保护活动预览并在后续预览中回收宿主意外退出的残留；独立短路径避免深数据目录触发组件初始化崩溃。没有扩大工具文件权限，原附件与加密库仍保持原位置。长度限制、清理边界与诊断规则见 P10 设计。

资源随程序分发，初版优先完整可用，体积与干净系统安装留 P12 验证。此路径尚未在 macOS/Linux 实机通过。格式、容量和实现细节见 [P10 设计](development/P10-文件与图片设计.md)。

## 18. P11 记忆部分实际落地

记忆状态归 Rust 存储层所有，通过 schema 10 保存当前索引、确认状态、版本和候选回执。React 只经现有受控通信管理记忆；模型只有检索与提出候选两个入口。用户确认、编辑、删除和恢复均有版本核对。

执行循环每次调用重新加载当前任务范围内的有效记忆，并将使用的编号、版本与来源保存在实际模型输入中。恢复旧任务时更新历史记忆检索结果，压缩摘要不复用旧检索正文。候选形成必须核验主任务用户原话，AI 分派文字和外部页面不能代替用户来源。

记忆没有新增外部检索服务或向量数据库。边界见 [P11 记忆设计](development/P11-记忆设计.md)。随后接入的定时部分由同一 Rust 引擎承担，见下节。

## 19. P11 定时部分实际落地

schema 11 为原计划表增加游标、发生记录与命令回执。Rust 引擎每 250 毫秒检查未来触发；React 管理计划与发生历史，不持有调度器。每次发生先持久化领取并推进下次时间，再创建普通任务、核对原目录身份和启动原执行流程。计划权限与任务本身同时提交，意外退出后仍可还原原来的权限。

发生记录绑定计划版本与不可变配置引用，任务完成状态直接来自原任务/团队。重叠检查同时覆盖等待审批、子助手与文件工作区操作。退出后不执行；重启只记录错过和启动中断，未来计划正常安排，旧任务须人工继续。

计划以明确 IANA 时区计算，冻结模型、审查模型和项目设置版本。夏令时、时钟回拨和观测到暂停后的规则及容量边界见 [P11 定时设计](development/P11-定时设计.md)。没有增加系统服务或云端执行，真实 OS 睡眠仍待单独验证。
