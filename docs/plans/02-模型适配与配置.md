# P02 模型适配与配置

状态：待外部条件

完成后进入：[P03 单助手执行与恢复](03-单助手执行与恢复.md)

## 目标

建立独立的三协议适配层，让同一执行器连接用户配置的主流模型服务，并准确处理能力差异和错误。

## 实现任务

1. 定义服务配置：显示名称、协议、基础地址、模型标识、认证方式、可选参数、能力声明、凭据引用。
2. 分别实现 Chat Completions、Responses、Messages 的请求、文本流、工具请求、工具结果关联及结束状态。
3. 处理地址包含或不包含版本前缀的情况；给出最终请求路径的脱敏预览，避免重复拼接 /v1。
4. 支持配置导入导出与手动添加模型；服务提供模型列表时可读取，不把列表存在当作实际访问成功。
5. 引入能力清单：文本、图片输入、工具、流式、用量等；自动探测与用户配置的结果注明来源。
6. 模型按全局默认、项目默认、任务/助手覆盖解析，保存每次调用实际使用的配置版本。
7. 禁用自动重试、自动模型回退；连接错误、HTTP 错误、流中错误、超时和不完整结束统一形成可读错误。
8. 用量有返回则记录；价格由可维护配置提供，未知时显示未知，不冒充精确账单。
9. 预留本地模型提供方接口，但首版验收以三类云端协议为主。

## 协议适配重点

| 协议 | 必须验证的差异 |
|---|---|
| Chat Completions | 增量消息、工具索引与标识、结束原因、可选用量 |
| Responses | 不同输出项、工具调用与结果关联、分类型事件、续接所需字段 |
| Messages | 不同内容块、工具请求/结果、块结束与消息结束、流中错误 |

执行器拿到统一事件，但适配器保留必要的原始关联数据。完整工具参数经过验证前不得交给执行层。

接入图片输入不等于具有图片生成能力，图片服务另在 P10 实现。

## 交付物

- 三个协议适配器、配置仓储及连接诊断。
- 模型能力和真实兼容清单，注明测试日期与服务配置，不记录密钥。
- 正常、慢流、碎片、错误和断流的固定样本。
- 可被桌面设置页复用的配置接口。

## 测试与验收

- [x] 三类协议均能处理文本和完整工具调用；工具参数跨多个数据片段时组装正确（固定样本和 Windows 桌面）。
- [x] 401、429、5xx、超时和流中错误均只产生一次模型请求，不自动更换服务或模型（本机 HTTP 计数）。
- [x] 被取消的请求停止向旧任务追加有效执行结果，迟到响应可被识别。
- [x] 文本模型收到图片输入时能明确提示能力限制，不悄悄丢掉图片。
- [x] 地址、参数、认证错误显示大白话原因，并保留脱敏技术详情。
- [ ] 至少各有一种真实服务通过对应协议的完整调用；缺少可用凭据时标记真实测试待完成。
- [x] 所有凭据仅由明确配置读取，不探查其他软件的账号或凭据文件。

## 阶段边界与风险

“主流模型支持”通过具体服务/模型兼容清单表达，不能声称只要兼容某 URL 就具备全部能力。三类协议不必绑定同一家服务，第三方代理的差异也需要记录。

参考：[官方资料 S09—S13](../06-资料与依据.md)。
