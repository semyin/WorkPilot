## 目标

让项目中的文件可查看、编辑、追踪和恢复，并提供基本编程工作区。版本记录覆盖受管理执行产生的文件变化。

## 实现任务

1. 文件树、文本/代码编辑器、搜索、打开所在目录、外部应用打开和文件状态。
2. 文件写入记录修改前后版本、来源任务/助手/工具、时间与校验信息；保留新增、修改、重命名和删除记录。
3. 对文本提供差异；对办公等二进制文件提供版本和可用预览。大文件采用合适的保存和比较策略。
4. 恢复旧版本前检查当前文件是否变化，先保存当前版本，再建立一次明确的恢复操作。
5. 终端和脚本执行前后核对项目文件变化，补齐仅靠内置写文件工具无法覆盖的修改。
6. 并发文件写入使用版本前提与冲突协调；实际落盘采用能保证完整性的方式。
7. 集成项目终端，支持输出、运行状态和取消，适配 Windows 命令环境；终端调用也进入权限与任务记录。
8. Git 状态、修改对比和提交操作；正确处理已有未提交修改，不因 AI 工作而覆盖用户修改。
9. 运行项目并提供本机预览，记录启动的服务端口与进程归属，任务结束时按约定管理生命周期。

## 文件历史覆盖范围

至少覆盖应用自身工具及所管理项目中的脚本、终端和插件写入。外部应用的任意瞬间版本、项目目录之外的全部硬盘变化不自动保证完整捕获；应明确实际版本覆盖边界。

文件监听用于发现变化，执行前快照和版本核对用于保护数据，两者不能互相替代。导入已有项目时不重写目录或自动清理未知文件。

## 交付物

- 文件浏览编辑和版本索引。
- 文本差异、二进制版本查看及恢复。
- 可用终端、Git 操作和本地运行预览。
- 文件冲突与恢复记录。

## 测试与验收

- [ ] 工具写入、脚本写入、重命名、删除都能关联变化和前置版本。
- [ ] 用户外部编辑后，AI 不会静默覆盖，恢复旧版本也保护当前内容。
- [ ] 两助手同时修改同一文件时能够协调或提示冲突。
- [ ] 中文路径、空格、长文件名、大小写差异和大文件经过测试。
- [ ] 已有 Git 未提交修改保留，提交范围与用户任务一致。
- [ ] 终端长进程可停止，停止不杀掉用户原本运行的无关程序。
- [ ] 网页/HTML 预览不会因此获得桌面宿主的文件与命令权限。
