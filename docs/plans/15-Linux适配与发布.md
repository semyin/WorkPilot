# P15 Linux 适配与发布

状态：未开始  
前置：P14  
关联需求：Q04、Q12c、Q13、Q28、Q38、Q39、Q40、Q47

## 目标

交付支持范围明确的 Linux 版本，逐项验证发行版、桌面环境和随包依赖，避免笼统声称所有 Linux 都一致。

## 实现任务

1. 选定首批发行版、版本、处理器和桌面环境，形成测试矩阵；选择由开发者提出并说明维护成本。
2. 验证网页显示组件、字体、中英输入、文件选择、托盘、通知和窗口生命周期。
3. 验证不同显示环境下的桌面表现与浏览器连接；不能默认一个桌面环境的托盘机制适用于全部环境。
4. 适配凭据服务、文件权限、符号链接、进程组、命令环境和受限执行方案。
5. 核对系统库与随包 Node/Python/浏览器/文档工具，明确哪些系统依赖需安装、哪些可随包提供。
6. 选择适合私有分发的安装包形式，验证安装、启动、桌面入口、升级及卸载。
7. 保持三协议、文件版本、多助手、双浏览器、图片生成和定时规则与已有平台一致。
8. 提供发行版差异与排错说明；无法满足的环境明确标为不支持或未验证。

## 交付物

- 支持矩阵、Linux 安装包和依赖清单。
- 托盘/通知、网页组件、工具环境和浏览器的实际验证。
- 共享功能回归及特有差异说明。

## 测试与验收

- [ ] 每个宣称支持的首批环境有真实运行证据。
- [ ] 关闭窗口后任务继续，明确退出后停止；缺托盘支持时提供不会丢失入口的明确处理。
- [ ] 字体、中文输入、路径、大小写和文件权限正确。
- [ ] 工具取消、版本恢复、模型错误和多助手隔离通过。
- [ ] Chrome/Edge 支持范围按实际平台资产和测试记录说明，不能靠名称推定。
- [ ] 安装更新、导入导出和本地诊断通过。
- [ ] 系统依赖缺失有清晰说明，不静默失败，也不宣称完全自包含。

对应验收：AT01—AT30 中适用于目标环境的场景。

## 阶段边界与风险

Linux 的范围需逐步扩大。只有构建检查或无桌面的容器测试不能证明桌面体验通过。原生电脑操控、所有发行版覆盖及全部浏览器支持仍不在本阶段默认范围。
