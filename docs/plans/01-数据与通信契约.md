# P01 数据与通信契约

状态：已验收

完成后进入：[P02 模型适配与配置](02-模型适配与配置.md)

## 目标

让任务、助手、文件成果和界面之间有统一记录。后续能力都能保存进度、显示真实过程和定位错误。

## 实现任务

1. 确定项目、任务、执行、消息、助手、模型配置、工具调用、审批、成果版本、定时计划和记忆的数据结构。
2. 建立 SQLite 迁移、数据库版本、事务边界和升级前备份机制。大文件和大输出存为磁盘内容对象。
3. 建立任务事件记录：事件编号、任务和助手编号、时间、来源、类型、内容引用；同一任务内保证可恢复的顺序。
4. 定义界面命令和引擎事件，生成或共享类型，防止前后端字段各写一套。
5. 实现命令去重、接受回执、执行结果、断线补读；命令接受不代表操作完成。
6. 建立数据访问层，使界面和插件不能直接随意改写核心任务表。
7. 实现用户凭据的系统存储接口；数据库只存引用，日志写入前脱敏。
8. 定义磁盘对象清理、引用检查、导入导出版本和删除任务的边界，避免删除任务时误删用户项目源文件。

## 需要固定的契约

- 文本、工具、审批、助手、成果、错误和用量分别使用明确事件类型。
- 可见队列、引导请求和取消请求可持久化。
- 崩溃前已开始、但没有结束记录的工具必须标为待核对，不能统一改成成功或自动重做。
- 数据库是任务状态的权威来源，界面缓存不能覆盖更新后的引擎状态。
- 读写数据库不能阻塞处理模型流和停止请求的执行线程；实现方式在本阶段测量后确定。

## 测试与验收

- [x] 在状态写入和事件写入之间注入崩溃，恢复后没有“已完成但无结果”的假状态。
- [x] 重复发送同一个请求编号只产生一次操作；不同编号相同内容不被误吞。
- [x] 界面从中间序号重连，事件不漏、不重复。
- [x] 使用大输出和大量事件时，内存和数据库写入保持有界。
- [x] 删除任务记录不会删除未明确选择删除的项目文件。
- [x] 模拟凭据不会进入日志、事件导出或普通配置文件。
- [x] 数据库迁移失败可以回到此前可用数据，不覆盖唯一副本。
