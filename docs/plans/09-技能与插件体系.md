## 目标

让用户通过通用技能、MCP 工具和扩展包增加能力，并能用自然语言创建自己的技能。

## 实现任务

1. Skill 加载支持说明文件、元数据、配套参考资料、脚本和模板；定义发现、启用、按需加载及项目/全局范围。
2. 不把所有技能全文一开始塞入上下文；保留可搜索描述及真实资源引用，按任务加载。
3. MCP 实现本地进程与远程 HTTP 接入、协议版本协商、工具发现、调用、取消、错误和连接状态。
4. 认证信息进入系统凭据存储。远程服务需要登录时提供正常授权入口，密钥不放进技能正文。
5. 扩展包清单记录名称、版本、来源、内容摘要、依赖和权限；先支持本地目录/包及明确来源的网上包。
6. 安装前预览内容和权限；校验后原子安装。停用、卸载、更新失败回退都保留可理解的记录。
7. 第三方代码在受管理工具进程中运行，不直接把未知代码载入有完整权限的桌面宿主。
8. 自然语言创建流程：描述 → 生成草稿及资源 → 检查说明/权限 → 用户确认 → 启用 → 测试。
9. 技能版本变化、卸载或工具列表变化后，清理失效缓存，已经排队的调用需重新核对。

## 与执行引擎的关系

Skill 是任务方法和资源，MCP 是连接工具的协议，扩展包用于管理和分发。核心模型循环仍由 WorkPilot 控制。

MCP 连接本身不赋予任务无限权限。工具输入与输出进入同一套审批、事件、取消和成果接口。服务器声明的描述和风险提示属于参考，平台仍执行自己的授权规则。

“通用兼容”通过测试样本和版本范围表达，不承诺 Pi、Codex 或其他产品的全部私有扩展接口直接可用。

- 本地和网上扩展包的安装、版本及依赖记录。
- 自然语言创建技能、确认启用和测试流程。

## 测试与验收

- [x] 现有通用 Skill 的说明及资源可正确加载，缺文件和格式错误可读。
- [x] 本地 MCP、远程 MCP 各有真实服务或真实协议测试服务通过。
- [x] 工具返回错误、连接中断、取消和动态工具变化不会破坏任务状态。
- [x] 未确认的模型生成技能保持草稿，确认后才能参与任务。
- [x] 安装坏包、路径穿越、依赖失败时不破坏已有插件和用户文件。
- [x] 停用或撤销权限后旧调用不可继续获得权限。
- [x] 单独配置的凭据不进入技能导出包，普通诊断遮盖已登记凭据。
- [x] 新增工具或技能能够增加任务能力，不要求修改执行循环业务分支。
- [ ] 用户实际模型创建、安装管理体验和需要的商业服务登录。
