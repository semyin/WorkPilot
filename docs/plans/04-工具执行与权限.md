# P04 工具执行与权限

状态：待用户体验
前置：P03  
关联需求：Q05、Q15、Q25、Q32、Q34、Q36  
完成后进入：[P05 多助手编排](05-多助手编排.md)

## 目标

把模型请求转换为经过检查的实际动作，同时实现三档权限、完整记录和可靠取消。

## 实现任务

1. 工具注册表包含名称、说明、参数结构、结果结构、作用范围、风险信息、取消能力和重复执行语义。
2. 实现首批平台工具：目录/文件读取、搜索、受管理写入、运行命令、检查运行结果和登记成果。
3. 工具输入完成后先校验结构、路径、工作目录和权限，再产生实际调用。
4. 实现请求审批、帮我批准、完全访问；默认请求审批，支持设置覆盖和有效模式显示。
5. 帮我批准实现规则阶段和 AI 审查阶段；审批模型失败或结果不确定时回到人工，不执行原动作。
6. 建立实际执行范围：文件真实路径与链接检查、工作目录约束、凭据不自动继承、外部服务权限；终端和插件的隔离另行落实。
7. 管理子进程树、输出、超时、取消和退出状态。受管理进程拥有明确任务归属。
8. 在受管理文件写入前后记录版本；终端或脚本调用预留项目快照与变更核对，供 P07 完整实现。
9. 审批记录绑定参数和目标版本，执行前再次校验，防止等待期间动作已变化。

## 权限行为

请求审批不是每次读取都弹窗；用户已明确授权的目录与操作范围可复用，但范围改变必须重新判断。

帮我批准不是让执行模型自称批准。平台调用独立审查步骤，记录规则命中、审查意见、最终决定和依据。

完全访问允许在系统账户已有权限内直接执行，不代表可以取消参数验证、日志、停止和凭据脱敏。

独立进程、Windows 进程树管理和路径检查各有作用，不能把其中一种机制宣称为完整沙箱。未验证的隔离能力不得在产品中标为已保护。

- 文件版本创建接口和冲突检测前提。

## 测试与验收

- [x] 不完整参数、未知工具、越界路径、链接绕行、无效授权均在执行前被识别。
- [x] 同一审批不能批准变更后的参数、目标或不同任务的操作。
- [x] 审查模型断流、拒绝或不可用时，原工具没有实际执行。
- [x] 撤销权限后排队中的旧动作不能继续沿用授权。
- [x] 长脚本及其自有子进程能够取消；普通子进程错误不会关闭整个工作台。
- [x] 工具错误和非零退出码不会被写成成功。
- [x] 终端、文件工具和供插件复用的独立进程边界均实际测试；完整插件加载及 MCP 集成仍按 P09 验收，未冒充本轮已完成。
- [x] 网页、文档或工具输出里的“忽略权限”等文字不能修改平台授权。

## 阶段边界与风险
