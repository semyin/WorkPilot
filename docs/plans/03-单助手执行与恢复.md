# P03 单助手执行与恢复

状态：待用户体验
前置：P01、P02  
关联需求：Q07、Q14、Q18、Q19、Q22、Q27、Q36  
完成后进入：[P04 工具执行与权限](04-工具执行与权限.md)

## 目标

实现通用的“模型决定下一步—执行工具—反馈结果”循环，以及真实可恢复的任务状态。这个阶段是多助手共用内核，不是缩减首版范围。

## 实现任务

1. 按 [运行规则](../03-交互与运行规则.md) 实现任务状态和状态转换，禁止不合法跳转。
2. 整理每轮上下文：目标、用户要求、项目规则、相关资料、已完成步骤和工具结果；不一次塞入所有文件。
3. 长上下文整理保留目标、限制、待办和来源引用，摘要不能覆盖原始历史。
4. 处理模型文本、询问、工具调用和完成输出；有外部效果的工具执行留到 P04，本阶段用受控测试工具。
5. 实现持久化消息队列与“引导”控制，记录哪些排队项已处理。
6. 实现停止、执行检查点和人工继续；重启后核对不确定工具状态。
7. 实现聊天、规划、执行模式的边界；规划产生可展示步骤，但任务流程仍根据实际结果调整。
8. 建立独立任务并发调度和全局上限，不让单个长任务饿死停止、审批等控制消息。

## 核心约束

- 不写固定办公流程作为引擎唯一执行路径；通过不同工具组合验证通用性。
- 模型故障立即结束该次执行，保留部分输出和错误，不自动重试或换模型。
- 人工继续建立新的执行记录，关联之前的检查点；先核对实际成果，不能机械重放全部历史工具。
- 时间、步骤和资源上限是可配置的运行保护；达到上限如实暂停并说明。
- 单助手上下文与任务状态必须能够被 P05 复用，不能在本阶段把“只有一个助手”写死进数据库。

## 交付物

- 可通过开发入口驱动的执行器。
- 三种工作模式、队列、引导、停止、继续接口。
- 上下文整理和状态恢复记录。
- 覆盖不同工具组合的通用任务样本。

## 测试与验收

- [x] 同一执行器完成至少三种不同工具组合的目标，未编写对应的固定业务流程分支。
- [x] 新消息默认排队，点击引导后在正确边界生效，旧要求不造成重复操作。
- [x] 关闭实际桌面窗口不结束引擎；真正结束进程后重新启动不会自动重跑任务。
- [x] 在“执行前”“执行中”“执行后未记录完成”三个位置注入退出，恢复结果不同且正确。
- [x] 模型错误只产生一次请求，错误和可恢复状态可读。
- [x] 长上下文整理后仍保留原目标、限制、待办和工具结果关联。
- [x] 聊天/规划模式不能调用执行类工具，工作模式切换有明确记录。

以上原勾选由本机模拟模型、受控工具及 Windows 桌面支撑。P04 本轮补齐三协议真实模型多轮任务，当前转“待用户体验”；不等于正式 V1 或所有服务商已兼容。

对应验收：AT02、AT05、AT06、AT22。

## 阶段边界与风险

本阶段受控工具不能被发布为具有真实系统权限的产品工具。P04 权限与工具生命周期完成后才开放实际执行。控制循环只是基础，不能跳过后续协作、浏览器和桌面集成。
