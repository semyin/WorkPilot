# P05 多助手编排

状态：待用户体验
前置：P04  
关联需求：Q08、Q17、Q19、Q20、Q26、Q36  
完成后进入：[P06 桌面工作台](06-桌面工作台.md)

## 目标

让主助手真正分派任务、接收成员结果并形成可检查成果。首版必须包含这一能力，不用几段角色提示词或同一串聊天冒充多个助手。

## 实现任务

1. 建立主任务、子助手、角色、职责、模型和依赖关系。每个成员拥有独立运行状态及必要上下文。
2. 主助手可自动建立分工；用户可覆盖成员、职责和模型，不把所有任务固定成同一种团队。
3. 独立任务可并行，依赖未满足的步骤等待；提供全局及单任务并发限制。
4. 结果通过结构化交付记录和实际成果引用返回，主助手需要检查后再汇总。
5. 子助手权限不高于父任务，审批继承明确范围；主助手不能用分派来绕过审批。
6. 子助手模型报错立即停止该助手，其他独立工作继续。主任务决定放弃、询问用户或创建新助手接替。
7. 接替尝试保存原失败、接手原因和目标，受最大接替次数与协作深度约束。
8. 文件修改使用任务归属和版本前提；竞争写入由调度/冲突机制处理，不让最后写入者静默覆盖。
9. 父任务停止、彻底退出、任务恢复覆盖整棵助手关系，并记录仍不可确定的外部动作。

## 协作事件与可见性

界面将需要展示：成员列表、模型、职责、依赖、当前状态、操作过程、成果、错误、接替关系及用量。P05 先把这些事件完整产生，P06 再做正式界面。

可以保留长期专家配置，但“专家配置”不等于正在运行的助手实例。配置和每次运行分开保存。

## 交付物

- 多助手调度器、分派与汇总接口。
- 模型与角色覆盖配置、权限继承规则。
- 依赖、失败隔离、接替和取消记录。
- 可重现的多成员协作演示及完整事件。

## 测试与验收

- [x] 至少三个助手执行具有独立分支和后置汇总的任务，结果各有来源。
- [x] 同一任务中的不同成员实际使用不同模型配置，日志准确。
- [x] 某成员模型错误不会直接中断其他独立成员，也不会自动重试原模型请求。
- [x] 主任务显式新建接替助手后，原错误仍可查，依赖关系正确更新。
- [x] 持续失败达到上限后停止继续新建助手，向主任务/用户说明。
- [x] 父任务停止后成员不继续启动新工具；恢复不重复已经完成的成员工作。
- [x] 两个成员修改同一文件时不静默覆盖，外部人工修改也能被识别。
- [x] 多任务同时运行时，事件、资料和审批不会串到其他项目。

以上勾选代表本机实现与自动验证通过；用户重点体验仍待集中确认。真实补测使用同一基础模型的三个独立协议配置，未宣称三个不同基础模型或供应商均已验收。

对应验收：AT07—AT09、AT12、AT28。

## 阶段边界与风险

不承诺并发助手越多结果越好。默认数量通过延迟、资源、服务配额和结果质量测量确定。已具备多助手能力不代表所有任务必须启用多个助手。
