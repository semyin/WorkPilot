状态：已验收

## 目标

建立可持续开发的工程，并先验证最容易引起后期重构的技术点。交付的是开发骨架和证据，不冒称正式可用版本。

## 实现任务

1. 建立 Rust 工作区、React/Tauri 2 客户端和最小独立引擎程序，保留现有图标、脚本和调研产物。
2. 锁定依赖与工具链版本，提供 Windows 上可重复的开发构建步骤；平台相关逻辑集中到适配模块。
3. 从最早页面引入中英资源文件，设置语言和已有品牌图标；禁止将全部文案散写进界面组件。
4. 建立格式检查、类型检查、Rust 测试和界面构建入口。准备跨系统构建检查配置，缺少运行环境时如实标注。
5. 定义版本号、开发/测试/发行数据目录，测试不可触碰真实项目数据。
6. 建立本地模拟模型服务，能按脚本返回文本、工具请求、慢流、错误、断流，供后续稳定复现。

## 关键验证

| 验证 | 要做什么 | 需要的证据 |
|---|---|---|
| 引擎与宿主 | 独立引擎收发事件，关窗继续，彻底退出结束自有子进程 | 进程记录、退出/恢复演示 |
| Tauri 网页呈现 | 展示本地文件、网页结果、长执行日志，验证右侧工作区方案 | 实际窗口体验及限制 |
| 专用浏览器 | 启动独立目录浏览器、导航、读网页、点击和保存下载 | 可重复本地测试页结果 |
| 日常浏览器 | Chrome、Edge 扩展与本机桥接原型，连接获准标签页 | 两浏览器分别的授权、动作、断开结果 |
| Windows 执行边界 | 验证受管理进程树取消、目录边界和必要隔离机制 | 正常与越界样本，不把进程分离当沙箱 |
| 随包运行环境 | 识别 Rust 程序、Node、Python、浏览器、Git 与文档组件的资产来源 | 来源、版本、体积、许可和离线条件清单 |
| 图片生成 | 明确图片服务适配位置和至少一种可实施接入路线 | 服务协议说明；未有凭据时标明尚未真实调用 |

浏览器原型不复制日常用户目录或登录凭据。需要用户在浏览器授权的操作在后续实际验证时由用户完成。
