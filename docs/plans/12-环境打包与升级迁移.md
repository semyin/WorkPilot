# P12 环境打包与升级迁移

状态：未开始  
前置：P07、P08、P09、P10、P11  
关联需求：Q02、Q12a、Q13、Q39、Q40、Q41、Q42、Q43、Q46  
完成后进入：[P13 Windows 首版验收](13-Windows首版验收.md)

## 目标

让用户安装后即可使用首版内置能力，尽量不再自行准备运行环境，并具备更新、迁移和本地诊断能力。

## 实现任务：安装与运行环境

1. 建立按操作系统/处理器区分的发布资产清单，包括 Rust 引擎、桌面壳及首版需要的 Node、Python、浏览器、Git 和文档工具。
2. 为每项资产记录版本、来源、校验值、许可说明、体积和更新方式；选用明确可随产品分发的组件。
3. 优先自包含的应用内工具环境，不修改用户全局 PATH、不替换用户已有 Python/Node/浏览器。
4. 使用固定依赖构建受控运行目录；Python 办公组件和浏览器版本也要纳入清单。
5. 处理 WebView 等系统依赖的安装条件；能提供离线资产的组件尽量随包提供，确实受限项须明确说明并解决，不把缺环境留成隐藏前提。
6. 安装包、快捷方式、应用标识、图标、托盘入口和卸载流程一致，默认保留用户项目成果。
7. 自有后台程序按任务和应用生命周期管理，彻底退出后不保留执行器服务。

## 实现任务：更新

1. 检查更新并展示版本与变更，用户决定何时安装。
2. 校验下载包完整性与更新签名；网络错误不能损坏当前安装。
3. 更新前协调运行中的任务，暂停新调度，完成数据备份后迁移。
4. 数据版本与应用版本相容；迁移失败保留可恢复副本。不能直接回退程序却让旧程序打开不兼容的新数据库。
5. 分开管理应用更新、随包工具更新和第三方插件更新，显示来源和影响。
6. 前期私有分发可以使用受控更新源；公开托管或购买签名服务属于后续具体决定。

## 实现任务：导出、导入与诊断

- 用户选择导出的项目、会话、配置、技能、记忆和文件成果，包中包含版本与路径映射信息。
- 模型密钥重新填写，不导出系统凭据、浏览器登录资料或认证头。
- 导入到已有数据时先预览冲突，支持新的项目位置，不能静默覆盖同名项目。
- 诊断日志只在本机保存，用户主动导出；运行事件和错误均先脱敏，不默认上传遥测。
- 扩展包重新导入后需要重新核对路径、依赖和有效权限，不能借迁移提升权限。
- 接续 P07：文件版本存放于独立加密对象库。导出导入必须覆盖版本引用与可解密性，不能只复制数据库或把系统凭据明文放入包中；在完整可恢复备份后提供版本保留/清理策略及团队历史永久删除，保留来源关系与用户项目文件。

## 交付物

- Windows 安装包与完整随包资产清单。
- 更新检查、用户安装、失败恢复及数据库迁移。
- 导出导入工具与本地诊断包。
- 普通用户安装、配置、连接浏览器和排错说明。

## 测试与验收

- [ ] 在未装开发环境的 Windows 测试环境完成安装，内置文件、脚本、办公和专用浏览器工具可运行。
- [ ] 断网可启动界面并处理本机已有资料；云端模型不可用时明确报错，不宣称离线 AI。
- [ ] 现有 Chrome/Edge 连接的安装授权步骤可复现。
- [ ] 更新由用户决定；损坏包、断网、权限不足、迁移失败均保留原数据。
- [ ] 导出包中检索不到测试用密钥，导入后提示重新填写凭据。
- [ ] 中文/空格路径、不同项目位置和同名冲突迁移正确。
- [ ] 卸载不误删用户项目；数据删除需要明确范围。
- [ ] 新机器能恢复被选择迁移的加密文件版本；丢失/错误解密材料时明确失败。清理和团队历史删除先展示范围，不留下悬空引用，也不删除项目实际文件。
- [ ] 彻底退出后自有执行工作停止，用户日常浏览器保持不受影响。

对应验收：AT22、AT24、AT25、AT27、AT29。

## 阶段边界与风险

随包并不等于可以包含任何第三方商业软件，也不代表所有未来插件的依赖均已预装。必须给出首版内置能力的明确依赖范围和真实干净环境验证。

参考：[官方资料 S05—S07](../06-资料与依据.md)。
