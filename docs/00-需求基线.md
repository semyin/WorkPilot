# WorkPilot 需求基线

更新日期：2026-10-04

依据：本次对话四轮需求访谈，问题编号 Q01—Q48。后续回答优先于先前回答；工程建议与用户确认分开记录。

## 1. 产品与技术定位

WorkPilot 是可扩展的通用 AI 工作平台，融合项目工作台和通用助手的体验。首先服务个人和小团队，源码及发布范围先保持私有。

已认可的技术基线：

- Rust：自研执行引擎，负责任务、模型、工具和状态。
- Tokio：处理模型连接、进度事件等同时进行的工作。
- React：制作桌面界面。
- Tauri 2：桌面外壳；关键浏览器嵌入能力须在 P00 验证。
- SQLite：本地任务与配置记录；文件成果保存在实际文件目录。
- 独立工具进程：按需运行 Python、Node.js 和原生程序；首版所需环境尽量随安装包提供。

2026-10-04 补充的用户维护要求：单个代码文件不超过 1000 行，现有超长代码按职责拆分，并写入开发入口供后续遵守。具体统计口径与检查命令见 [AGENTS.md](../AGENTS.md)，这项约束不改变产品范围或技术组合。

模型本身使用现有服务。可以参考 Pi 等项目的分层方式，但不把它们的执行器当作已选定的主引擎，也不假称已获得其他产品的私有实现。

## 2. 首个正式可用版本

Windows V1 必须具有：

1. 中英双语的项目、任务、聊天和成果工作台。
2. 三种模型协议，用户自己的服务地址和凭证，任务及助手各自可选模型。
3. 聊天、先规划再执行、直接执行三种工作模式。
4. 通用执行循环、消息排队、引导插队、停止和人工恢复。
5. 多个独立任务并发，主助手与多个子助手协作。
6. 请求审批、帮我批准、完全访问三档权限，默认请求审批。
7. 专用浏览器及日常已登录 Chrome、Edge 两种接入通道。
8. 文件读取、修改历史、前后对比、版本恢复、代码编辑、终端与运行预览。
9. Skill、MCP、扩展包管理、自然语言创建技能。
10. 文字、文件、图片输入；办公文件生成、预览和外部打开；明确的图片生成入口。
11. 用户确认后保存的长期记忆，本机定时任务，关闭窗口后继续运行。
12. 随包运行环境、可安装软件、用户决定是否更新、导出导入、本地诊断。

以上是正式可用版的完整范围。中间原型可以只完成部分层次，但不得以原型替代 V1 验收。

## 3. 后续版本范围

电脑桌面操控、完整的内置 Word/Excel/PPT 编辑、语音交流、音视频输入与生成、本地模型正式支持、公共插件商城、团队共享和多机同步放入 P16 后续路线。仅做接口预留不算这些能力已经实现。

发布顺序：Windows → macOS → Linux。核心从第一天保持跨平台结构，实际交付顺序与实际验证范围分别记录。

## 5. 需要同时成立的规则

- 隐藏窗口不是退出程序。隐藏后，普通任务、子助手和定时任务都可以继续。
- 托盘“退出 WorkPilot”、系统结束应用或关机后，任务不再执行；应用重新启动不会自动恢复被中断的工作。
- 子助手接替是主任务显式创建的新尝试，保留失败记录；不是底层请求重试，也不能偷偷改用另一个模型。
- 权限模式与工作模式独立。聊天或规划模式不能因为选了完全访问，就开始未经执行指令要求的实质操作。
- “兼容三类接口”是协议适配范围，不是所有模型具备图片、工具、费用上报等全部能力的承诺。
- “完整过程”指应用和服务实际返回、可以记录的事件；凭证需要脱敏，服务没有返回的内部信息不能凭空补出。
- “本机保存”指 WorkPilot 的存储设计；调用云端模型仍会按任务发送所需内容。
- “环境随包”降低用户安装负担，不代表云端模型可以断网工作，也不代表所有未知第三方插件的依赖均已包含。

## 6. 当前边界

不要求用户先提供某个办公场景来限定产品。开发验证使用跨类型、可重复的任务来检查平台通用能力。

没有时间或费用硬上限，不代表应主动购买服务、公开发布源码或更改产品范围。具体服务、签名条件和平台实机条件到对应阶段再落实。

Q44 通知方式已于 2026-10-04 获得用户确认，按软件内提醒、Windows 系统通知和托盘提示实施。开关、失败降级和实际体验仍须实现及验证；其它工程默认值和技术验证项集中列在 [决策与待办](05-决策与待办.md)，不得混写为用户已确认需求。

P13 本轮测试安排于 2026-10-04 调整：用户明确要求不要四小时连续测试，因此取消该项，不自动重新安排；长期连续稳定性结论保持未验证，其余验收按阶段记录推进。
