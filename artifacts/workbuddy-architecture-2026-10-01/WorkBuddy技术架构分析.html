14个技术模块：实现、作用和证据

已核验组件存在部分已核验官方披露每张卡可展开证据和限制
01

桌面界面

已核验
Electron + React

Electron把网页界面装进桌面窗口；React负责聊天、项目、资料库和产物面板等界面。

查看证据与结论边界

证据：安装包入口为main/index.js；包含renderer和preload；运行进程中有Chromium渲染进程。界面包内发现React 18.3.1。

边界：确认本机5.6.2包含这些组件，不代表每一个面板都只使用同一种界面框架。

02

桌面宿主

已核验
Electron main + preload bridge

负责窗口、菜单、系统文件操作，并把界面的请求转给后台。preload是界面与系统能力之间的桥接层。

查看证据与结论边界

证据：preload/index.js中有contextBridge和ipcRenderer；主程序有wb:invoke分发与daemon连接。

边界：IPC是电脑内不同进程之间传递消息；它与访问互联网不是同一件事。

03

后台业务

已核验
Node daemon / App Server

常驻的任务管家，维护会话状态、后台服务、连接器、数据库和升级迁移。Node用于运行JavaScript业务代码。

查看证据与结论边界

证据：包内架构说明列出SessionManager、MCP apps host、SQLite和connector；当前确实存在daemon-app-server-entry进程。

边界：包内还保留评测时在主进程内运行daemon的路径；常规桌面与评测模式要区分。

04

AI执行

已核验
@genie/agent-cli / CodeBuddy执行组件

接收任务，发出模型请求，执行工具，再把进度和结果送回来。CLI在这里是后台执行程序，用户无需打开命令行。

查看证据与结论边界

证据：cli/package.json名称为@genie/agent-cli，描述明确指向CodeBuddy；包含headless和lite-wb构建；当前观察到2个相关进程。

边界：可以确认使用CodeBuddy执行组件；不能据此说整个产品的代码与另一产品完全相同。

05

会话通信

已核验
ACP + stdio / Streamable HTTP

ACP是界面与AI执行器沟通的协议，可传提问、进度、工具授权和结果。stdio是子进程间的输入输出通道。

查看证据与结论边界

证据：本地包有ClientSideConnection、session/prompt、session/update等实现；包内架构说明标注daemon与CLI之间的ACP/stdio链路。

边界：不同运行模式可能走不同传输；云端公开通道另见下方，不把所有连接都概括成WebSocket。

06

模型适配

已核验
多模型配置与提供方适配模块

执行器把同一任务交给所选模型，让界面和办公功能复用同一套执行流程。

查看证据与结论边界

证据：包内声明@genie/agent-provider；前轮真实调用快速、均衡、极致，看到Deepseek与Hy4 preview标识。

边界：具体请求是否经腾讯统一转发、如何自动选模型、失败后如何切换，没有完成逐请求核验。

07

工具扩展

已核验
Skills + MCP + 连接器

Skill保存任务方法、说明及可选脚本；MCP是把外部工具接入AI的标准接口。连接器把工具接入和使用说明一起交给用户。

查看证据与结论边界

证据：安装包含MCP SDK与技能、连接器模块；官方连接器说明提供MCP+Skill、CLI+Skill两种方案；前轮实际调用过创作工具。

边界：包内存在不等于所有连接器已接通。外部服务仍可能需要自己的账号和授权。

已核验

专家是保存好的角色与方法；专家团由主理人分配任务、收集成员结果。

11

本地存储

已核验
SQLite + 文件目录 + 会话记录文件

SQLite是电脑上的小型数据库，保存任务索引和状态；实际文档、图片和视频保存在文件目录。

查看证据与结论边界

证据：代码有better-sqlite3、建表语句及WAL配置；表含sessions、workspaces、automations和automation_runs。CLI中另有子成员.jsonl记录路径。

边界：这里只读了程序中的表结构，没有读取账号数据库。不能据此断言所有聊天正文都存SQLite，或所有资料都只在本机。

安全执行

查看证据与结论边界

证据：存在sandbox-center、sandbox-cli、sandbox-cli-gc运行进程；包内有权限策略和credential-protection模块；前轮批量删除曾被拦截。

边界：这些证据不等于完成安全审计；沙箱的完整隔离强度、所有边界条件及凭证保护实现尚未验证。

“把销量20改成21”，背后发生什么

下面是结合模块实现与前轮实测还原的流程，不是对该次操作逐条网络消息的录制。

  1. 界面收集指令与上下文。包括当前任务、所选模型、工作目录和已打开的表格。
  2. 后台找到这次会话。关联工作区、任务状态和可用能力，再把请求交给执行器。
  3. 执行器请求模型。模型给出回答，或要求调用读取/编辑等工具；复杂任务可能反复经历这一轮。
  4. 工具通过对应通道操作文件。这次在已打开表格的上下文中完成读取和修改，并受现有权限约束。
  5. 结果流回界面并保存。界面展示工具过程、更新表格；保存后实际文件中的销量为21。

为什么“打开文件”很关键

前轮直接按文件路径读取遇到问题，先在右侧编辑器打开后，AI才成功读取表格并修改。

安装包存在文档服务、预览注册和界面桥接模块。这与“文件路径读取”和“当前编辑器文档访问”有不同接入方式的判断相吻合。

本次结果：产品收入由700变为735，总销量46，总收入2055；独立检查已保存文件，销量单元格确为21。

这能解释编辑器为什么是重要组成部分；首次4012错误的具体根因仍未查定。

专家、技能、连接器，各自负责哪一段

组成大白话技术位置
专家给AI一套角色、方法和回答规则。插件配置指向角色说明文件；角色正文是系统提示词。官方专家格式
专家团主理人分派工作，再把成员成果合起来。定义主理人与成员，以及可共享技能和工具依赖。官方专家团格式
Skill告诉AI如何完成某类工作，可附说明、模板和脚本。作为可加载的能力包，被任务或专家使用。官方任务与技能说明
MCP / 连接器把可以实际执行的工具接进来。官方提供MCP+Skill或CLI+Skill方案；前者可连接本地或远程工具。官方连接器方案

前轮的策划、文案、配图三名成员各自完成任务，与这种组织方式一致；未证明它们各自独占一个系统进程。

成员会话记录CLI实现存在以.jsonl文件保存子成员记录的路径；这种文件按行记录结构化内容。未读取账号已有对话记录；不推断所有历史消息的唯一存储位置。
资料库与记忆已实测资料库文档保存、搜索和引用；界面有记忆与进化设置。是否使用向量数据库、如何切分文档和排序、记忆如何提取合并，目前没有足够证据。

云端能确认的是接口与通信方式

官方把“发送给电脑上的本地助理”和“创建云端任务”列为不同能力。云端会话公开使用ACP，接收端以SSE持续收消息，发送端以POST提交JSON-RPC调用；也有查询历史产物的接口。官方Open API说明

SSE可以理解为服务器持续把进度推回来；JSON-RPC是一套带操作名和参数的调用格式。以上是公开服务契约，不是对服务器内部部署的推断。

还不能下结论的技术细节

依赖存在，使用范围仍要追踪

  • OpenAI Agents SDK：安装包和CLI依赖均包含0.5.2。只能确认包含该开发库，不能据此认定每条工作流都基于它，或所有请求都发给OpenAI。
  • E2B：CLI依赖声明了该云端执行环境开发库。不能据此认定全部云端任务都使用同一供应商。
  • Node、Python、Git：安装目录带有运行环境压缩包。不能仅凭文件存在判断每个任务实际调用了哪个版本。

客户端无法完整展示的部分

  • 云端数据库、缓存、消息队列和集群拓扑。
  • 模型自动选择、降级切换和成本控制的完整算法。
  • 资料检索的切分、向量模型、排序及记忆整理机制。
  • 所有沙箱权限边界与企业部署的安全保证。
  • 高并发下的真实吞吐、时延和失败恢复能力。
