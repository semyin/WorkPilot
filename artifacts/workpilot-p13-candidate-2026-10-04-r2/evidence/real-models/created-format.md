# 汇总输出格式说明

本文件是 `p13-reusable-summary` 的唯一格式权威。每次使用技能先读它。

## 1. 最终输出（严格）

报告文件的全部内容严格为一行：

`{标题前缀}|合计={总和}`

- 单行，仅此一行；无空行、无标题、无 Markdown 代码块、无前后空格。
- 无末尾换行符（结尾不写 `\n`）。
- 分隔符固定为一个半角竖线 `|`，等号固定为半角 `=`，中间不加空格。
- `{标题前缀}` 原样使用来源字符串：不翻译、不改标点、不加减空格。
- `{总和}` 是 `values` 数组全部元素累加的结果，不带单位、不带千分位、不做四舍五入。

格式示例（仅示意，不是任何一次的实际结果）：

- 前缀 `月度数据汇报`，`values` 为 `[1, 2, 3]` → `月度数据汇报|合计=6`
- 前缀 `Q3 汇总`，`values` 为 `[0.5, 1.25]` → `Q3 汇总|合计=1.75`

这些数字只演示排版；任何前缀或合计都必须来自当次记忆与当次文件。

## 2. 标题前缀的取值

1. 用 `memory_search` 查询“汇报标题”，取用户已确认条目中记录的标题前缀。
2. 若查询无结果、结果中没有明确前缀，或存在互相冲突的条目：用 `ask_user` 询问用户要用哪个前缀，冲突时以用户答复为准。
3. 绝不编造、绝不沿用示例前缀、绝不把本轮临时答复当成永久偏好；技能不写入或修改记忆（新的长期偏好需用户自行在记忆面板确认）。

## 3. 数字与求和

- 只接受 JSON 数字字面量（整数、小数、负数）。`values` 中的字符串（如 `"3"`）、`null`、布尔值、嵌套数组或对象都视为异常：停下来问用户，不静默过滤、不隐式转换。
- 求和按数组原顺序逐项累加；空数组的总和记为 `0`，输出 `{前缀}|合计=0`，并在回复中提醒用户 `values` 为空。
- 保持原始精度：整数结果输出为整数（`6`，不是 `6.0`）；小数结果按精确十进制值输出，不补零、不截位。
- 含小数时按十进制精确累加（先按各元素的小数位数对齐再相加），避免出现 `0.1 + 0.2` 这类浮点表示误差；若无法保证精确，如实说明并按可验证的结果输出，不伪造。
- 极长或科学计数法数字：用 JSON 中可读回的十进制形式输出，并在回复中说明元素数量与原始值范围。

## 4. 文件与登记

- 默认文件名 `summary-report.txt`（UTF-8）；用户指定文件名或位置时一律以用户为准，保持用户选择的路径。
- 写入用 `write_file`：新文件 `expected_sha256=null`；覆盖已存在文件必须先 `read_file` 拿到当前哈希并向用户确认。
- 写入后必须 `read_file` 回读并逐项核对：
  - 恰好一行，末尾无换行；
  - 前缀与记忆条目（或用户本轮明确答复）逐字符一致；
  - 合计等于当次 `values` 的累加结果，元素个数与文件内容一致；
  - 无多余空白、引号或代码块标记。
- 核对通过后用 `register_artifact` 登记该文件；把元素个数、总和与核对结论一并告知用户。
