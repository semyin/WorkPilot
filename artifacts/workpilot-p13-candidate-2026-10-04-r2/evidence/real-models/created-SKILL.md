# 可复用数字汇总（汇报标题 + 合计）

开始前先读 `references/format.md`：标题前缀来源、求和细则和最终输出的严格格式全部以该文件为准。不要用记忆里的格式或本正文的概述代替它。

本技能面向任意输入数字，不预设、不内置任何一次的具体结果；正文与参考文件中的示例只用于说明格式。

## 需要的输入

- 用户指定的 JSON 文件（项目内相对路径），其中 `values` 是数字数组。路径缺失或含糊时先问用户，不要猜测文件。
- 已确认的项目记忆“汇报标题”提供标题前缀。

## 执行步骤

1. 读 `references/format.md`。
2. 用 `memory_search` 查询已确认的“汇报标题”项目记忆，取得标题前缀。
   - 只有工具明确返回的、用户已确认的条目可当作前缀来源。
   - 若没有任何已确认条目，或条目里没有明确的前缀：用 `ask_user` 询问用户本次要用的标题前缀。在得到答复前不要写报告、不要编造或沿用示例中的前缀。
   - 用户在本轮临时给出的前缀只用于本轮，不据此推断新的长期偏好，也不自行写入记忆。
3. 用 `read_file` 读取用户指定的 JSON 文件，解析 `values`，确认该字段存在且每个元素都是 JSON 数字。
   - 文件不存在、`values` 缺失、含非数字元素等情况：说明具体原因并询问用户如何处理；不静默跳过元素、不按 0 代替。
4. 对 `values` 全部元素求和：按数组原顺序逐项累加，保留精确结果，不四舍五入、不补零格式化。求和规则的细节见 `references/format.md`。
5. 用 `write_file` 写出报告文件，内容严格等于 `references/format.md` 规定的单行文本。目标为新文件时 `expected_sha256=null`；若目标已存在，先 `read_file` 取得当前版本哈希，并向用户确认后再覆盖。
6. 用 `read_file` 回读写出的文件，核对：只有一行、无末尾换行、前缀与来源一致、合计与 `values` 求和一致。核对不通过就修正后重新写入并再回读，不要把未核对的内容当成完成。
7. 用 `register_artifact` 登记该报告文件。
8. 回复用户：使用的标题前缀及其来源（记忆条目或用户本轮答复）、JSON 文件路径、参与求和的元素个数与总和、报告文件路径与回读核对结果、以及未验证项。

## 配套资源

- `references/format.md`：输出格式、前缀取值、数字与异常处理、文件命名与登记核对规则。每次使用本技能都先读它；不需要读其他文件。

## 边界

- 只使用当前任务确实提供的工具：`memory_search`、`read_file`、`write_file`、`register_artifact`、`ask_user`。
- 本技能包只含上述两份 Markdown，不含脚本、不含插件/MCP 服务器、不含凭据；凭据一律由用户在扩展认证设置里配置。
- 草稿需用户在“技能与插件”中确认后才启用；技能的执行仍受任务模式与审批约束，编写技能本身不扩大任何授权。
